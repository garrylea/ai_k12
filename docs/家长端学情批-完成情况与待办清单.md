## 1. 这批做了什么（已完成）

### 1.1 后端：新模块 `apps/server/src/modules/parent-insights/`

6 个**只读**端点（全部 `@Roles('parent')`，归属校验先于取数，Controller 不手工包信封）：

| 端点 | 说明 |
|---|---|
| `GET /api/parent/dashboard` | 多孩聚合：每孩概览 + 按学科卡片（进度/正确率/自评/未清零错题/考试场次/近 7 天活跃） |
| `GET /api/parent/students/:id/reports?period=weekly\|monthly` | 学情报告，**实时聚合**（不落 `learning_reports`、不调 LLM）：stats/trend/subjects/weakPoints/exams |
| `GET /api/parent/students/:id/errors` | 错题查看（只读主线错题本），7 个筛选 + 分页。轨道 = `main`(practice/discuss/exam) \| `training`(targeted/error_practice/auxiliary)；**辅线答疑问过的题归训练**（2026-09-19 由 `main\|aux` 改，见 changelog） |
| `GET /api/parent/students/:id/chat-logs` | AI 对话回放列表，轨道/场景/时间/标题关键词筛选 + 分页 |
| `GET /api/parent/students/:id/chat-logs/:dialogueId` | 单条对话逐句回放（含 `reasoning`、`safetyFlag`） |

内部结构：1 个聚合仓储 `parent-insights.repo.ts`（727 行）+ 4 个 service（`dashboard` / `report` / `errors` / `chat-logs`）+ `dto/` + 两个口径工具 `window.util.ts`（时间窗）/ `rate.util.ts`（正确率，`answered=0` → `null` 而非 `0`）。

**关键口径（改动前先读，别"统一"掉）**：
- 正确率 = `practice_results`（排除 `unanswered`/`self_assess`）+ `exam_answers`（排除 `is_correct IS NULL`）两源合并；窗口可选，**同一套 SQL**。
- 活跃度 = 四表时间并集（`practice_results` / `point_ledger` / `exam_sessions` / `ai_messages`），`lastActiveAt` 全时段、`activeDays7` 近 7 天。
- 错题列表**刻意不 JOIN 知识点**（41% 的题多 KP，JOIN 会让 `LIMIT` 作用在翻倍行上）→ 拆两条查询 + `listErrorKnowledgePoints` 批量取。
- 「已开始学科」= `progress.status <> 'not_started'`（**不是**「有 progress 行」）。
- 会话列表 `updatedAt` = **最后一条消息时间**，不是 `ai_dialogues.updated_at`（后者实质冻结）。

> 下面这段是**当时的判断原文**（保留作对照）：

用户判断：**现在仪表盘显示/统计的内容还不够，这些需要增加大量埋点记录信息后才能真正显示出可用的数据。** 下面是「想展示什么 → 现在有没有数据 → 缺什么」的逐项盘点，作为下一步梳理的起点。

### 2.1 缺的是**学习时长**（最核心，一次解锁四处）

现在仪表盘只有「近 7 天活跃 N 天 + 最近活跃时间」，这是**代理指标**：孩子挂机不答题 = 不活跃；也无法回答「今天学了多久 / 这周比上周多还是少」。

**全库现在没有任何时长字段、没有学习会话表**（`ai_messages.response_time_ms` 恒写 NULL；`progress.last_active_at` 只在首次领课时写一次且仓储不读）。

需要的埋点：一张 **`study_sessions`**（或等价的心跳表），例如 `student_id / subject_id / scene / started_at / last_heartbeat_at / ended_at / active_seconds`，前端在进入学习页、切卡、提交答案、发消息、页面可见性变化时上报（`visibilitychange` + 空闲裁剪）。

**它一次解锁 4 处**：
1. 仪表盘/报告的**学习时长**（PRD §7.7 的原文要求）
2. **每日趋势**（现在只有 `judged_at` 能按天聚合，只覆盖做题；阅读卡片/讨论/背单词完全没数据）
3. **行为管控**的「今日已用时长」（`controls.daily_time_limit_minutes` 只是**上限**，没有已用量）
4. **学习目标**（P6.5）的达成率（`goals` 现在也是死表）

### 2.2 缺 **知识点掌握度**（真薄弱点）

`student_knowledge_mastery` 是**死表**（全仓 `apps/server/src` 零写入）。现在报告的「薄弱知识点」是**错题数代理**，且只有约 40% 的错题能映射到知识点（实测 139 条错题只有 55 条能映射），页面只能靠 `weakPointsUncoveredCount` 提示「另有 N 道未标注」。

需要的埋点：**判题后回写**（答对/答错时更新 `correct_count`/`error_count`/`mastery_score`/`last_seen_at`），落点在 `JudgeCoreService` 的对错出口。顺带要解决**题库 KP 覆盖率**（`question_knowledge_points` 只覆盖 203/529 题）。

### 2.3 缺 **专项类学情**（语文三专项 / 英语背单词 / 辅线）

这三块**都不写 `progress` 行**，所以：
- 仪表盘**没有它们的学科卡**（只背单词的孩子会同时看到「活跃 3 天」和「还没开始任何主线学科的学习」）
- 语文三专项**没有学生进度表**，只能从 `point_ledger`（`ref_type='passage'`）间接推「做过哪些篇目」
- 英语有 `student_word_progress`（`learned`/`wrong_count`）→「共背多少词」「易错词 Top」**可查**；但 `last_seen_at` 是**覆盖式最新值**，「每天背了几个词」**没有数据源**

需要的设计：要么新增按天的专项进度/事件表，要么接受「每天几个词」暂不做。**这一项要先做前置调研再立项。**

**B. 实现与契约的不一致（有边界，不紧急）**

**C. 注释仍失实**

**D. 结构债（下一批碰这块时做，别现在纯重构）**

20. `SessionEffects` 是可变类型、而部分实例被 `Object.freeze` → 冻结性不一致（可变路径上就地改会成功、空操作路径上会抛）；`sceneMap.ts` 的 `NOT_TRACKED` 同样未冻结。建议统一 `Readonly<SessionEffects>` 或全部冻结。
