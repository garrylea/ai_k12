两条子系统**自己的表、自己的端点、自己的页面**。**共同原则（勿违背）**：作答单位不是「题」（语文是**篇目**、英语是**词/义项**），标准答案是内容自带属性，判题方式专项专属 —— 因此**不挂 `questions`、不进错题本、不参与主线清零门禁、不用「不再展示」/提示缓存/自评**；表都**无外键**（或只挂学生表），表即完整边界。**但语文题库类（真题考试 / 专项练习 / 错题练习）不属于本例外**——它们走 `questions` + 错题本 + 清零门禁，判题口径见 `ai-core.md`（语文非客观题一律自评，2026-10-28）。

**边界勿泛化到学科**：语文/英语的**试题类**（试卷/真题/考试）属正常题库业务，作答单位是「题」、错题要进错题本参与门禁，**仍走 `questions` + 错题本 + 考试/组卷既有体系，复用、不另起一套**。划界依据是**形态**（「篇目/词」还是「题」），**不是学科**。

各专项的端点、抽题池谓词、判题枚举见 API 文档 §4.18 与 §5.20–§5.23。**以下是「勿动」清单**：

- **三处「有意不统一」，勿合并**：① 三个专项的抽题池**逐层加闸门**（默写「必背」→ 解释「内容就绪」→ 含义再加 `sentence_meanings`）；② 英语**判题三条路由 + 计错口径**（只有 `wrong` 计错，`off_target`/`unanswered`/`undetermined` **都不计**）；③ 解释逐句判（`judge` 带 `sentenceIndex`）与含义 `method` **不含 `exact`**（理解性作答一律过 LLM、无归一化全等短路）。
- **英语防泄漏铁律**：`promptKind='cn2en'` 的题**后端不下发** `word`/`phonetic`/`context`/`hasFamily`；**`+` 号只在 `promptKind==='en2cn' && hasFamily` 时渲染**（词根族树必然含单词本身，中→英题点开等于直接看答案；有渲染钉子用例）。
- **数据面硬约束**：`english_words` **无外键**、`error_count` 只增，**loader 的 `ON DUPLICATE KEY UPDATE` 必须显式排除 `error_count`**（否则全量重灌抹掉全平台易错统计）；`student_word_progress.word_id` **故意不设外键**（否则内容表全量重灌会被入向外键卡死）；抓取**必须串行 + `--crawl-delay 1.5`**（smartedu 会 403）；**音标本期不做**。记账唯一实现在 `normalize-english.util.ts` 的 `progressDelta`；场景 `english_word_judge` = primary `local` / fallback `deepseek-flash`，设计见 `docs/superpowers/specs/2026-09-16-english-vocabulary-special-design.md`。
- **语文内容走旁路**（`dictation_cli`/`interpretation_cli`）：**不接**四阶段主线、不产 `cards`、不写 `questions`；字词由**用户手工整理**。**改 `tools/db/migrations/2026-09-15_chinese_passages.sql` 前记住**：删 `questions` 行前必须先摘掉 `dictation_passages` 的 CASCADE 外键（首跑曾因级联静默清空篇目、从备份恢复，根因见 `docs/superpowers/plans/2026-09-15-chinese-passages-standalone.md` Task 9）。设计见 `docs/superpowers/plans/2026-09-16-chinese-interpretation-special.md`。

## 题库类训练按 subjectId 参数化（2026-10-31）

**题库类训练**（专项练习 / 真题考试 / 错题练习 / 薄弱点图谱）的学科差异**集中在前后端各一份配置表**，**不要在各页写 `if subject ===`**：

- 后端：`apps/server/src/common/subject-config.ts` —— `TARGETED_TASK_CODE` / `PAPER_TASK_CODE` 两张按 `subjectId` 查任务码的映射表（1/2/4/5/9 各一套）、`SELF_ASSESS_SUBJECTS` 自评学科集合、`selfAssessSkipsJudging(subjectId, type)`（闸门①）、`isSelfAssessSubject`（闸门②）、`targetedTaskCode` / `paperTaskCode`（表外 6/7/8 回落 `math_*`，不报错，行为与今天一致）。
- 前端：`apps/web/src/subjectConfig.ts` —— `TRAINING_SUBJECTS` 配置数组（每行：`id` / `name` / `desc` / `enabled` / `badge` / `homePath` / `typeOptions` / `targetedTaskCode` / `isMathLike`）、`getTrainingSubject` / `subjectName` / `subjectHomePath` / `parseSubjectId`（白名单 `1|2|3|4|5|9`，缺省/未知回落数学）/ `isMathLikeSubject` / `selfAssessEligible(subjectId, type)`（闸门③，数学分支与今天逐字等价）。

**新增学科 = 在两张表各加一行 + `subjectConfig` 里把 `enabled` 翻成 `true`**。各页（`TrainingSubjectPage` / `TrainingHomePage` / `TargetedConfigPage` / `WeakPointGraphPage` / `exams.service.ts` / `training.controller.ts` / `training.service.ts` / `judge-core.service.ts`）只读配置表、不写学科 if 分支；**任何页面新增 `if (subjectId === X)` 都是回归信号**（应改成在配置表里加一项）。

**判题三道闸门语义不同，不能合并成一个判断**（spec §3.5）：
- 闸门① `selfAssessSkipsJudging`（`exams.service.ts`）：考试侧「跳过判题直接自评」——语文=非客观、物/化/道=仅 `short_answer`/`proof`；**比闸门②窄**：化学填空等值答案能走 `exact` 判对（只有不等才转自评），不能在①就被抢去自评。
- 闸门② `isSelfAssessNonObjective`（`judge-core.service.ts`）：归一化比对失败的兜底——`subjectId∈{2,4,5,9}` 的非客观题 + 物/化/道的 `fill_blank`/`calculation` 不等时转 `self_assess`。
- 闸门③ `selfAssessEligible`（`QuestionRunner.tsx`）：前端是否「同步等判题 + 弹自评视图」——数学 `short_answer`/`proof`（与今天一致），非数学学科一切非 `choice`/`true_false`。**不在名单里的题型，服务端返回 `needsSelfAssessment: true` 也会被记成 `isCorrect: false`**（学生看到「错」且无自评入口）。

**交卷无参考答案题**：`finalizeSession` 的「未作答按错计」保持 `is_correct=0`，但**只有 `q.answer <> ''` 才写错题本**（物理 51/52/53 号卷大量无答案题，进错题本后学生清不掉）。数学卷题都有答案，行为不变。

**不变量**：物理/化学/道法任意题型都不会调用 `JudgmentCapability`（AI 判题写死 `subject:'math'`，新学科不可达）。`judgeForPractice`（主线课程路径）不改：主线只跑数学课程，新学科不经过该路径。
