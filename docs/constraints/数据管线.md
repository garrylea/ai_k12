# 数据管线（tools/data-refinery）

> **本文由根 `CLAUDE.md` 于 2026-09-24 迁出**（体量纪律：根文件只留仍生效硬规则与索引，带细节的「勿动」清单按主题搬到本目录）。**内容一字未改。**

> ⚠️ **动手改本主题之前必须先读本文** —— 这里的每一条都是「读代码/配置得不到的为什么」或「改了会踩坑的勿动」。索引见根 `CLAUDE.md` 的「权威文档索引」。

`convert_cli (MinerU) -> extract_cli (LLM) -> publish_cli (物化图片) -> db_loader_cli (MySQL)`；`refinery_cli.py` 串联 publish + db_loader，DB 由 `tools/db/install_mysql.sh` 初始化。题目内容回写工具 `answer_importer`（JSONL/Markdown → questions 的 answer/approach/explanation/type，`--export` 出模板 / `--apply` 幂等写入）。试卷答案补录是**两段式**（2026-10-28）：`answer_extract_cli`（按学科策略从 md 提取 → 答案文档）→ `answer_importer --doc --paper-id`（回写，`answer_verified=1`）。

**识别问题分「题号层」和「内容层」，两层都要扫（2026-11-01）**：`recognition_scan` 原来只查题号（缺号 / 顿号题号 / 修复砍短 / 噪声题），题号齐、正文坏的一律静默 —— 人大附 2024 物理 34 题号全在，第 27 题缺小问 (1)、第 24 题吞了第 25 题、第 25 题装着第 23 题的正文，三处一个都没报。现在加两类确定性判据（**不调 LLM**）：`incomplete_content`（小问从 (2) 起且无 (1)；或 `needs_review` 且 `labeling_issues` 有 `is_complete=false`）、`merged_content`（正文里出现另一个题号**且** md 里该题号后面确实是这段话；或本题正文开头在 md 里**唯一**归属于另一个题号 —— 多归属时不报，避免「两题都以『如图所示…』开头」误伤）。人工确认走两段门：答「没问题」只落 `verdict=no_change`、**一个字段都不改库**，重扫不再打扰；答「有问题」才补录，由 `apply_fixes` 原地 UPDATE 并 `is_active=1`。`content_sig`（正文归一化后的 md5）是让旧结论失效的开关：正文变了 `reopen_changed` 自动退回待确认。**`verdict=no_change` 的 resolved 记录没有补题记录，`reopen_unbacked` 必须跳过它**，否则每次扫描都会把「确认无问题」退回待处理。**`applied=true` 只证明「当时写过库」，不证明「现在还活着」**（2026-11-01：人大附重导一次就把人工补的 7/16/18/23 摘掉、把第 6 题重置成 `is_active=0`，而清单一直显示已解决）。两道对账缺一不可：`reopen_unbacked(present=当前 extracted 题号集合)` —— 缺号类补题只要切题产物里仍没有该题号就重新打开；`apply_fixes._replay_reason` —— 写库前查库，题没了或 `is_active=0` 自动重放。**`_UNREPAIRED_OK` 那几科（语文/道法/史地生）不报 `needs_review` 类不完整**：画线句/加点字/图片内表格按设计就是 `is_complete=false`、只报告不修复，报出来实测 30 张语文卷 197 条，真缺陷全被淹；那几科只留确定性判据（小问从 (2) 起 / 前后题合并）。

**答案提取的学科分派**：`src/subject_strategies/` 一科一份 `extract_answers`（语文独立实现；数学/物理/化学/英语/道法走 `generic.py` 的整卷对齐），入口统一 `get_strategy(code).extract_answers(text, md_path)`；未登记学科（生物/历史/地理等）抛 `UnknownStrategyError`，不回退 generic。答案提取的学科 code 由 `subject_codes.subject_code_for_path(rel_md, default="")` 得出——**不给默认 `math`**，路径首段不是已知学科目录就报错跳过（答案写错学科比提取失败更危险）；**不要**把语文特例塞回通用 `question_splitter`，也**不要**在标点归一化里映射「、」（中文大题序号分隔符，归一后大题标题会混进上一题答案）；答案段题号必须**递增**，回退编号是评分细则，不能开新答案段（否则串到第 1 题）。

**答案表格必须按版式分派，不能按位置猜（2026-11-01）**：`question_splitter.parse_answer_table` 以前写死「每行跳过第 0 格」（那是「题号/答案」标签位），但真实卷有三种版式：① 双标签 `题号|1|2…` + `答案|A|B…`；② 单标签（只有数字行有标签）；③ **无表头** `1|2|3…` + `C|D|A…`（第一格就是题号 1）。②③ 会把**首题答案整格丢掉**。另外一张表里可能有多组「数字行+答案行」（如 1–10 一组、11–15 另一组，第二组行尾常带 `rowspan/colspan` 合并格），**只读前两行会整组丢失**。现在的规则：标签格按「不像本行内容」判（不维护白名单——数学卷有 `选项` 这种标签）、行尾空占位先修剪、多组循环配对、列数对不齐的那组不写并打 `[WARN] 答案表列数不齐`。**非答案表（数学数据表 `x|…|0|1|2` + 数值行）必须整表返回 `{}`**：旧实现会把 `0/1/2/3` 当题号、把表里的数值当答案写进第 1–3 题。回归用例 `tests/test_answer_table.py`，含真实表格逐字复刻。

**答案写入没有任何一致性校验**：`answer_importer` 拿到文档就写、写完 `answer_verified=1`，不会核对「这个值是不是来自试卷答案表」。所以**答案表解析只要静默少一格，缺的那题就会被后续「补空答案」随意填**，且被打上「已核验」（北师大实验 2024 物理卷第 1 题：真值 C，库里是 D）。改答案表解析后必须做**三方核对**（md 答案表 / `output/answers/*.md` / `questions.answer`），别只看「导入成功」。

**LLM 提示词的学科分派（2026-10-29）**：凡是同一任务要跑多学科的提示词，一律「`_common.txt` 放 JSON 契约/字段（**唯一真源**）+ `<subject>.txt` 放学科差异 + `_generic.txt` 兜底」，按 `<subject>` 加载。已落地的两处：`src/prompts/question_labeler/`（什么叫完整、哪些缺陷可修复、题型映射、难度分层）与 `src/prompts/question_kps/`（选点规则、角色名）。新增学科必须补对应文件，否则回退通用版。**不要**把学科规则写回 `_common.txt`，也**不要**恢复一份提示词全学科共用：语文 3 选项、画线句必丢，按数学标准会判「不足 4 项」并编出第 4 项；英语/物理标 KP 会顶着「初中数学老师」的角色选点。原文缺失型缺陷（画线句指向、加点字、图片内文字、未随卷给出的链接材料）在 `_UNREPAIRED_OK` 学科里允许 `is_complete=false` + `regenerated=null`，题材按原文入库并 `needs_review=true`（`is_active=0`），**不得**为了让题「看起来完整」而让模型补写。

例外：`kp_tree.txt` 只服务数学 KP 树初始化（内容基于《义务教育数学课程标准》），其它学科建树需另写课程标准提示词，不能靠换角色通用。

**语文试卷切分（2026-10-28 / 2026-10-29）**：阅读材料在题号之前，靠学科策略的材料归属（`split_page(..., strategy=get_strategy("chinese"))`，语文 `material_policy().attach=True`）按小节归属到每题的 `material_text`（含图片）；OCR 粘连的下一节标题在行尾，必须拆出并关闭本题，否则材料被吞进上一题题干；选项紧贴标点无空格，裸字母边界是「非英文/数字」；**标注失败不得丢题**（确定性兜底），LLM 修复产出的占位文本不得入库。**部分标题是材料边界**：`第一部分 北京城市发展史上的水源问题` 这类不带「选择/非选择」字样的标题（`is_part_header` 返回 `part_kind=None`）必须 `_start_scope()` 并把标题并入新材料，否则下一题仍挂上一节材料（东直门 2024 题3/5/6 全部拿到「前言」，被模型判「材料不完整」）。**二维码判定要兜底**：公众号码带 logo 时 `cv2.QRCodeDetector` 解不出（`detect` 也返回 None），`is_qr_code` 走 `_looks_like_qr` 形态判据（近正方/黑占比 0.35-0.62/边缘密度 ≥0.15/边长 60-400），阈值与真实配图（黑占比 0.05-0.06）有 5 倍间隔。

**题号识别的四个坑（2026-10-29 实测 32 卷）**：① 行内粘连 `…楼房。16.根据材料三…`（MinerU 合并两行）→ `_split_glued_next_stem`，只在题号 == 上一题+1 时拆，卷首考试说明 `150分钟。2.在试卷…` 因 `current is None` 不触发；② `8（1）转朱阁…` 题号后直接跟小问号（OCR 丢点，默写题常见）→ `_MAIN_STEM_RE` 第三分支，剥离时只剥题号保留 `（1）`；③ `## 2. 甲组同学推荐…` MinerU 把题号行识别成 markdown 标题 → 正则允许 `#{0,6}` 前缀，且材料小标题分支加 `and not ok`，否则被当材料吞掉；④ OCR 十位错认 `22 → 33 → 24` → 前跳一位且个位吻合时纠正为 23 并打 WARN。修完 32 卷缺号从 15 卷 32 处降到 10 卷 13 处，剩余是 md 里确实没有该题（MinerU 漏转），只能告警。**【甲】【乙】【丙】/①②③ 既可能是选项也可能是填空占位**：只有题干含「一项/下列/选择/最恰当…」才按选项拆（`subject_strategies/chinese.py` 的 `_CHOICE_STEM_RE`），否则 `我的分析：【甲】文…【乙】文…` 会被拆成 A/B/C。

**扫描件是 Markdown 的硬边界（2026-10-29 实测）**：`语文/初中/first` 32 份里 16 份无文字层。MinerU 的 OCR 能转出文字，但 Markdown **不表达下划线/加点/波浪线**——这些是图像像素。`emphasis_cli` 靠 PDF 字体坐标 + 图形层检测，扫描件 0 命中，只有文字版有效（大兴 36 处、五中 14 处）。**不要**指望改提示词或换 MinerU 参数解决：扫描件的画线句只能走 OCR 字符框 + 图像层横线检测（或视觉模型），未做之前一律 `needs_review`。

**语文知识点（2026-10-28）**：`knowledge_points` 两级树（code 前缀 `C01`/`C0101`，1 级 4 类 + 2 级 29 个），种子在 `tools/db/migrations/2026-10-28_add_chinese_knowledge_points.sql`（幂等）。标定命令 `python src/backfill_question_kps.py --subject chinese`（默认 math）。**题不标 KP 就进不了抽题池**（抽题 SQL 必须 JOIN `question_knowledge_points`）；**作文题不标 KP**（用户裁决：作文答案只是评分参考，标了会被专项练习抽到；新卷导入后需移除）。LLM 标注必须人工抽检（实测文言题会被误标现代文考点）。

**改动前必读三条**（细节见 `docs/data-refinery-管线总结与后续.md` §3）：① LLM 配置用 `.env` 的 `LLM_BASE_URL`/`LLM_AUTH_TOKEN`（refinery 专属），**不要用 `ANTHROPIC_*`**（会被 shell 里 Claude Code 覆盖）；② `db_loader` 的 full-reload 有**业务数据守卫**（库里有 answers/error_books 等外键数据时默认报错退出），需显式 `--purge-business-data`（按 FK 安全序清空）或改用 `--load-cards` 增量；③ 重抽目标页用 `unmark_extracted` 而非 `--force`（`--force` 绕过 skip 分支会断 lesson_id 的跨页继承回填）。

**入库范围与幂等（2026-10-28 用户裁决）**：**一次导入只允许改指定范围，且不得重写已完成的数据**。`db_loader_cli --load-cards` 必须配 `--subject` / `--file` / `--questions-only` / `--cards-only` 之一来限定范围（范围过滤与 full-reload 互斥，CLI 会拒绝）；卡片按唯一键 `(lesson_id, sort_order)` **原地 upsert**（`id` 不变、无变化跳过），**禁止删旧卡重插**（`practice_results.card_id` 是 CASCADE、`ai_dialogues.card_id` 会置 NULL）；题目按 `(paper_id, question_no)` 原址更新，`answer_verified=1` 不覆盖。

**统一范围参数**：`--subject/--stage/--term/--year/--file` 在 convert/extract/publish/db_loader/编排 CLI 同名同义，唯一实现在 `src/scope_filter.py`（不要在各 CLI 里各写一套归一）。日常单科/单卷导入用 `python src/import_cli.py --subject 语文 --year 2025`（convert→extract→publish→增量入库一条命令）。

其余 extract/publish/db_loader 细则（全角括号归一、页眉页脚剥离与书尾识别、二维码过滤、版次 edition 维度、页码锚定 lesson_anchor 等）属已稳定行为，见 `docs/ai-core-changelog.md`。
**语文试卷的着重号/下划线（2026-10-28）**：MinerU 的 Markdown **不表达下划线**，着重号也只是偶尔识别成 `<sub>．．</sub>` —— 语文卷「文段中加点词语 / 画横线句」的标记必须在入库后由 `src/emphasis_cli.py` 从 PDF 补回（`pdf_emphasis.py`：下划线=细填充矩形、着重号=字下 3pt 窄带小墨点，排除表格区域）。输出 `<u>…</u>` / **逐字** `<span class="cn-emphasis-dot">字</span>`；前端用 `::after` 画字下实心点（0.15em 纯黑，`text-emphasis` 无法调大小/颜色），下划线 2px 深色。**不要**把 `<sub>．．</sub>` 直接当最终展示（会变成字后小点）；也**不要**靠 LLM 猜哪些字被加粗/加点（不可复现）。该命令默认 dry-run、幂等、只改 `content/material_text/options/content_hash` 且写后校验其它列未变；目前只支持电子版（有文字层）PDF，纯扫描件需 OCR 字符框，暂不做。

**多选题（multi_choice，2026-11-01）**：卷面大题标题写「多项选择题」时，这一节的题一律 `multi_choice`——切题器 `RawQuestion.multi_choice` 带标记，`question_extract` 落库时覆盖 labeler 的 `choice`（模型只会给单选）。存量数据用 `python3 scripts/backfill_multi_choice.py`（默认 dry-run，`--apply` 才写；幂等，只改 `questions.type`）回填。**判断多选区间不能按扫到的题号**：OCR 会把「16.」认成「6.」，按题号会误伤前一大题的单选；脚本用「本大题之前最大题号+1 → 本节最大题号」的区间。判题侧 `multi_choice` 属于客观题（exact），答案按字母集合比对（`BD` == `DB`），**不做部分得分**。

**题型一律按大题判，不要按单题特征猜（2026-11-01）**：`section_analyzer.analyze_sections()` 先扫 md 的大题标题，把「第 A–B 题 = 什么题型」划好，切题后整段覆盖 labeler 的 type。**不要**再依赖「能拆出 4 个选项就是选择题」——物理实验题常用 A/B/C/D 标四幅图（人大附第 22 题），按特征会把整节实验题改成选择题。标题丢了时用标题里的「共 X 分 / 每小题 Y 分」算应有题数来定位换题型的位置（比选项特征可靠），缺口整段判一个题型；数学「解答题」混排 proof/calculation，不整节覆盖。存量用 `python3 scripts/backfill_section_types.py`（默认 dry-run）。

**清 `options` 前必须并入题干（2026-11-01）**：把题型从 choice 纠正成 short_answer/fill_blank 后，旧 options 往往就是题干的一部分（物理实验题的四幅图、选择题的四个待选答案）——**直接 `options=NULL` 会让题干残缺**。正确做法：把 options 里题干还没出现的文本按 `A. …` 追加到 content，再清空 options 并重算 content_hash；`extracted`/`published` 两份产物同步改，否则下次导入会灌回来。
