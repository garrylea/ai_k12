**Python 目录收敛（2026-11-05）**：`tools/data-refinery/` 下**只有一个 Python 目录 `src/`** —— 库模块、阶段 CLI、一次性回填/迁移、回归与运维入口全部在此；原 `scripts/` 的 7 个文件已并入 `src/`，**不要**再新建 `scripts/` 或往项目根目录新增工具脚本。`src/` 是扁平 import 命名空间（无 `__init__.py`，由 `conftest.py` 把 `src/` 加入 `sys.path`），运行统一 `python3 src/xxx.py`，脚本内无需再 `sys.path.insert`；`ROOT = Path(__file__).resolve().parents[1]` 仍指向 `tools/data-refinery/`。目录树与约定见 `tools/data-refinery/README.md` §目录。

**素材格式与唯一发现入口（2026-11-05）**：`convert` 的输入格式由 `src/scanner.py` 的 `DOCUMENT_SUFFIXES` 唯一决定 —— 当前 `.pdf` / `.doc` / `.docx` / `.ppt` / `.pptx`（整份文档，一份文件一个 `Material`）+ `page_*.jpg`（教材拆页图片）。**`MaterialScanner` 是唯一素材发现入口**（`convert_cli` 与 `import_cli._scan_rel_paths` 都调它），不要另写扫描逻辑。**新增输入格式必须同时改 `scanner.py` 的 `DOCUMENT_SUFFIXES` 与 `convert.py` 的 `MineruRunner._DOCUMENT_SUFFIXES`**，两处必须相等（`tests/test_scanner.py::test_suffixes_match_convert_layer` 是对账护栏）；否则发现层收进来、执行层按拆页图片走错日志与 15s 节流。历史坑：MinerU `extract` 一直支持 Word/PPT，`convert.py` 也早就列了 Office 后缀，但 `scanner.py` 只扫 `*.pdf`，手工放进 `crawler/data` 的 Word 被静默漏掉、连 `--dry-run` 都不列。**Office 的 `kind` 复用 `"pdf"`**（语义是「整份文档」，不是字面 PDF）：`--source smartedu` 只认 `kind="images"`，Word 卷走默认 `--source all` 或命名带「试卷/答案」走 `zgkao`；同目录同名不同后缀（`foo.pdf` + `foo.docx`）时 PDF 保留原名、Office 那份 rel_path 加 `_docx` 等短后缀区分，避免输出目录撞车。**`kind` 是分流分类，不得直接打印成文件格式名**：`convert_cli._input_label()` 负责在 `--dry-run` 里显示真实后缀（`(docx)` 等），否则 docx 会被显示成 `(pdf)`、用户以为自己的 Word 没被找到（2026-11-05 实测踩过）。另：**`--dry-run` 不调 MinerU**，`output/md` / `output/published` 不会新增产物，因此 stage4（paper_meta）/ stage5（db_loader）的「0 命中」是预期、不是素材没发现；`extract_cli.py` 的 `[scope] -> N 个文件` 是 `--file` 过滤前的计数。

`convert_cli (MinerU) -> extract_cli (LLM) -> publish_cli (物化图片) -> db_loader_cli (MySQL)`；`refinery_cli.py` 串联 publish + db_loader，DB 由 `tools/db/install_mysql.sh` 初始化。题目内容回写工具 `answer_importer`（JSONL/Markdown → questions 的 answer/approach/explanation/type，`--export` 出模板 / `--apply` 幂等写入）。试卷答案补录是**两段式**（2026-10-28）：`answer_extract_cli`（按学科策略从 md 提取 → 答案文档）→ `answer_importer --doc --paper-id`（回写，`answer_verified=1`）。

**识别问题分「题号层」和「内容层」，两层都要扫（2026-11-01）**：`recognition_scan` 原来只查题号（缺号 / 顿号题号 / 修复砍短 / 噪声题），题号齐、正文坏的一律静默 —— 人大附 2024 物理 34 题号全在，第 27 题缺小问 (1)、第 24 题吞了第 25 题、第 25 题装着第 23 题的正文，三处一个都没报。现在加两类确定性判据（**不调 LLM**）：`incomplete_content`（小问从 (2) 起且无 (1)；或 `needs_review` 且 `labeling_issues` 有 `is_complete=false`）、`merged_content`（正文里出现另一个题号**且** md 里该题号后面确实是这段话；或本题正文开头在 md 里**唯一**归属于另一个题号 —— 多归属时不报，避免「两题都以『如图所示…』开头」误伤）。人工确认走一张题卡（2026-11-26）：`k` 只落 `verdict=no_change`、**一个字段都不改库**；`回车` 有改动才生成记录、没改动什么都不发生；`s` 保持 pending；**有未保存修改时 `k`/`s` 必须二次确认**（第一次只警告，避免把刚改的内容当「确认」丢掉）。**收口按题目身份 `(source, group_order, sub_no)`**：同一小问的多条 flag 一次全关、**不跨 `sub_no`**，绝不换个 kind 再问同一道题（`mark_issue` 的 `sub_no=None` 表示旧语义「整题」；`statuses` 只允许 pending/recorded，**不得把已 resolved 降级**）。`repair_truncated` 不强制整题重录：把修复前原文（`labeling_issues.jsonl.original_content`；issue 的 `excerpt` 被 `_excerpt` 截到 600 字，**不可**用于恢复）与修复后并列给人工校对一次，选「恢复原文」才生成 `content_only` 记录，`apply_fixes` 只改题干，选项/材料/答案一律不碰；**不要盲目把「砍短」当修复失败**——西城模拟一题18 的原文反含坏填空和邻题「19题图」，修复后才干净；补录在题卡主菜单里选段：`1` 题干/选项、`2` 共享材料、`3` 题内材料、`4` 答案、`5` 图；槽内**回车=不改、其余输入都是内容、命令一律 `:` 前缀**（`:e`/`:l`/`:f`/`:c`/`:p`），**槽位不存在也照样问**（PDF→MD 丢材料时这是唯一入口）。`E` 编辑器改整题、`R` 全换（清材料/图、`material_url` 显式置空、答案保留）、`u` 用修复前原文。共享材料有 URL 就改正文并同步同卷；没有则允许新建（粘全文 + 指定共用题号），`apply_fixes._create_article_doc` 按「试卷+正文」算 key 写文档，并把 `material_url`/`content_hash` **直接写库**（publish 不写库）挂到本题与共用题；题内材料永远可改/可补，写 `material_text`；只有 `k` 等同「确认无问题」（只落 `verdict=no_change`）。**答案清空必须显式**：记录带 `clear_answer=True` 才写 `answer=''`；没有该字段的空答案按旧语义 `COALESCE(NULLIF(%s,''), answer)` 保留原值，**不要用「空答案」表达清空**。extracted 里读不到当前题时只能整题重录，避免盲写空题干。`content_sig`（正文归一化后的 md5）是让旧结论失效的开关：正文变了 `reopen_changed` 自动退回待确认。**`verdict=no_change` 的 resolved 记录没有补题记录，`reopen_unbacked` 必须跳过它**，否则每次扫描都会把「确认无问题」退回待处理。**`applied=true` 只证明「当时写过库」，不证明「现在还活着」**（2026-11-01：人大附重导一次就把人工补的 7/16/18/23 摘掉、把第 6 题重置成 `is_active=0`，而清单一直显示已解决）。两道对账缺一不可：`reopen_unbacked(present=当前 extracted 题号集合)` —— 缺号类补题只要切题产物里仍没有该题号就重新打开；`apply_fixes._replay_reason` —— 写库前查库，题没了或 `is_active=0` 自动重放。**扫描豁免名单与标注豁免名单刻意不同（2026-11-19 改）**：`recognition_scan._UNREPAIRED_OK_SUBJECTS` 只剩 `{道法, 历史, 地理, 生物}`，**语文已移出** —— 语文的画线句/加点字/图片内表格缺失也进人工补题队列，由人决定是否从 PDF 补；此前静默 `is_active=0`（八中 2026 期中题 7/21 使 26 题变 24 题，无人收到通知）。`question_labeler._UNREPAIRED_OK` 仍含语文，**不要为了对称去改它**：那是标注开关，删掉会逼 LLM 编造原文；扫描这边只管「是否报给人工」。豁免的科目仍只留确定性判据（小问从 (2) 起 / 前后题合并）。

**判断题不参与「有无设问」的完整性判定（2026-11-06）**：判断题题干就是一句陈述，「缺少设问」由题型决定，不是缺陷。LLM 完整性检查按「有没有设问」判，海淀道法 10 道判断题里 8 道被判 `is_complete=false` → `needs_review` → `is_active=0` → 学生端整卷少 8 题。放行规则（**确定性，不看 LLM 措辞**）在 `question_labeler._true_false_stem_is_self_contained`：题干带图、或去标签后 ≥6 字且不以 `，、；：（` 收尾；由 `apply_true_false_exemption` 在**两处**调用 —— labeler 出结果时 + 按大题定型之后（LLM 常把判断题标成 `short_answer`，定型后才改成 `true_false`，只在第一处改会漏 5 题）。真空题干/明显截断仍然拦，`is_active=0` 保留。

**道法大题按小问拆 + 三条「误判不得隐藏题目」的确定性豁免（2026-11-23 重构）**：道法大题（35 中 26–28、海淀 2026 26–30）是「材料 → `(1)` → 材料 → `(2)`」结构，由 `subject_strategies/politics_subquestions.expand()` 在 `split_page` 末尾拆成多条题：每条 `group_order` 仍是原大题号、`sub_no=1..n`，正文从 `(N)` 到该小问分值行，材料归到对应小问；**分值只展示，不参与能否拆的判定**（读不到就留 NULL）。无自有材料但正文指代「结合材料/两个活动」的小问继承前序材料；`+学科观点` 这类平台残留整行丢弃。只有 `(1)` 或末句设问的题不做小问拆分，走 `politics_subquestions.split_tail_question_rule`（最后一个非空行、以设问词起头、材料 ≥60 字、材料里没有两行 A–D）。**道法不再复用物化的 `material_split.py`**（那只服务物理/化学）。材料渲染位置**不入库**（2026-11-24 删列）：后端按学科下发 `materialPosition`——物理/化学/道法是 `before`（题干上方），语文/英语为 `null`（题干下方），映射在 `apps/server/src/common/subject-config.ts` 的 `materialPositionFor()`；管线与试卷数据都不再写这个字段。**不要**给 politics 开 `material_policy().attach`：`## 研学任务单`/`## 展品一` 会被跨题状态机当成边界，26 题被切碎。`section_analyzer._EACH_SCORE_RE` 必须同时认「每小题」与「每题」——只认前者时「二、选择题（共15题，每题2分，共30分）」的区间会铺到 30，26–30 被当选择题、拆不出选项 → 整段 `is_active=0`。另外三条 LLM 断言可直接用 Python 核对，核对不成立必须放行：`apply_material_subq_exemption`（说「仅包含第(1)问」但 content 里确有 `(2)`）、`apply_kp_issue_exemption`（issue 全是「知识点列表为空/匹配不到 code」——那是我们没建 KP，不是题目缺陷）、`apply_material_sections_exemption`（说「缺三段视频素材/缺①②③序号」但 material_text 已有 ≥3 个 `## ` 分段——海淀题 28 的三段文字就是被排序的素材，原文没有视频也没有编号）。真缺陷（材料里确实没有对应分段/小问）仍然 `is_active=0`。`_split_inline_material` 必须 `getattr(strategy, "split_material", None)` 判空：语文/英语没有该钩子，裸调用会在重抽时 AttributeError。

**答案提取的学科分派**：`src/subject_strategies/` 一科一份 `extract_answers`（语文独立实现；数学/物理/化学/道法走 `generic.py` 的整卷对齐；英语复用整卷对齐后再单独展开答案区区间格式），入口统一 `get_strategy(code).extract_answers(text, md_path)`；未登记学科（生物/历史/地理等）抛 `UnknownStrategyError`，不回退 generic。**MinerU 把答案输出成 HTML 表时，英语与其它学科共用 `question_splitter.parse_answer_table`，不要在英语策略里另写一套表格分支**。**英语答案区必须支持 `1-5 CBBCD` / `11-12 BB`**：按印刷题号逐项展开；答案数与区间长度不等时整段不展开并写 issue，绝不按位置猜。该规则只在英语策略内，不能塞回通用 `question_splitter`（否则会改变数学/物理等答案对齐）。答案提取的学科 code 由 `subject_codes.subject_code_for_path(rel_md, default="")` 得出——**不给默认 `math`**，路径首段不是已知学科目录就报错跳过（答案写错学科比提取失败更危险）；**不要**把语文特例塞回通用 `question_splitter`，也**不要**在标点归一化里映射「、」（中文大题序号分隔符，归一后大题标题会混进上一题答案）；答案段题号必须**递增**，回退编号是评分细则，不能开新答案段（否则串到第 1 题）。**学科名映射只认 `subject_codes.SUBJECT_NAME_TO_CODE` 一份**（2026-11-06）：爬虫目录简称与 `subjects.name` 全称都要收录（`道法` / `道德与法治` → `politics`）；漏一个别名，`subject_code_for_parts(..., default=None)` 就返回 `None`，extract 第一步直接报「学科 code 为空」，整卷 0 题。

**答案区必须按块解析（2026-11-25；2026-11-28 扩顿号）**：`question_splitter` 只负责定位答案区，表格、裸选择、统一编号块和未知块由 `answer_blocks.py` / `answer_region.py` 处理。禁止恢复 `current_answer_n` / `last_answer_n` 逐行游标。多个独立答案块对同一题遵循“第一套非空答案优先”；不能确定边界时整块不猜并写 issue。没有答案区时安静返回；有答案区但零命中时必须产生 `answer_region_no_assignments`，`answer_extract_cli` 返回 2，`answer_backfill` 计入 failed。**统一编号块的题号分隔符必须同时覆盖 `.` / `．` / `、`，且块边界识别与块内题号扫描两处保持一致**（76522 的 `9、… 10、…` 曾整组落入 unknown）；这里的顿号支持只作用于答案题号，不等于在全局标点归一化里映射 `、`。**无题号的块级 issue 必须在有其他题目答案时也透传**：`generic.py` 要把 `question_no=None` 的 `answer_block_unparsed` 等统一追加到全局问题记录，不能只在整卷零命中时才写，否则日志只剩若干 `answer_missing` 症状、真正的块解析原因被吞掉。

**题解内嵌分段（2026-11-27）**：答案块必须先按题号归属，再由 `answer_sections.py` 拆分。`答案/正确答案/参考答案` → `answer`，`解析/分析/思路/解题思路` → `approach`，`详解/解答/点睛` → `explanation`；裸 `解：/证明：/原式：` 不单独迁移。疑似混入多题答案、只有解析/详解而没有答案正文、或代码围栏未闭合时必须跳过并报告，不猜。存量整理时已有 `approach` / `explanation` 保留在前，新内容以空行追加在后，`answer_verified` / `content_hash` 不变。extract → publish → db_loader 必须全程透传 `approach`；其中图片必须按 `approach_NN` 物化，入库护栏同时检查 `approach`。勿在各学科策略里另写一套分段标题或字段映射。

**转换丢失的选项/答案只记录、不自动修（2026-11-17）**：选择题 `options` 少于 4 项（语文少于 3 项）记 `options_incomplete`；md 自带答案区但题库答案为空记 `answer_missing`。这两类都是 MinerU 转换损失，脚本不做猜测式补齐，只进 `recognition_issues.jsonl` 让人工补题。答案缺失必须以**题库**为准（第 6 步才回填），且只在 md 有答案区时检查。

**试卷/答案页码清洗（2026-11-17）**：MinerU 单 MD 没有页边界，页脚是普通文本行；试卷/答案链路必须在 `split_page` 前调用 `page_markers.strip_page_markers`（主提取 / publish 兜底 / 独立答案 / 答案回填 / 语文加点五个入口）。publish 兜底不能省：`db_loader` 只读 published，旧 published 带页脚会在重跑入库时把页脚写回库。**禁止用「删除纯数字行」清页码**（一零一物理的 `1/2/3/4` 是图片标号）；`本试卷共8页`、正文「第 N 页」引用不得删。答案区用 `question_splitter.is_answer_structure_line` 跳过页码/小节标题（`（二）（共 5 分）`），语文 `_align_by_number` 同步跳过。存量清洗用 `python3 src/fix_page_markers_cli.py --apply --yes`，必须保留备份；`content` 变化重算 `content_hash`，冲突整行跳过，不重置 `answer_verified`。新页脚形态先补 `page_markers.py` 与 `tests/test_page_marker_corpus.py` 的 auto/negative/manual 分类，不要静默放过。弱锚点除独行 `第N页`/`共N页` 外，还有「第」被 OCR 丢掉的独行 `2页 共7页`（昌平一中语文 2024 实测，一脏脏三题）。

**答案表格必须按版式分派，不能按位置猜（2026-11-01；2026-11-25 扩展填空答案）**：`question_splitter.parse_answer_table` 以前写死「每行跳过第 0 格」（那是「题号/答案」标签位），但真实卷有三种版式：① 双标签 `题号|1|2…` + `答案|A|B…`；② 单标签（只有数字行有标签）；③ **无表头** `1|2|3…` + `C|D|A…`（第一格就是题号 1）。②③ 会把**首题答案整格丢掉**。另外一张表里可能有多组「数字行+答案行」（如 1–10 一组、11–15 另一组，第二组行尾常带 `rowspan/colspan` 合并格），**只读前两行会整组丢失**。现在的规则：标签格按「不像本行内容」判、行尾空占位先修剪、多组循环配对、列数对不齐的那组不写并打 `[WARN] 答案表列数不齐`。**选择题和填空题共用同一表格解析**：A–D 之外的公式、数值、比较符也按列提取；自由文本必须带明确的「答案/选项/解答」标签，无标签或空标签不猜，HTML 实体统一反转义（`&lt;` → `<`）。**非答案表（数学数据表 `x|…|0|1|2` + 数值行）必须整表返回 `{}`**，否则会把数值当答案写进题号。回归用例 `tests/test_answer_table.py` 与 `test_natural_sciences.py`，含昌平 2026 数学 9–16 题真实表格。

**答案写入没有任何一致性校验**：`answer_importer` 拿到文档就写、写完 `answer_verified=1`，不会核对「这个值是不是来自试卷答案表」。所以**答案表解析只要静默少一格，缺的那题就会被后续「补空答案」随意填**，且被打上「已核验」（北师大实验 2024 物理卷第 1 题：真值 C，库里是 D）。改答案表解析后必须做**三方核对**（md 答案表 / `output/answers/*.md` / `questions.answer`），别只看「导入成功」。

**LLM 提示词的学科分派（2026-10-29）**：凡是同一任务要跑多学科的提示词，一律「`_common.txt` 放 JSON 契约/字段（**唯一真源**）+ `<subject>.txt` 放学科差异 + `_generic.txt` 兜底」，按 `<subject>` 加载。已落地的两处：`src/prompts/question_labeler/`（什么叫完整、哪些缺陷可修复、题型映射、难度分层）与 `src/prompts/question_kps/`（选点规则、角色名）。新增学科必须补对应文件，否则回退通用版。**不要**把学科规则写回 `_common.txt`，也**不要**恢复一份提示词全学科共用：语文 3 选项、画线句必丢，按数学标准会判「不足 4 项」并编出第 4 项；英语/物理标 KP 会顶着「初中数学老师」的角色选点。原文缺失型缺陷（画线句指向、加点字、图片内文字、未随卷给出的链接材料）在 `_UNREPAIRED_OK` 学科里允许 `is_complete=false` + `regenerated=null`，题材按原文入库并 `needs_review=true`（`is_active=0`），**不得**为了让题「看起来完整」而让模型补写。

例外：`kp_tree.txt` 只服务数学 KP 树初始化（内容基于《义务教育数学课程标准》）。其它学科必须另写课程标准提示词（道法：`kp_tree_politics.txt`），并给 `generate_kp_tree.py` 传 `--subject/--prompt/--code-prefix`（道法 `DF`）。该脚本支持 `--json-out`（先审后写：生成候选树存 JSON）、`--from-json`（从审过的 JSON 出 SQL，跳过 LLM）与 `--retries`（LLM 输出形状会抖，数量越界时重试而不是放宽校验）。**审阅的对象必须是最终写进迁移的那棵树**：LLM 每次输出不同，`--json-out` → 人工抽检 → `--from-json` 是不可省的顺序。

**语文试卷切分（2026-10-28 / 2026-10-29）**：阅读材料在题号之前，靠学科策略的材料归属（`split_page(..., strategy=get_strategy("chinese"))`，语文 `material_policy().attach=True`）按小节归属到每题的 `material_text`（含图片）；OCR 粘连的下一节标题在行尾，必须拆出并关闭本题，否则材料被吞进上一题题干；选项紧贴标点无空格，裸字母边界是「非英文/数字」；**标注失败不得丢题**（确定性兜底），LLM 修复产出的占位文本不得入库。**部分标题是材料边界**：`第一部分 北京城市发展史上的水源问题` 这类不带「选择/非选择」字样的标题（`is_part_header` 返回 `part_kind=None`）必须 `_start_scope()` 并把标题并入新材料，否则下一题仍挂上一节材料（东直门 2024 题3/5/6 全部拿到「前言」，被模型判「材料不完整」）。**二维码判定要兜底**：公众号码带 logo 时 `cv2.QRCodeDetector` 解不出（`detect` 也返回 None），`is_qr_code` 走 `_looks_like_qr` 形态判据（近正方/黑占比 0.35-0.62/边缘密度 ≥0.15/边长 60-400），阈值与真实配图（黑占比 0.05-0.06）有 5 倍间隔。**但形态统计会误伤黑白纹样**（2026-11-02：86419 题 2 的铜镜选项图 184×184、黑占比 0.378、边缘 0.179，四项全中，C 选项被删成空白）——真二维码三个角各有「黑-白-黑」三层嵌套的定位图案，黑白装饰纹样没有。所以 `_looks_like_qr` 最后必须过 `_finder_pattern_groups(img) >= 2`（按边长聚类，取最大一组）；同批语料 352 张判码图里 13 张是 0–1 组（铜镜/物理实物图），改后不再误删，带 logo/裁边的真码仍有 2–4 组继续删。**不要**改成 3：实测 4 张真码只能检出 2 组。宁可漏判（留下二维码）也不误删配图。

**题号识别的四个坑（2026-10-29 实测 32 卷）**：① 行内粘连 `…楼房。16.根据材料三…`（MinerU 合并两行）→ `_split_glued_next_stem`，只在题号 == 上一题+1 时拆，卷首考试说明 `150分钟。2.在试卷…` 因 `current is None` 不触发；② `8（1）转朱阁…` 题号后直接跟小问号（OCR 丢点，默写题常见）→ `_MAIN_STEM_RE` 第三分支，剥离时只剥题号保留 `（1）`；③ `## 2. 甲组同学推荐…` MinerU 把题号行识别成 markdown 标题 → 正则允许 `#{0,6}` 前缀，且材料小标题分支加 `and not ok`，否则被当材料吞掉；④ OCR 十位错认 `22 → 33 → 24` → 前跳一位且个位吻合时纠正为 23 并打 WARN。修完 32 卷缺号从 15 卷 32 处降到 10 卷 13 处，剩余是 md 里确实没有该题（MinerU 漏转），只能告警。**【甲】【乙】【丙】/①②③ 既可能是选项也可能是填空占位**：只有题干含「一项/下列/选择/最恰当…」才按选项拆（`subject_strategies/chinese.py` 的 `_CHOICE_STEM_RE`），否则 `我的分析：【甲】文…【乙】文…` 会被拆成 A/B/C。

**题号/选项标记位的分隔符（2026-11-21）**：题号与选项标记后允许 `.`/`．`/`、`/`，`（`question_splitter._MAIN_STEM_RE`、`_STEM_PREFIX_RE`、`_BARE_INLINE_RE` 等，语文 `chinese._LATIN_FLEX_RE`）—— 西城 2026 模拟二实测 `23，结合文中…`（题号）与 `C，交代了刘子骥的结局…`（Q14 选项），旧正则只认 `.．` 导致 Q23 丢题、Q14 的 C/D 被吞进 B。**勿动**全局标点归一化表（`chinese._FULLWIDTH_TO_HALF` 仍不映射 `、`）：大题标题「一、选择题」靠中文数字不匹配题号正则来避开，不是靠归一化；答案区 `split_inline_stems` 仍只认 `[.．]`，给它加 `，` 会把「每空1分，共2分」的 `2分` 误判成题号。反例护栏见 `tests/test_question_splitter.py`（`A、B、C、D 四点` 不拆）。

**材料标题与题间材料（2026-11-07）**：`发言稿一 烽火古道 赤诚抗日` 这类 13–24 字的带序号栏目标题也是材料边界——旧 12 字上限会让题1 吞掉题2/题3 的文段；两题之间的无标题文段是**新的材料域**，要替换该节旧材料并让后续同节题共享（只挂下一题会让题5 缺材料；叠加旧材料会让题5 拿到题2/题3 的「发言稿一」）；`looks_like_between_material` 必须排除选项行（分段落排版的 D 会被误判成材料，整段语段反而丢失）。**`material_text` 不在 `content_hash` 里**：同卷重导时 `old_hash == chash` 也必须比较并写 `material_text`，否则 JSONL 已挂新文段、题库还停在旧材料（2026-11-07 海淀题2/题3 实测）。

**小节标题只做材料边界，绝不进 `material_text`（2026-11-22）**：语文 `（一）阅读《…》，完成 12-14 题（共 N 分）` / `(一)默写。(共4分)` 这类标题在 `question_splitter.is_section_header` 命中时**只 `_start_scope()` 重置材料域，不把标题行 append 进 `scope_pending`**。为什么：阅读小节后面有正文会盖过标题，但默写等**没有文章**的小节会把标题当成唯一材料（东城模拟一 Q6 实测 `material_text='(一)默写。(共4分)'`；海淀模拟二 5170–5172 同病）。**两层防线都别拆**：① 切题器不 append（防新数据）；② `chinese_material_doc.is_heading_only` 必须把裸标题（无 `##`）也当标题（`_SECTION_INSTRUCTION_RE` 命中即跳过，`:61-79`），否则 publish 清理救不了存量。回归钉是 `test_question_splitter.test_section_heading_never_becomes_material`（**同一 fixture** 同时断言 默写无材料 / 阅读不串节 / 文言文裸子篇保留 / 任何材料不含小节标题行——修一边破另一边必红）与 `test_chinese_material_doc.test_heading_only_true_for_bare_section_header`。**勿动**：`is_section_header` / `_SECTION_INSTRUCTION_RE` 的 `[一二三四五六七八九十]` 是**中文数字**，不要扩到阿拉伯数字——扩了会把默写小问 `(1)(2)…` 当成小节标题切断。

**语文文章外置为 md（2026-11-20）**：整篇文章（阅读/古诗/文言文/非连续文本）在 `publish` 阶段发布为 `output/assets/materials/chinese/{doc_key}/content.md`，`questions.material_url` 指向它（同节每题存同一个 URL）；**`material_text` 只放题中素材**（题号之内、这道题自带），文章题为 NULL，训练轨试卷不再把文章复制到每题 `material_text`。**`publish` 不调 LLM**：题内素材按规则确定性切分，切不动的进 `output/material_inline_review.jsonl` 由单独 CLI 处理，不阻塞 publish。`image_rewrite._CANONICAL_PREFIXES` 与 `db_loader._CANONICAL_IMG_PREFIXES` 的图片白名单必须同时含 `materials/` **和** `material/`（后者是物化回填已有的单数目录，漏了会在重发布时报「未物化」）。

**扫描件标记 dry-run（2026-11-07）**：`src/scanned_emphasis.py` 用 PaddleOCR mobile + 图像连通域检测加点/下划线，`--pdf/--subject/--file` 可出清单（`output/scanned_emphasis_dryrun.jsonl`），不改库/不改 md。已知表格表头边框会误报（`confidence=low` 的单字下划线同理），dry-run 仍用于人工复核。

**语文标记只按材料块识别（2026-11-07 用户裁决）**：入口是 `material_text` 非空且题干命中 `加点/画线/下划线/波浪线/着重号`；用 MinerU JSON 的 `page_idx + bbox` 只裁材料块（`material_bbox.match_material`）；电子版走 `pdf_emphasis.detect_decorations(regions=...)`，扫描件走 `scanned_emphasis.detect_material_marks`（PaddleOCR **只 OCR 裁剪块**）；注入只写 `material_text`，不再扫题干。`convert` 必须 `-f md,json`，否则没有块坐标。无 JSON 时：电子版回退整份检测但仍只注入材料；扫描件跳过并提示重新 convert。**不要**恢复整页/整份 PDF 的扫描，也不要把题干里的「不正确」当加点。

**选择题的「加点/画线标记丢失」可以自动放行（2026-11-07）**：语文卷的加点字/画线句标记常是图片像素，`pdf_emphasis` 对扫描件/水印件检测不到（海淀 2026 期中只检出 15 处水印「易水小寒转发」）。选择题只要**选项自己点名了考点**——引号内的词、≥4 字原文片段能在材料/题干找到，或选项是「第①②句」且材料确有对应圈号——缺视觉标记不影响作答，由 `question_labeler.apply_lost_mark_choice_exemption` 放行（判据是结构，不看 LLM 措辞）；**简答题没有选项可自证，仍保持 `is_active=0`**（题6/12/21 类）。不要把所有「画线句缺失」一刀切放行，也不要把这类题强行改写成「文中第 N 句」。

**扫描件是 Markdown 的硬边界（2026-10-29 实测）**：`语文/初中/first` 32 份里 16 份无文字层。MinerU 的 OCR 能转出文字，但 Markdown **不表达下划线/加点/波浪线**——这些是图像像素。`emphasis_cli` 靠 PDF 字体坐标 + 图形层检测，扫描件 0 命中，只有文字版有效（大兴 36 处、五中 14 处）。**不要**指望改提示词或换 MinerU 参数解决：扫描件的画线句只能走 OCR 字符框 + 图像层横线检测（或视觉模型），未做之前一律 `needs_review`。

**答案/解析导入（2026-11-05；PDF 支持 2026-11-19）**：`import_cli --answers <path>` 把指定答案文件交给第 6 步 —— `.md` 走 `answer_importer --doc`，`.jsonl` 走 `--records`，`.pdf` 走「复用/转换 md → 按学科提取答案文档 → --doc」（**绝不能把 PDF 直接当文本读**，PDF 头 `%\xc4…` 会报 utf-8 decode 错）；非 dry-run 自动补 `--apply --yes`，dry-run 只出 diff。定位（`.pdf`/`.md` 统一走 `_resolve_answers_paper`，2026-11-25 改）：**显式 `--paper-id` > 答案文件名去「答案」后缀（最长优先剥一次，`_strip_answer_suffix`）模糊查 `exam_papers.title`/`source_key`**；1 份打印卷名让你确认、多份编号让你选、0 份提示改名；`# 试卷：` 标题不再参与 `--answers` 定位；非交互终端不猜，引导用 `--paper-id`；运行时打印 `[匹配] 依据=… → paper_id=…`。**硬冲突（同给立即报错并逐一点名冲突参数）**：范围参数 `--subject/--stage/--term/--year/--file/--files`、重建参数 `--reconvert/--re-extract/--re-publish/--redo`、`--preview`（原实现会在预览中误写库）/ `--cards-only` / `--fix-only`。`--answers` 只导答案，这些参数会把流程拉回 convert~入库整条管线或别的操作；用户带 `--subject/--year` 时往往以为只是补答案，**必须打印冲突并停下，不能默默跑全管线**（2026-11-19 用户明确要求）。可搭配的只有 `--paper-id` / `--dry-run`。**重名卷在终端里列表选择、脚本里用 `--paper-id`，不能用 `--file`**（硬冲突，直接报错）。「昌平一中」实测同时命中 2024 语文 #26 与 2026 数学 #362。Markdown 每题**必须**有非空「答案：」（`_validate` 硬校验），「思路/解析/题型」可选、可多行，围栏代码块原样保留；`# 试卷：` 标题用于定位。**卷名同时匹配 `exam_papers.title` 与 `source_key`（素材原名）**（2026-11-07 修）：库内 title 已被 paper_meta 归一化成「年 地点 年级 考试类型」，只比 title 会让「拿素材文件夹名当标题」的文档永远打不中（海淀道法卷 `# 试卷：2026北京海淀初三（上）期中道德与法治` → 库里 `2026 海淀 初三 期中`#433）；匹配顺序为 title 精确 → source_key 末段精确 → title 子串 → 唯一候选，仍多条才列候选（候选行会并列「来源：原名」），0 候选明确说「没有标题或素材路径包含…」。`--list-papers` 同口径。**字段名允许 Markdown 强调与列表前缀**（LLM 生成的文档常写成 `**答案：** A` / `- **答案：** A`），解析层（`answer_doc.FIELD_RE`）统一识别并剥掉值的整体强调，缺这个容忍会把有答案的题误判成「缺少答案」。**只给 `--answers`（范围/重建参数已被 parse_args 硬拒绝，只剩 `--paper-id`/`--dry-run`）时只跑第 6 步**，自动跳过 convert~入库与 7/8/9 步（`_answers_only()` 兜底，`tests/test_import_cli.py` 有判定用例）。

**试卷+答案成对导入（2026-11-24）**：同一素材目录下同时有 `X-试卷.pdf` 与 `X-答案.pdf` 时，`--file/--files` 解析出试卷后会主动找同目录的答案兄弟，只把答案追加进 convert 的 `--materials`（逗号 OR）；切题时由 `maybe_merge_answer_md` 合并，extract/publish/load 仍只处理试卷。答案名直接当关键词时会反向收敛到试卷。只支持同目录 + `-答案/_答案/（答案）/(答案)/答案` 命名；跨目录或命名不规整用 `--answers` / `--paper-id`。`--preview` 也会转换答案（有一次 MinerU 成本）。

**PDF 答案的拆解与匹配（2026-11-19）**：答案文件名按 `（答案）`/`(答案)`/`-答案`/`_答案`/`答案` 最长优先剥一次才能命中试卷——八中 `…试卷答案.pdf` → `…试卷` → paper 667；转换出的 md 首行标题被 paper_meta 归一化后拿去查库是 0 命中，**不要用标题定位 PDF**。`output/md/…/X答案.md` 已存在就直接复用（零 MinerU）；PDF 必须在素材目录下（学科识别依赖目录首段）。`answer_extract_cli --file` 要传 md 的 **stem**，`normalize_path` 会剥 `.md`，带后缀反而不命中。语文 `chinese._align_by_number` 用 `split_inline_stems` 拆 `1.… 2.A` / `(三)…12.A13.A14.…` 这类行内多答案（**用原文拆、不写回半角标点**；须题号严格递增且首个 > last_no，作文评分细则的回退编号续行不受影响）——八中样例 17→26 题、0 issues；写库键是 `(paper_id, question_no)`，印刷题号 1–26 无偏移。

**试卷题的知识点链路（2026-11-05）**：`knowledge_points` 在 `extract` 阶段由 `question_labeler` 产生、写进 `output/extracted/*.jsonl`；**必须经 `publish` 透传并在 `db_loader.load_questions` 落 `question_knowledge_points`**。`publish` 用 `ExamQuestion(**raw)` + `model_dump()` 重建记录，**Pydantic 会静默丢弃模型里没有的字段** —— 这正是 2026-07-12（publish 建立）到 2026-11-05 期间试卷题永远没有知识点的根因（extract 标了、publish 扔了、db_loader 也没写入路径）。**新增任何需要入库的 extract 字段，必须同时加进 `models.ExamQuestion`**，否则会被静默丢。**不要把 `backfill_question_kps.py` 当常规路径**：它只用于存量补标（再跑一次 LLM），常规导入已自带 KP。另：人工复核答「没问题」（`verdict=no_change`）**不会**把题设为 `is_active=1`（只记裁决、不改库），存量修复用 `src/fix_question_kps_and_active.py`。

**语文知识点（2026-10-28）**：`knowledge_points` 两级树（code 前缀 `C01`/`C0101`，1 级 4 类 + 2 级 29 个），种子在 `tools/db/migrations/2026-10-28_add_chinese_knowledge_points.sql`（幂等）。标定命令 `python src/backfill_question_kps.py --subject chinese`（默认 math）。**题不标 KP 就进不了抽题池**（抽题 SQL 必须 JOIN `question_knowledge_points`）；**作文题不标 KP**（用户裁决：作文答案只是评分参考，标了会被专项练习抽到；新卷导入后需移除）。LLM 标注必须人工抽检（实测文言题会被误标现代文考点）。

**改动前必读三条**（细节见 `docs/data-refinery-管线总结与后续.md` §3）：① LLM 配置用 `.env` 的 `LLM_BASE_URL`/`LLM_AUTH_TOKEN`（refinery 专属），**不要用 `ANTHROPIC_*`**（会被 shell 里 Claude Code 覆盖）；② `db_loader` 的 full-reload 有**业务数据守卫**（库里有 answers/error_books 等外键数据时默认报错退出），需显式 `--purge-business-data`（按 FK 安全序清空）或改用 `--load-cards` 增量；③ 重抽目标页用 `unmark_extracted` 而非 `--force`（`--force` 绕过 skip 分支会断 lesson_id 的跨页继承回填）。

**入库范围与幂等（2026-10-28 用户裁决）**：**一次导入只允许改指定范围，且不得重写已完成的数据**。`db_loader_cli --load-cards` 必须配 `--subject` / `--file` / `--questions-only` / `--cards-only` 之一来限定范围（范围过滤与 full-reload 互斥，CLI 会拒绝）；卡片按唯一键 `(lesson_id, sort_order)` **原地 upsert**（`id` 不变、无变化跳过），**禁止删旧卡重插**（`practice_results.card_id` 是 CASCADE、`ai_dialogues.card_id` 会置 NULL）；题目按 `(paper_id, question_no)` 原址更新，`answer_verified=1` 不覆盖。

**统一范围参数**：`--subject/--stage/--term/--year/--file` 在 convert/extract/publish/db_loader/编排 CLI 同名同义，唯一实现在 `src/scope_filter.py`（不要在各 CLI 里各写一套归一）。日常单科/单卷导入用 `python src/import_cli.py --subject 语文 --year 2025`（convert→extract→publish→增量入库一条命令）。

**`--file` 是关键词，不是路径子串（2026-11-06）**：按空白（含全角）、`-`、`_`、`/`、`·`、`、` 分词，**所有词都要出现在相对路径里**（顺序无关、不分大小写），实现在 `scope_filter.split_keyword/normalize_path/match_keyword`，convert 的 `--materials`、extract/publish 的 `--book`、answer_extract/toc_parse、recognition_scan/manual_fix/apply_fixes 全部调它 —— **不要在任何地方另写 `in` 判断**。`import_cli` 入口先解析一次：0 命中打印「在 <目录> 下没有同时含「…」的素材 + 逐词命中数」并 rc=2（不空跑 9 步）；1 命中打印 `[解析]` 并继续；多命中列编号选一份，**非交互终端直接 rc=2**（不替用户猜）。`--materials` 的逗号仍是「条目间 OR」，单条内部才是 AND。

**交互选中后必须按精确路径继续（2026-11-24）**：`import_cli` 把用户选中的完整相对路径传给后续阶段时，不能继续塞回公开 `--file` 关键词过滤器。短卷 `西城-期末-试卷` 的全部词也是三帆卷 `西城·三帆中学-期末-试卷` 的子集，继续按关键词匹配会重新扩成两份，`--redo` 还会把两份都删产物重抽。唯一做法是 `scope_filter.match_exact_file()` / `--file-exact`（convert 用 `--materials-exact`）：相等匹配素材相对路径，并兼容 `卷/卷.md`、`卷/卷.jsonl` 的嵌套产物形态；extract/publish/meta/db_loader/答案回填/扫描/补题都沿用同一精确 source。**不要**通过再补关键词、改 `--file` 全局语义或只修 extract 来绕过——convert、发布、入库和人工补题仍会范围漂移。

其余 extract/publish/db_loader 细则（全角括号归一、页眉页脚剥离与书尾识别、二维码过滤、版次 edition 维度、页码锚定 lesson_anchor 等）属已稳定行为，见 `docs/ai-core-changelog.md`。
**语文试卷的着重号/下划线（2026-10-28）**：MinerU 的 Markdown **不表达下划线**，着重号也只是偶尔识别成 `<sub>．．</sub>` —— 语文卷「文段中加点词语 / 画横线句」的标记必须在入库后由 `src/emphasis_cli.py` 从 PDF 补回（`pdf_emphasis.py`：下划线=细填充矩形、着重号=字下 3pt 窄带小墨点，排除表格区域）。输出 `<u>…</u>` / **逐字** `<span class="cn-emphasis-dot">字</span>`；前端用 `::after` 画字下实心点（0.15em 纯黑，`text-emphasis` 无法调大小/颜色），下划线 2px 深色。**不要**把 `<sub>．．</sub>` 直接当最终展示（会变成字后小点）；也**不要**靠 LLM 猜哪些字被加粗/加点（不可复现）。该命令默认 dry-run、幂等、只改 `content/material_text/options/content_hash` 且写后校验其它列未变；目前只支持电子版（有文字层）PDF，纯扫描件需 OCR 字符框，暂不做。

**多选题（multi_choice，2026-11-01）**：卷面大题标题写「多项选择题」时，这一节的题一律 `multi_choice`——切题器 `RawQuestion.multi_choice` 带标记，`question_extract` 落库时覆盖 labeler 的 `choice`（模型只会给单选）。存量数据用 `python3 src/backfill_multi_choice.py`（默认 dry-run，`--apply` 才写；幂等，只改 `questions.type`）回填。**判断多选区间不能按扫到的题号**：OCR 会把「16.」认成「6.」，按题号会误伤前一大题的单选；脚本用「本大题之前最大题号+1 → 本节最大题号」的区间。判题侧 `multi_choice` 属于客观题（exact），答案按字母集合比对（`BD` == `DB`），**不做部分得分**。

**题型一律按大题判，不要按单题特征猜（2026-11-01）**：`section_analyzer.analyze_sections()` 先扫 md 的大题标题，把「第 A–B 题 = 什么题型」划好，切题后整段覆盖 labeler 的 type。**不要**再依赖「能拆出 4 个选项就是选择题」——物理实验题常用 A/B/C/D 标四幅图（人大附第 22 题），按特征会把整节实验题改成选择题。标题丢了时用标题里的「共 X 分 / 每小题 Y 分」算应有题数来定位换题型的位置（比选项特征可靠），缺口整段判一个题型；数学「解答题」混排 proof/calculation，不整节覆盖。存量用 `python3 src/backfill_section_types.py`（默认 dry-run）。

**清 `options` 前必须并入题干（2026-11-01）**：把题型从 choice 纠正成 short_answer/fill_blank 后，旧 options 往往就是题干的一部分（物理实验题的四幅图、选择题的四个待选答案）——**直接 `options=NULL` 会让题干残缺**。正确做法：把 options 里题干还没出现的文本按 `A. …` 追加到 content，再清空 options 并重算 content_hash；`extracted`/`published` 两份产物同步改，否则下次导入会灌回来。

**人工补题的图片归属以最终 options 为准（2026-11-27）**：`Snapshot.images` 只负责按编辑前 options 预过滤；生成补题记录时还必须按**本次 patch 后的最终 options** 再过滤。选项引用的图从题干删除，只把最终选项未引用、且新题干缺失的原图补回末尾。否则 76707 第 2 题这种“编辑前 `options=[]`、编辑中才把四张图补成 A–D”的场景，仍会被 `keep` 重新塞回题干。回归钉是真实 fixture `tests/fixtures/real_cases/76707/` 与 `test_review_records.py::test_real_76707_q2_keep_does_not_restore_images_added_as_options`。

**素材类型判定不许只看文件名（2026-11-03 用户裁决）**：手工丢进 `crawler/data` 的卷子（`2026北京北京中学初三（上）期中数学.pdf`）名字不带「试卷」二字，extract 判成教材卡 → 56 条 practice 碎片 → db_loader 走 `load_book_cards`、`parse_book_rel_path` 返回 None 抛「无法解析教材 rel_path」，题库 0 条。唯一实现是 `src/material_kind.py`，顺序固定 **名称 → 卷面首屏 → 目录结构 → 问用户**，**不要再**在 extract/publish/db_loader/paper_meta 里各写一遍 `"试卷" in name`（`--source zgkao/smartedu` 是素材来源分类，不属类型判定，保持按名字）。教材**不能靠内容判**：教材是逐页 md（`page_018.md`），单页既没卷首也没章节号；「同目录有 `page_*.md` 兄弟」才是强特征（实测 824/825 教材成立、95/95 试卷不成立）。交互选择落 `output/.material_kinds.json`，同一条命令的 9 个阶段只问一次；**判不出来不许默认当教材、也不许直接拒绝**（用户明确否决），非交互终端才报错并给出该往缓存里写什么。publish/db_loader 另加一层**形状判定**：JSONL 首行有 `card_type` 是教材卡、有 `group_order`/`options` 是试卷题，形状判不出才退回文件名——数据都切好了，形状不会骗人。

**第 4 步（试卷元数据）同样要内容兜底（2026-11-03）**：`parse_paper_meta` 的正则只认爬虫命名 `学科-年级(上)-YYYYMM-区县-考试类型-试卷`，不匹配原先直接 0 命中、题目入库但不建 `exam_papers`（学生端看不到整卷）。现在走 `parse_path_parts`（目录给 学科/学段/学期/年份）+ 卷面与文件名（年级/考试类型/学校）+ sidecar 回读；仍缺的**交互问用户**，非 TTY 跳过且不猜。sidecar 的 `merged` 必须带 `year/semester/exam_type`，`db_loader` 用 `meta_from_sidecar` 拼 PaperMeta；字段不全返回 None（宁可暂不归组，也不建一张字段缺失的假卷），别只写 title/district/grade。

**地点段不要求中点（2026-11-05）**：手工资料常直接写 `西城35中`，不能要求用户输入难打的中点。`paper_meta.split_location()` 无分隔符时按已知区县前缀切分，也接受 `·`/`-`/`_`/`/`/空格/`、`/`，`；学校后缀除 `中学|学校|附中|附小|小学|教育集团` 外，还认「数字/中文数字 + 中」（`35中`、`八十中`、`十二中`、`北京三十五中`），**数字必须在前**——`初中/高中/期中/其中` 不误判。`paper_head._SCHOOL_RE` 的明确后缀分支必须保持贪婪优先（否则 `昌平二中教育集团` 会被截成 `昌平二中`）；剥区县前缀只在剩余是「数字+中」简称时做，完整校名不拆残。新增区县只改 `paper_meta.DISTRICTS`，新增学校后缀只改 `paper_head._SCHOOL_RE`。

**补题输入支持剪贴板图片（2026-11-07 / 2026-11-26 改）**：槽内 `:f` 从文件/剪贴板/图片取（回车=读剪贴板、给路径=读文件、图片走 MinerU）；图槽的「回车」也是连续读剪贴板（内容相同的图按 hash 去重）。为什么必须由进程自己读剪贴板：终端只往 stdin 送字符，图片在 PTY 里没有通道，⌘V 一张图只会得到「什么都没输入」；Claude Code / CodeBuddy 能贴图也是它们在客户端读系统剪贴板，不是终端转发。实现是在 macOS 上用 `osascript` 读 `«class PNGf»` 落成临时 png（Linux 走 `wl-paste` / `xclip`），再复用既有的 `_from_image` 走 MinerU —— **别再另写一套 OCR 入口**。AppleScript 里**先判 `«class furl»` 再判 PNGf 的顺序不能改**：Finder 里 ⌘C 一个文件时剪贴板同时带文件 URL 和缩略图 TIFF，只读图像数据会把「文件图标」当题目截图送去识别。剪贴板没图时静默退回文本输入，不能用报错打断用户。裸 `@路径` 已取消：`@` 开头的真实内容现在是内容，取文件统一用 `:f`。

**数学题中考模型标签（2026-11-14）**：入口 `cd tools/data-refinery && python3 src/label_model_tags.py`；表 `question_model_tags`，一题可多行（大类 + 模型），不分主次。**只打标签，不改题目/知识点/掌握度**。模型枚举唯一真源是 `src/model_tags.py`，prompt 里的枚举由代码注入，不要手写第二份。LLM 配置从 DB `llm_models` 取（默认 `qwen3.8-max`，可 `--model-key local`）；打标关闭 thinking、不设 temperature。**题目重灌会 `DELETE FROM questions`，外键级联清空标签——任何卷子重灌后重跑同一条命令**。抽检只看 `output/model_tags/review_sample.csv` 的 30 条；人工修正写 `source='manual'`，不要改 CSV。`review.csv` / `review_sample.csv` 是**本轮运行快照**：`--limit` / `--question-id` 会整份覆盖，定向补跑后 CSV 只含那几题，要等一次全量重跑才和库对齐。失败题（LLM 调用/解析/校验失败或写库失败）在 CSV 里带 `failed` flag、不写标签，明细见同目录 `failures.jsonl`（全绿重跑会自动删掉该文件）。2026-11-14 实测：DB 里 qwen/kimi/deepseek 的 Key 均 401，改用本地 Qwen3.8-27B（`--model-key local`，支持图片）跑完 509 题。

## 材料修正的规则（2026-11-22 修订）

- **两种载位合法共存**：`material_url`（文章正文）与 `material_text`（题内素材）可以同时存在（Q11/Q15）。不要再用「URL 非空就拒绝一切 material_text」的护栏。
- **人工只改内容、系统自动路由**：不再让人选「题内素材/共享文章」存储通道。按目标写到正确位置——有 `material_url` 就改文档（重算 doc_key/url、只同步**同卷**引用题、`material_text` 置空）；只有 `material_text` 就改它；两者都有则先文章后素材（`material_target=both`，素材存 `material_inline_text`）。判「这段是不是文章」用 `same_article`（归一化 + 去首行标题 + 子串/相似度≥0.85，容忍个别错字）。
- **重复即脏**：`material_text` 与文档同段（`same_article`）视为脏数据，直接清空并按文章处理（Q5 类自愈）。publish 注入 `_post_material_text`/manual inline 前也做同一判重，命中写 `output/material_duplicate_healed.jsonl`。
- **卷内隔离 key（新导入/编辑生效）**：`doc_key = hash(paper_scope + 归一化正文 + 图片哈希)`，`paper_scope = rel_path/source`（与 `exam_papers.source_key` 同源）。同一段内容在不同试卷 = 不同文件；改文档只同步**同卷**题，旧文档不删。`PUBLISH_VERSION` **故意不 bump**（bump 会全量重发、等同一次全量迁移）。
- **勿动**：原 doc_key 判定不能用裸 `doc_key()`，要走 `write_material_doc(..., dry_run=True)`（先洗页码、去小节指令、算图片哈希）。key 不变才原地改 `content.md`；key 变了必须同步同卷题并清 publish checkpoint。
- **勿动**：publish 时不要把 article 目标的正文写进 `material_text`（文章靠 `material_doc_overrides.jsonl` 生效）；题内素材写 `_post_material_text` 通道。
