# 教研角色与内容纠错（试卷/题目）— 设计 spec

**日期**：2026-11-19
**状态**：待实施
**关联**：`docs/superpowers/specs/2026-11-09-admin-paper-delete-design.md`（本 spec 迁移并扩展其试卷管理能力）；API 文档 §4.17；`tools/db/schema.sql` 的 `admins` / `auth_sessions` / `questions` / `exam_papers` / `paper_questions` / `uploaded_files`

---

## 1. 背景

上一版「管理员端试卷管理」（2026-11-09）只能按元数据筛选并删除整卷，看不到卷内题目内容，也不能改答案。但：

1. `questions.answer` 是判题的**唯一权威字段**，客观题 exact、主观题 LLM 比对、自评题参考答案展示全部直接读它。一处存错 = 该题为所有学生的判题全错。
2. 答案错误是真实、多次发生的，且根因在 PDF→Markdown 答案表对齐（跨页页脚、版式错位、全角题号、扫描件缺图），不是 LLM 生成。如北师大实验 2024 物理卷第 1 题真值 C、库里 D；某物理卷 34 题整卷无答案；语文 27 题答案严重错位。`answer_verified=1` 只是「已导入」标记，不代表正确。
3. 目前唯一能改答案的是本地命令行 `answer_importer_cli.py`（需服务器权限 + DB 凭据），运营在页面上无路可走。
4. 管理端是平台运维/商业化/数据角色，PRD §7.14 反复声明管理员不进学习域。内容纠错是独立的教研职责，不应塞进 admin。

用户 2026-11-19 裁决：新增独立的**教研角色**，专门负责内容；可以删卷、更正答案/题干等；**改答案后不回填历史数据**。

## 2. 目标

1. 新增 `researcher` 角色，与 admin 平级互斥，登录后可进入独立教研空间 `/research`。
2. 将现有「试卷管理」（列表 / 删除预览 / 删除）**从 admin 迁移到教研**，admin 不再有试卷入口与接口。
3. 教研可查看试卷内题目明细（题干 / 选项 / 答案 / 解析 / 思路 / 来源），并可更正五个字段。
4. 更正时支持在答案 / 解析 / 思路里上传多张图片，并设计完整的上传、存放、引用、清理生命周期。
5. 所有内容改动写审计日志；改答案**不回填**历史判题数据，并在界面明示。

## 3. 非目标（本期不做）

- 不改题型、难度、满分、`material_*`、题面图片本身（图片替换不在本期）。
- 不改学生端 `/api/exams`、`/api/practice` 等任何接口。
- 不回填历史作答 / 错题本 / 积分 / 掌握度 / 旧解析缓存（用户明确裁决）。
- 不改数据管线的答案提取逻辑，不回填历史 PDF 答案原文。
- 不做回收站、软删除、答案版本回滚。
- 不新增账号表、不新增图片表（复用现有，见 §5、§8）。

## 4. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 角色标识 `researcher`，复用 `admins` 表加 `role` 列，不新建 `researchers` 表 | 登录链路、seed、改密页都基于 `admins`；只多一种 staff 身份，改动最小 |
| 2 | 试卷管理从 admin **迁移**到 research（不是复制） | 教研「专门负责内容」；避免两个角色都能改内容导致审计边界模糊 |
| 3 | 可编辑字段限定五个：`answer` / `content` / `options` / `explanation` / `approach` | 这是纠错最小闭环；题型/难度/分值/材料/图片风险更高，本期不碰 |
| 4 | 强制勾选「已对照原卷」才能保存；不存 PDF 原文，靠线下自备原卷对照 | 结果结构没保留 PDF 页码/原文；入库存原文要改管线 + 回填，工作量大（用户裁决轻量方案） |
| 5 | `content_hash` **不重算** | 现有 CLI 只改 answer 不动 hash；现有哈希本就剥掉 Markdown 图片（`content-hash.util.ts:18-33`）；重算会撞 UNIQUE 且 TS/Python 口径不一致 |
| 6 | 图片复用 `uploaded_files`，新增 `source='research'`，**零新增表** | 辅助答疑上传本就写这张表；清理需要 URL→fileId→磁盘路径、created_at、source 边界（用户 2026-11-19 追问确认） |
| 7 | 清理分三层：保存差集、取消清理、GC 兜底 | 现网明确接受孤儿文件（`2026-11-01-answer-paste-image-design.md:82,93,156`）；教研反复改图必须补生命周期 |
| 8 | 改动与清理全部写 `content_audit_logs` | 当前 admin 是扁平角色、账号操作无专门审计表；答案改动必须留痕 |

## 6. 路由与页面

```
/research/papers                     试卷列表（迁移）：筛选 + 删卷
/research/papers/:id                 试卷详情：元信息 + 题目列表（含五字段当前值）
/research/papers/:id/questions/:qid  题目编辑抽屉（页内，不单独开页）
/research/audit                      审计日志
```

- 新 `ResearchLayout` + `ResearchNav`（轻量，只放上面四项），包在 `<RequireRole role="researcher">` 里。
- 编辑抽屉用页内 overlay，URL 参数 `:qid` 可直接深链定位；关闭回到试卷详情。

### 6.1 编辑抽屉状态机

| 状态 | 进入条件 | 可操作 | 离开条件 |
|---|---|---|---|
| `closed` | 初始 / 关闭 | 点题目「编辑」 | → `loading` |
| `loading` | 打开 | — | 加载成功 → `editing`；失败 → `error` |
| `editing` | 数据就绪 | 改五字段、传图、勾「已对照原卷」 | 点保存 → `validating`；点取消 → `closing` |
| `uploading` | 任一字段有图在传 | 等待 | 全部完成 → `editing`；失败 → `editing` 并标红失败图 |
| `validating` | 点保存 | — | 通过 → `saving`；不通过 → `editing` 并提示 |
| `saving` | 校验通过 | — | 成功 → `saved`；失败 → `error` |
| `saved` | PATCH 返回 | 关闭 / 继续编辑 | → `closed` |
| `error` | 保存/加载失败 | 重试 / 关闭 | → `editing` 或 `closed` |
| `closing` | 点取消且 dirty 或有未保存图 | 确认丢弃 / 继续编辑 | 确认 → 调 `DELETE /api/research/images` → `closed` |

**保存按钮禁用条件**（任一即禁）：无字段变更、`confirmedSource` 未勾选、有上传在 flight、`saving` 中。

**静态提示**（常驻抽屉顶部，不可关闭）：「本次修正仅影响之后的判题，不会修改已有作答记录、错题本、积分与掌握度。」

## 7. 后端接口（端点级）

统一前缀 `/api/research`，统一 `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles('researcher')`。未登录 401/1003，越权 403/1005。

### 7.1 `GET /api/research/papers`（迁移）

- Query（zod，空串视为未填）：`subjectId? / year? / gradeBand?(primary|junior|senior) / keyword?(≤50) / page=1 / pageSize=20(1-100)`。
- 逻辑：同 `admin-papers.repo.ts:120-157`，`subjectId` 传了才加 `WHERE p.subject_id = ?`；计数 `pool.execute`，分页 `pool.query`（`LIMIT ?` 预编译坑）；`ORDER BY p.id DESC`。
- 返回：`{ items: [{id,subjectId,subjectName,title,grade,gradeBand,semester,year,district,examType,sourceKey,questionCount,sessionCount,createdAt}], total, page, pageSize }`。
- 错误：1001（入参）、1003、1005。

### 7.2 `GET /api/research/papers/:id`（新增）

- 路径参数 `id` 正整数 → 1001。
- 逻辑：查 `exam_papers JOIN subjects`，不存在 → 404；查 `paper_questions JOIN questions ORDER BY question_no`，取五字段原值 + `type / difficulty / full_score / source / source_year / textbook_page / answer_verified / is_active`。
- **与学生端相反，answer/explanation/approach 不剥离**——教研必须看到当前值。
- 返回：`{ paper: {...}, questions: [{id, questionNo, type, content, options, answer, explanation, approach, source, sourceYear, textbookPage, answerVerified, isActive}] }`。
- 选项走 `parse-options.util.ts` 的解析（但保留可编辑结构，剥离 `isCorrect`）。
- 错误：1001、1003、1005、404。

### 7.3 `GET /api/research/papers/:id/delete-preview`（迁移）

逻辑/返回同现有 `admin-papers.service.ts:94-107` 与 `admin-papers.repo.ts` 的 `countImpact`。错误同上。

### 7.4 `DELETE /api/research/papers/:id`（迁移 + 图片清理）

- 删除事务沿用 `admin-papers.repo.ts:218-268` 的全部规则（只删独占题；被学生数据引用的题保留只解绑；该卷会话连同作答一并删）。
- **新增**：事务内收集「真正被物理删除的题目」五字段里的 `/uploads/research/` URL；commit 后按 §8.3 的引用检查清理图片（共享题保留，不动其图）。
- 返回：`{ paperId, deletedQuestions, retainedQuestions, deletedSessions, deletedAnswers, deletedImages }`。
- 错误：1001、1003、1005、404；FK 冲突按现有逻辑转 409。

### 7.5 `PATCH /api/research/questions/:id`（新增，核心）

**Body**（zod）：

| 字段 | 类型 | 规则 |
|---|---|---|
| `answer` | string | 可选；非空字符串，最长 20000 |
| `content` | string | 可选；非空，最长 20000 |
| `options` | array | 可选；`[{label:string, text:string}]`，长度 ≤ 10；透传前剥 `isCorrect` |
| `explanation` | string | 可选；允许空串（= 清空），最长 20000 |
| `approach` | string | 可选；允许空串，最长 20000；**禁止相对路径图**（见 §8.2） |
| `confirmedSource` | boolean | **必须为 true**，否则 1001 |
| `note` | string | 可选，≤255，写入审计 |

**逐步逻辑**：

1. 校验 body；字段全缺省或无实际变更 → 400/1001。
2. 事务开始：按 id 查 `questions`（不存在 → 404）。
3. 记录 `before`：五个字段的旧值（仅记录本次涉及的）。
4. `UPDATE questions SET <changed fields>, answer_verified=1 WHERE id=?`；**不更新 content_hash、updated_at 由列级 ON UPDATE 自动维护**。`answer_verified=1` 在本次改了 `answer` 时置位；若只改解析/思路/题干/选项，保持原值不变（避免把管线导入时未核验的题误标为已核验）。
5. 计算图片差集：旧五字段 URL 集合 − 新五字段 URL 集合 → 待清理 research 图列表（§8.3）。
6. 写 `content_audit_logs`：`action='question.update'`, `target_type='question'`, `target_id=id`, `paper_id`（由 `:id` 反查任一 `paper_questions`，无则 null）, `before_json/after_json`（只含变更字段）, `note`。
7. 提交事务。commit 后执行磁盘文件删除（§8.3 第 4 步）。
8. 返回：`{ question: {id, <changed fields 新值>, answerVerified:1}, changedFields: string[], deletedImages: number }`。

**边界**：并发两人同时改同一题 → 后写覆盖先写（本期不做乐观锁，审计可追溯）；图片差集只对 `source='research'` 的 URL 生效。

### 7.6 `GET /api/research/audit`（新增）

- Query：`actorId? / action? / targetType? / targetId? / from?(ISO) / to?(ISO) / page=1 / pageSize=20(1-100)`。
- 逻辑：`content_audit_logs` 按 `created_at DESC` 分页；时间区间用 `BETWEEN`；非法时间 → 1001。
- 返回：`{ items: [{id, actorId, actorRole, actorName, action, targetType, targetId, paperId, beforeJson, afterJson, note, createdAt}], total, page, pageSize }`。
- 错误：1001、1003、1005。

### 7.7 `POST /api/research/images`（新增，上传）

- `multipart/form-data`，字段名 `file`；服务端 `FileInterceptor`，`fileSize ≤ 20MB`，**MIME 白名单 `image/*`**（非图 → 400/1001）。
- 逻辑：`FilesService.store(file, uploaderId, 'research', 'researcher')`（从现有 `upload()` 抽出共用 `store()`，不改动学生端点行为）。
- 落盘 `UPLOAD_DIR/research/<uuid><ext>`，`url='/uploads/research/<uuid><ext>'`。
- DB：`uploaded_files` 新增行，`uploader_type='researcher'`、`uploader_id`=当前教研 id、`source='research'`。**不触发 PDF 提取任务**（`source='research'` 不在自动建任务的条件里）。
- 返回：`{ fileId, url }`。错误：1001、1003、1005。

### 7.8 `DELETE /api/research/images`（新增，取消时清理）

- Body：`{ urls: string[] }`，每条须以 `/uploads/research/` 开头（否则 1001）。
- 逻辑：逐条走 §8.3 的引用检查与删除；只清 `source='research'` 且无其它引用的图。
- 返回：`{ deleted: number, skipped: number, reasons?: Record<url,string> }`。错误：1001、1003、1005。

### 7.9 `POST /api/research/images/gc`（新增，兜底）

- Body（可选）：`{ olderThanHours?: number }`，缺省 24，范围 1–720，非法 → 1001。
- 逻辑：扫 `uploaded_files WHERE source='research' AND created_at < NOW() - INTERVAL ? HOUR`，逐条做 §8.3 引用检查；无引用则删 DB 行 + 磁盘文件；有 `extract_tasks` 关联的跳过。
- 返回：`{ scanned, deleted, skipped, failed }`。错误：1001、1003、1005。
- 调用方式：运维手动触发或纳入现有定时维护；本期不做后台常驻进程。

## 8. 图片生命周期

### 8.1 两套图片体系（不可混淆）

| | 题库静态图 | 用户上传图 |
|---|---|---|
| 来源 | data-refinery 从 PDF 物化 | 浏览器 multipart 上传 |
| 形态 | 相对路径 `questions/...`、`textbooks/...` | 绝对 URL `/uploads/<source>/<uuid><ext>` |
| 磁盘 | `tools/data-refinery/output/assets/`（`main.ts:51-59` 挂 `/assets/*`） | `UPLOAD_DIR`（`main.ts:61-69` 挂 `/uploads/*`） |
| 前端解析 | `resolveAsset` 补 `/assets/` 前缀 | `resolveAsset` 特判透传（`markdown.tsx:60-63`） |

教研上传的图**只能**是 `/uploads/research/...` 绝对路径，绝不能写相对路径。

### 8.2 编辑器约束

- 复用 `LatexEditor.tsx` 的「纯文本占位 `［图N 上传中…］` → 顺序上传 → 精确替换 `![图N](/uploads/research/…)`」模式；前端压缩沿用 `image-compress.ts`（最长边 1600、≤5MB）。
- **五字段各自独立**的 token 与 `onReplaceToken` 路由，防止上传结果写错字段；切字段/切题时 in-flight 上传按「发起时归属」失效（照搬 `QuestionRunner.tsx:228-250,694-708`）。
- `approach`（思路）是管线物化盲区：`publish_cli.py:33` 四字段白名单与 `db_loader.py:103` 入库护栏都**不含 approach**，相对路径图必 404。因此 PATCH 对 `approach` 校验：出现的 `![...](...)` 若不是 `/uploads/`、`http(s)://`、`data:` 开头 → 400/1001。其余四字段允许历史相对路径，但新图一律走上传。

### 8.3 uploaded_files 复用说明（用户 2026-11-19 追问确认）

**不新增图片表。** `uploaded_files` 已存在于 `tools/db/schema.sql:1111-1122`，结构为 `id / uploader_id / uploader_type / url / mime_type / size_bytes / source / created_at`。

- **辅助答疑上传是有记录的**：每次 `POST /api/files/upload` 都调 `filesRepo.create(...)`（`files.service.ts:32-39`）写一行；答疑输入栏默认 `source='auxiliary'`。所以这张表一直在使用。
- **教研复用同一张表**，仅换 `source='research'`、`uploader_type='researcher'`、`uploader_id`=教研 id；文件物理上分到 `UPLOAD_DIR/research/` 子目录，URL 为 `/uploads/research/...`，与学生 `auxiliary/freeform` 不混。
- **为什么必须保留 DB 记录**（不能只扫磁盘）：
  1. URL → fileId → 磁盘路径的映射，删文件时要用；
  2. `created_at` 供 GC 判断 24h 孤儿；
  3. `source` 是「只清 research 图、绝不动学生图」这条铁律的边界依据；
  4. `uploader_id` 供归属校验（沿用 `findByUrlAndOwner` 模式）。
- **需要补的代码**：`UploadedFilesRepository` 加 `findByUrl(url)` 与 `delete(id)`（现只有 create / findById / findByIdAndOwner / findByUrlAndOwner，无删除）；`FilesService` 抽出 `store()`；`files.service.ts:34` 写死的 `uploader_type='student'` 在 research 分支按真实角色写。
- **字段容量核对**：`uploader_type VARCHAR(10)` 恰好容纳 `'researcher'`（10 字符），`source VARCHAR(20)` 容纳 `'research'`，无需改列宽。

### 8.4 清理三层

1. **保存时差集**：PATCH 事务内对比旧/新五字段的 research URL，`OLD − NEW` 为待清理候选。
2. **取消时清理**：抽屉 `closing` 状态把本次会话上传但未写入新文本的 URL 列表交 `DELETE /api/research/images`。
3. **GC 兜底**：`POST /api/research/images/gc` 扫 >24h 的无引用 research 图，覆盖崩溃/失败保存。

### 8.5 删除铁律（§7.4/7.5/7.8/7.9 共用）

1. 只清 `source='research'` 且 URL 以 `/uploads/research/` 开头的图；**绝不动** auxiliary/freeform/题库静态图。
2. 删前**全局扫描 `questions` 五列**（`content/options/answer/explanation/approach`）确认无其它引用；UUID 唯一，`LIKE '%url%'` 足够。同时扫描 `exam_answers.answer_text` / `answers.answer_text` / `special_answer_records.answer_text`（学生作答里可能引用了教研图，保守跳过）。

## 13. 风险与未决

1. **并发覆盖**：两人同改一题后写覆盖先写，本期靠审计追溯，不做乐观锁。
2. **`/uploads` 公开**：图片 URL 无签名，拿到即可访问；内部工具可接受，若将来要私有化需另立 spec。
3. **删卷图片清理的事务边界**：磁盘删除在 commit 后，若删文件失败会留孤儿磁盘文件（DB 已清），GC 不会再扫到（DB 行没了）——这是一处已知残留，需靠 GC 的磁盘扫描分支或人工巡检补；本期优先保证 DB 一致性。
4. **content_hash 不重算的代价**：教研改题干文字后，该题 content_hash 与文本不再匹配；下次管线重灌若按 hash 去重可能视为不同题。因 `answer_verified=1` 保护 + 管线重灌本就需人工核对，本期接受。
