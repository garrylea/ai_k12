# 九年级语文课本 → 默写题库数据管线

- 日期：2026-09-13
- 状态：设计已与用户逐节确认
- 关联文档：`docs/superpowers/specs/2026-09-13-chinese-dictation-special-design.md`（默写专项功能设计，本管线是它 §6「内容管线」的落地）、`docs/data-refinery-管线总结与后续.md`、`docs/data-refinery-使用手册.md`、`docs/superpowers/specs/2026-09-02-math-training-module-design.md`

## 1. 背景与问题

默写专项的前后端链路已实现并合并（三端点、纯程序判题、错因能力、前端三页），但**题库里只有两篇开发假数据**（`source_ref='DEV-FIXTURE'` 的《静夜思》《登鹳雀楼》），真实内容覆盖为零——学生实际练不到东西。

本文设计把**统编版九年级上/下册教材里的全部古诗文与文言文**抽成结构化篇目入库的离线管线。

## 2. 目标与非目标

**目标**

1. 用现有爬虫抓取统编版九年级上/下册语文教材（逐页 JPEG）；
2. 用现有 `convert_cli` 转成每页一个 Markdown（**不改动该工具**）；
3. 从教材目录解析出全部课文候选；
4. 判定其中哪些是古诗文/文言文，定位每篇的正文起止，原样切片入库（篇名/作者/朝代/正文 + 册次/页码）；
5. 通过自动自检 + 人工过目清单守住「正文逐字准确」。

**非目标**

- **不抽注释**（为后续「古诗文解释」专项留待那时再抽；页面图片留在本地，重跑只花转换时间，不需重爬）；
- **本次不判必背**：全量入库时一律置「非必背」，由用户后续标定；
- 不做后台管理界面（必背的日常维护后续再议）；
- 不改动 `convert_cli` / `extract_cli` / `publish_cli` / `db_loader_cli` 的既有行为，避免波及数学管线。

## 4. 管线总览

| 步 | 做什么 | 复用 / 新建 |
|---|---|---|
| 1 爬取 | 抓九上/九下逐页 JPEG → `tools/crawler/data/语文/初中/统编版/九年级/上册/<书名>/page_NNN.jpg` | 复用 `crawler_cli --site smartedu` |
| 2 转换 | 图 → MD。**MinerU 每个输入文件产出一个 MD**，教材是逐页图片，故产物是 `page_001.md`、`page_002.md`…（页码在文件名） | 复用 `convert_cli --source smartedu`（**不动代码**） |
| 3 目录候选 | 目录页 → 单元/课文结构 JSON | 复用 `toc_parse_cli` + `toc_merge` |
| 4 定位与分类 | 判定候选里哪些是古诗文/文言文，给出正文起止锚点与作者/朝代 | **新建**（LLM 只做判断） |
| 5 切片 | 按锚点从 MD **原样**切正文，剥运行页眉 | **新建**（复用 `page_chrome`） |
| 6 入库 | 写 `questions` + `dictation_passages` | **新建 importer**（复用仓储） |

**产物**：`tools/data-refinery/output/dictation/语文/初中/统编版/九年级/<册>/` 下的 JSONL（篇目清单）+ 人工过目清单 Markdown + 待人工处理报告。

**第 3 步是中途闸门**：目录候选清单先给用户过目确认「哪些篇目在范围内」，再进入第 4 步。

> **九上已确认的范围（2026-09-13 用户确认）**：共 **24 篇** —— 第三单元 10 篇（岳阳楼记、醉翁亭记、湖心亭看雪、诗词三首、课外古诗词诵读 4 首）、第六单元 13 篇（曹刿论战、邹忌讽齐王纳谏、陈涉世家、出师表、诗词曲五首、课外古诗词诵读 4 首）、外加破例收录的《沁园春·雪》1 篇。落盘于 `output/dictation/语文/上册/candidates.json`（`output/` 在 gitignore 内，故范围同时记在本文件）。
> **容器标题不收**：「14 诗词三首」「27 诗词曲五首」「课外古诗词诵读」本身不是篇目，只收其下的单篇；TOC 合并已把父栏目页码继承给子条目，故单篇都有页锚点。

## 4.1 实测的教材 MD 形态（2026-09-13 九上实跑，170 页）

爬取 + 转换已实跑一遍，实测结果（用于校正设计假设，**以实测为准**）：

| 事实 | 实测值 | 对设计的影响 |
|---|---|---|
| 页数 / 命名 | 170 页，`page_001.md`…`page_170.md`，与图片 1:1 | 页码在文件名，与假设一致 ✓ |
| 印刷页 → MD 页偏移 | **统一 +7**（7 个样本） | 偏移众数法可用 ✓ |
| 真正的运行页眉 | `人民教育出版社`（27 页首行，含正文页）、水印句 `仅供个人学习使用，未经授权不得另做他用`（5 页） | 二者都命中 `page_chrome` 的模式 + 频次双闸，**既有 `strip_chrome` 能剥掉** ✓ |
| 会被误当页眉的**真栏目名** | `思考·探究·积累`(7 页)、`阅读综合实践`(5)、`专题学习活动`(3)、`提示：`(3)、`资料夹`(3)、`读读写写`(7) | **幸好 `strip_chrome` 是「模式 + 频次」双闸**，这些不匹配模式故不会被误删。若只按频次剥就会删掉真内容——此设计不可放宽 |
| 页码页脚 | **全书仅 2 行含竖线**：`60 \| 阅读 \| 第三单元`（page_067）、封底 `九年级 \| 上册`（page_170）；**0 页有纯数字页脚行** | **不存在系统性页脚** → 不需要写「剥页脚」逻辑；改为在自检里兜底检测正文残留竖线 |
| 正文行内注释角标 | **79/170 页**含 `$^{①}$` 形式（如 `崇祯五年 $^{②}$ 十二月`） | 正文切片后**必须删掉角标**，否则入库正文夹带 `$^{②}$` 垃圾 |
| OCR 空格 | 无随机空格；所有「汉字-空格-汉字」都源自被删的角标 | 收空白必须在**删角标之后**做 |
| 注释排布 | 在正文**之后**、页底另起块，且**跨页**；形态 `⑥〔…〕` 与 `① 选自…` | 末句锚点法可用 ✓（首末句都取正文内部的句子） |
| 正文前的非正文段落 | **9 页**含「阅读提示」段落（如 page_063） | 定位 prompt 必须显式排除「阅读提示」，正文从作品第一个字开始 |
| 目录页 | 第 **004–007** 页（page_004 以 `## 目录` 开头） | 见 §4.2 |

## 4.2 学科化的版面规则（基类 + 每学科实现）

**问题**：MinerU 转出的 MD 里，**页眉/页脚残留与目录行的形态因学科而异**，而现有两处规则都硬编码成数学形态：

| 位置 | 现有规则 | 数学形态 | 语文学形态 |
|---|---|---|---|
| `toc_parse_cli._TOC_LINE_RE` | `第N章 X 页码` / `N.M X 页码` / `(小结\|复习题\|数学活动\|阅读与思考) … 页码` | `3 第二十一章 一元二次方程` | `1 沁园春·雪/毛泽东 3`、`阅读 7 …/习近平 22`、`9\*谈骨气/吴晗 33`、`第一单元 活动·探究 1`、`课外古诗词诵读 159` |
| `card_splitter._PAGE_NUMBER_HEADER_RE` | `^\d+\s+第[一二三四五六七八九十百零]+章\s+\S+.*$` | `3 第二十一章 一元二次方程` | `60 \| 阅读 \| 第三单元` |

实测后果：`toc_parse_cli` 对语文**完全失效**——它的目录页识别只认出 page_004，丢掉第三单元（正是古诗文单元）与「课外古诗词诵读」（`toc_lines = 0` → 不满足「≥30% 行匹配」→ 续页扫描在 page_005 就 break）。

**设计**：新增 `tools/data-refinery/src/textbook_profile.py`，把「学科相关的版面识别」收敛为**基类 + 每学科实现 + 注册表**：

```python
class TextbookProfile:                     # 基类：保守的通用规则，不猜学科专属形态
    def is_toc_line(self, line: str) -> bool: ...
    def is_page_furniture(self, line: str) -> bool: ...

class MathTextbookProfile(TextbookProfile):    # 逐字保留现有两条正则，行为零变化
class ChineseTextbookProfile(TextbookProfile):  # 语文形态（由实测目录页推导）

def get_profile(subject: str | None) -> TextbookProfile:   # 未注册学科回退基类
```

- `toc_parse_cli` 与 `card_splitter` 改为**按 `subject` 取 profile**，不再各自持有硬编码正则；
- **数学行为必须零变化**：`MathTextbookProfile` 的两条正则与原实现逐字一致，并配「黄金用例」回归（见 §9）；
- 语文的 TOC 行规则（实测推导）：**行末为 1–3 位数字**（`… 3` / `… 159`）**或含 `/`、`／`**（`篇名/作者` 形式，用于 `课外古诗词诵读` 下无页码的诗题行）。两条件叠加 `_is_toc_like_page` 原有的「无长正文段落 + ≥30% 行匹配」双闸，可正确接受 page_004–007 并在 page_008 停下；
- 语文的版面残留规则：`^\s*\d+\s*[|｜]` 形态（页码 + 栏目 + 单元）；实测全书仅 2 行，属兜底。

> 该重构**不属于**本设计的「非目标」清单里冻结的四个工具（`convert_cli`/`extract_cli`/`publish_cli`/`db_loader_cli`），但 `toc_parse_cli` 与 `card_splitter` 被数学卡管线共用，故**改动必须带数学回归测试**，避免影响既有数学结果。

## 5. 第 4/5 步设计（本文的技术核心）

### 5.1 候选来源

`toc_parse_cli` 输出的 JSON 结构为：

```json
{ "book": "...", "chapters": [ { "number": 3, "title": "...", "label": "第三单元 ...",
  "sections": [ { "number": [3,1], "title": "...", "label": "10 岳阳楼记", "printed_page": 46 } ],
  "supplements": [ { "type": "supplement", "label": "课外古诗词诵读", "printed_page": 60 } ] } ] }
```

候选 = 全部 `sections` + `supplements`。**单元标题（`chapters[].label`）是强信号**——部编版教材把古诗文集中在专门单元（如「第三单元 古诗文」），据此可先粗分。

**印刷页 → MD 页序的偏移**必须显式推导并校验，不能假设二者相等：取 TOC 中若干已知 `sections[].printed_page` 与其 `label` 在 MD 里实际出现的页序做比对，取偏移众数（与既有 `lesson_anchor` 的「偏移众数 + 余量」思路一致）。**若偏移不可靠**（众数不集中 / 样本不足），退化为**整书滑窗扫描**：按固定页窗（如 8 页）让 LLM 找篇目，TOC 此时仅用于完整性核对（目录里列了但滑窗没找到的，进待人工处理报告）。

### 5.2 LLM 的职责边界（只做判断，不产出正文）

**每单元一次调用**（不是每篇一次）：输入该单元涉及的若干页 MD 文本，输出每个候选的：

- `is_classical`：是不是古诗文/文言文（排除现代诗与现代文）。
  > **例外（2026-09-13 用户裁决）**：毛泽东《沁园春·雪》形式上是有词牌的词、且中考会考，**破例收录**。这是对本设计「现代词牌作品不收」的一次显式例外，只此一例；范围由人工确认的候选清单（`candidates.json`）界定，不由模型自行放宽。
- `work_title`：篇名
- `author` / `dynasty`：作者与朝代（教材注释里有则在，缺失留空）
- `genre`：体裁（诗/词/曲/文），供自检按体裁设长度下限
- `body_start_anchor`：**正文首句**（含，用作切片起点）
- `body_end_anchor`：**正文末句**（含，用作切片终点）

> **锚点是「逐字连续子串」，角标要原样包含在内**（2026-09-13 写实施计划时实测修正）：正文里的 `$^{②}$` 角标常夹在句中（实测真实文本是 `庆历四年 $^{②}$ 春，滕子京谪守巴陵郡 $^{③}$ 。`），所以**要求锚点不含角标会自相矛盾**——唯一合法的首句锚点会短到搜不准，且可能与「从正文第一个字开始」冲突。正确做法是**照抄含角标的完整句子**（保证在页文本里搜得到、且不截断开头），**角标由第 5 步的规范化删除**，不会进正文。
- `reason`：判断依据，写进人工过目清单便于复核

**LLM 不输出正文内容本身**。正文由第 5 步按锚点从 MD 中切出。

> **正文起点不是「该篇页面的开头」**：实测 **9 页**在正文前有「阅读提示」段落（如 page_063：`## 阅读提示` + 一段编者导语 + 然后才是 `崇祯五年 ② 十二月，余住西湖…`）。prompt 必须显式声明「阅读提示」是编者导语、**不属于正文**，`body_start_anchor` 要取作品的第一个字。

> **为什么用「首句 + 末句」而不是「正文起 + 注释起」**（2026-09-13 写实施计划时修正）：注释起始标记并非每篇都有；若该篇无注释，终点只能退化为「单元文本末尾」，**会把下一篇课文一起吞进正文**。而末句锚点必在正文之内，取到它为止天然排除了其后可能出现的注释。两个锚点都取「找不到即判未定位、进待人工处理」，不做兜底猜测。

### 5.3 切片

1. 用 `compute_book_chrome(md_dir)` 算出书级运行页眉集合，再对每页 `strip_chrome(text, chrome)`（均为现成函数，教材页眉正是它的设计目标）；
2. 按 `body_start_anchor` / `body_end_anchor` 在页文本中定位，**含两端锚点本身**取中间的原始字符作为正文；**任一锚点找不到 → 判为未定位，进待人工处理报告，不做兜底猜测**；
3. 跨页的篇目按页序拼接（先把该单元的页按文件名页序拼成一整段文本，再在其中定位锚点）；
4. **规范化**：先删行内注释角标 `$^{…}$`（实测 79/170 页含此类角标，是正文里指向注释的标记，不是正文），**再**去掉 OCR 插入的换行与空白；**保留全部标点与全角符号**（判题时的标点/空格忽略发生在 `normalizeChineseAnswer`，与存储无关——存储保留原文便于展示）。
   > **关于「先删角标再收空白」的次序（2026-09-13 写实施计划时实测校正）**：就当前角标正则（`\$\^\{[^}]*\}\$`，不含空白）而言，两条操作**其实可交换**——实测 170 页没有一页结果不同。保留该次序的理由是**防御性**：一旦角标正则将来允许内部空白，先收空白就会把角标与正文粘连、无法再清。**不要把这条读成「当前必须如此」**，也不要据此认为次序无关紧要而调换。
5. 记录 `source_ref`（书名 + 起止印刷页），供溯源。

## 6. 校验与闸门

「正文错一个字，写对的学生反而被判错」是本管线最贵的失败模式，故设两道闸门。

### 6.1 自动自检（每条必过）

- 正文非空；
- **体裁字数自检**：绝句/律诗按 5 言/7 言 × 句数可判，明显不符即标记（词与文言文只做长度下限）；
- 不含注释体例标记（「注释」「其：」「〔」「〕」等）；
- **不含版面／标记残留**：`$`（LaTeX 角标未删净）、`|` 或 `｜`（页码页脚残留，实测全书仅 2 行但要有兜底）——这两条是**实测新增**，原清单的「注释/其：/〔〕」抓不到它们；
- 不含页眉残留（书名、出版社、「练习」等）；
- 与篇名一致性：**只查正文开头**——篇名出现在前 `len(篇名)+6` 字内才判「把标题切进了正文」。
  > **为什么不能用 substring（2026-09-13 实测校正）**：《湖心亭看雪》的正文里**本来就含篇名**（末段「独往湖心亭看雪」），substring 判断会把一篇完全正确的正文误判为错，让它永远进不了题库——即静默丢掉一篇已确认篇目。故只查开头。

### 6.2 低频字标记（无法自动消除的风险）

正文含**可疑生僻字** → 标为 `needs_review`，进重点人工复核清单。原因：教材页是扫描图，MinerU OCR 对生僻字可能认错；而文言文里生僻字恰恰不少。**本方案无法自动消除这一风险，如实记录并请人工定向复核。**

> **实际实现的代理信号与已知局限**（2026-09-13 写实施计划时确定）：判据取「正文含 **CJK 基本区（U+4E00–U+9FFF）之外**的汉字」——那是最经典的 OCR 出错面（扩展 A/B 区字符）。**基本区内的生僻字（如「谪」「滕」「属」）不会被这条挑出来**，故这只是优先级提示而非完备检测；要完备覆盖需引入一份常用字表，本次未做（已记入计划的「后续」）。
>
> `needs_review` 是**管线产物**（JSONL 与人工过目清单）里的字段，**不落库**——它不是内容正确性的门禁，只是复核优先级提示。`verified` 仍由 §6.3 的自检结果决定。

### 6.3 结果分流

- 自检通过 → `verified = 1`（且 `memorize_required = 0`，故暂不进抽题池）
- 自检未通过 → 进「待人工处理」报告，`verified = 0`，管线**不阻断**（其余篇目照常入库）

### 6.4 人工过目清单

生成 Markdown 清单：篇名 / 作者 / 朝代 / 正文字数 / 正文首尾各 20 字 / 是否含低频字。用户只需抽看长文言文与低频字标记项。

## 7. 数据模型变更

```sql
ALTER TABLE dictation_passages
  ADD COLUMN memorize_required TINYINT(1) NOT NULL DEFAULT 0
  AFTER verified;
```

- 建表语句需**折回** `tools/db/schema.sql`（`install_mysql.sh` 只执行 `schema.sql`，迁移文件不会自动跑——仓库既有约定）；
- 同时提供 `tools/db/migrations/2026-09-13_add_dictation_memorize_required.sql`（幂等：`information_schema` 判存在再 `ALTER`，沿用上次迁移的写法）供已建库的环境；
- 字段名取 `memorize_required`（不叫 `required`，避免与列约束语义混淆）；
- `DictationPassagesRepository`：`DictationPassageRow` / `DictationUpsertInput` / `SELECT_COLS` 增加该字段；`upsert` 写入该字段；
- **三条抽题查询全部加 `AND dp.memorize_required = 1`**：`findRandomVerified`（随机抽）、`findVerifiedBySubject`（配置页清单）、`findVerifiedByQuestionIds`（按篇目指定）——保证「非必背」篇目在整个语文默写界面都不可见、也不可被指定；
- `findByQuestionId`（判题取篇目）**保持不加门**：这是功能设计阶段已裁决的口径（详见默写功能 spec §6 注记），本次不改变。
- **种子脚本 `apps/server/src/scripts/seed-dictation-fixture.ts` 的两篇假数据需置 `memorize_required=1`**（否则迁移后默认 0，抽题池会空掉、专项立刻不可用——这正是决策 7 要避免的）。配套改动：`DictationPassagesRepository.upsert` 的入参类型与两条 fixture 的 upsert 调用各加一个字段；该脚本的「按业务键定位后原地 UPDATE」逻辑沿用不变。
- **抽题池门禁需有测试钉住**：三条查询各自断言 SQL 含 `dp.memorize_required = 1`（沿用上次「删守卫验证 RED」的做法，证明断言非空洞）。

## 8. 运行方式

**第 1–3 步直接使用既有 CLI**（不包装、不改造，避免与四阶段工具耦合）：

```bash
cd tools/crawler    && python src/crawler_cli.py  --site smartedu --subject 语文 --publisher 统编版 --grade 九年级 --semester 上册
cd tools/data-refinery && python src/convert_cli.py   --source smartedu --subject 语文 --term 上册
cd tools/data-refinery && python src/toc_parse_cli.py --source smartedu --subject 语文 --publisher 统编版 --grade 九上
```

**第 4–6 步是本次新建的独立 CLI**：`tools/data-refinery/src/dictation_cli.py`。

```bash
# 定位 + 切片 + 自检 → 出 JSONL、人工过目清单、待人工处理报告
python src/dictation_cli.py --extract --book "九年级/上册" --term 上册
# 入库（幂等）
python src/dictation_cli.py --load --book "九年级/上册" --term 上册
# 两步串起来
python src/dictation_cli.py --all --book "九年级/上册" --term 上册
```

> 说明：第 1–3 步刻意**不**收进 `dictation_cli.py`——`crawler_cli` 是 `tools/crawler` 的独立工具，`convert_cli`/`toc_parse_cli` 属四阶段管线；包装它们会引入跨工具耦合，而这三步本身就是可独立重跑、自带 checkpoint 的现成命令。

- 幂等：入库按 `dictation_passages` 业务键 `(work_title, semester)` upsert；`questions` 行的定位沿用种子脚本已采用的「按业务键找已有 `question_id` → 原地 UPDATE」策略（题面模板变化时不会插重复行）；
- 产物目录独立于数学管线（`output/dictation/`），互不干扰。

## 9. 测试与验收

**pytest 单测**（与既有 `tools/data-refinery/tests/` 同风格）

> **测试惯例修正（写计划时核实）**：`tools/data-refinery/pytest.ini` **没有** `network` marker——那是 `tools/crawler/pytest.ini` 专属。该工具的既有惯例是：**LLM 调用在单测里 mock SDK**（见 `tests/test_llm.py` 的 `_mock_client`），**DB 集成测试在 fixture 里运行时 skip**（见 `tests/test_db_loader_integration.py`）。本管线沿用同一惯例，不新增 marker。

**学科版式档案的回归测试（§4.2 重构的硬要求，用户明确要求「不要出现纰漏」）**

- **数学行为零变化**：把现有两条正则对**一组代表性行**的判定结果固化成黄金用例（含 `3 第二十一章 一元二次方程`、`第N章 X 页码`、`N.M X 页码`、`小结/复习题/数学活动/阅读与思考 … 页码` 的正例，以及 `## 练习`、长正文行、`第N单元` 等反例），重构前后必须逐条一致；
- 语文规则用**实测行**做用例：正例取 `1 沁园春·雪/毛泽东 3`、`阅读 7 …/习近平 22`、`9\*谈骨气/吴晗 33`、`第一单元 活动·探究 1`、`课外古诗词诵读 159`、`月夜忆舍弟/杜甫`（无页码的诗题）；反例取 `## 目录`、`注：阅读单元的课文分…`、水印句、正文长句；
- **目录页识别端到端**：用九上真实的 page_004–008 文本（可作 `tests/fixtures/` 静态片段）断言「004–007 被识别为目录页、008 不是」，这条直接对应本次实测发现的失效点。

**其余单测**

- 切片：锚点定位、跨页拼接、标点保留、换行/空格规范化；
- 自检：字数不符、含注释标记、含页眉残留、与篇名重复 → 各自被拦下；
- 低频字标记命中与否；
- 入库映射：JSONL → `questions`（`content='请默写《篇名》'`、`answer='作者：…\n朝代：…\n正文：…'`、`type='poem_dictation'`）+ `dictation_passages`（`verified`、`memorize_required=0`）；
- 幂等：同一 JSONL 连续两次入库不产生重复行；
- 迁移：`memorize_required` 幂等添加。

**真库验收**

1. 九上/九下两本的篇目全部入库，人工过目清单无遗留未处理项（或已明确记录）；
2. 抽题池只出 `memorize_required=1` 的篇目——即此时**只有那两篇开发假数据**（验证门禁生效）；把某真篇目手动置 1 后能从抽题池抽到；
3. 数学专项抽题/判题无回归（三条数学查询未受影响）。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| TOC 对语文目录解析不准（数学是先例，语文未验） | §4 第 3 步设为中途闸门，候选清单先给用户确认 |
| LLM 边界判断错（正文切多/切少） | 自动自检 + 锚点可追溯 + 人工过目长文言文 |
| **OCR 生僻字认错** | 低频字标记 + 定向人工复核；**无法自动消除，如实告知**（本方案唯一不可自动消除的风险） |
| 误判「是不是古诗文」（如现代词牌作品） | 单元上下文 + 候选清单人工过目 |
| `printed_page` 与 MD 页序偏移错位 | 沿用既有 `lesson_anchor` 锚定思路；自检中「与篇名一致性」可兜住明显错位 |
| 与数学管线互相干扰 | 独立 CLI + 独立产物目录；不改既有四阶段工具 |

## 11. 实施顺序

1. **数据模型变更**（`memorize_required` + 抽题池门禁 + 迁移折回）——先做，否则真篇目入库后会被抽出来；
2. **爬取 + 转换九上** → 肉眼确认 MD 形态与页码边界（已完成实跑，结论见 §4.1）；
3. **学科版式档案重构**（§4.2：基类 + 数学/语文实现 + 数学回归黄金用例）—— 目录候选依赖它，故置于目录步骤之前；
4. **目录候选**（九上）→ 候选清单给用户确认（中途闸门）；
5. **定位 + 切片 + 自检**（九上）→ 出人工过目清单；
6. **入库 + 真库验收**（九上）；
7. **九下** 重复 2、4、5、6；
8. **收尾**：数学与 Python 全量回归、文档同步（含两份 API 文档与 special-design 的 DDL 折回）。
