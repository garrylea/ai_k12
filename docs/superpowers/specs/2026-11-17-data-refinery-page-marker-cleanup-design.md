## 2. 问题分类与根因

### 2.1 P0：页脚/页眉混入正文

**根因链**：

1. MinerU 输出一个 md，页脚是普通文本行，没有页边界标记。
2. 试卷/答案链路没有页脚清洗：
   - `question_extract.extract_questions_file`：读 md → 全角括号归一 → 合并答案 → 去二维码 → `split_page`。
   - `answer_extract_cli.main`：读 md → `strategy.extract_answers`。
   - `answer_backfill.backfill`：读 md → `strategy.extract_answers`。
   - `scanned_emphasis._scan_pdf`：读 md → `split_page`（语文加点/画线定位）。
3. 切题器把所有非题号行当续行：
   - 题干区：`question_splitter.py:1171-1181` 追加到 `current.content`；材料区 `1044-1079`、`1184-1185` 追加到 `scope_pending`。
   - 答案区：`question_splitter.py:1037-1041` 追加到 `current_answer_lines`；语文自己的 `chinese.py:364-366` 同样追加。

**结果**：

- 页脚在答案里：答案末尾/中间多出页脚；
- 页脚在题干里：题干末尾/中间多出页脚；
- 页脚在共享材料里：同一段材料挂几道题，就污染几道题（Q19-21 实测）。

### 2.2 P0：答案区结构行被并入上一题

`（二）（共 5 分）` 这类小节标题在答案区不是题号。语文的 `extract_chinese_answers` 会跳过，但通用的 `split_page` 不会，结果是上一题答案末尾多出 `（二）`（`_strip_answer_prefix` 把 `（共 5 分）` 当分值剥掉，只剩 `（二）`）。

**根因**：两条入口行为不一致；`split_page` 的答案区缺少「结构行」过滤。

### 2.3 P1：跨页/跨栏阅读顺序导致答案错位或题干截断

**已复现（答案侧）**：2025 海淀数学二模答案，MinerU 把第 27 题的解法排到第 28 题前后；切题器按「答案题号必须递增」处理，Q26 混入 Q27 后半段，Q27 只剩开头。

**潜在（题干侧）**：

- 下一页开头是重复的大题/部分标题 → `is_group_header` / `is_part_header` 会关闭当前题并 `current=None`，后续续行在下一个题号前被丢掉；
- 下一页开头像新题号（前跳） → 可能新建假题、截断上一题；
- 选项跨页 → 页脚并入上一个选项正文；
- 表格跨页 → MinerU 可能拆成两个 `<table>`，第二个缺表头。

这类问题**不是页脚清洗能解决的**。本期只做「可确定、零猜测」的页脚/结构行清洗；P1 的阅读顺序重排另立设计，不在本批实现。

## 4. 页码标记口径

### 4.1 什么算页码标记（正例）

> **先澄清**：MinerU 对一份 PDF 输出**一个 md**，md 里没有页边界；本方案清洗的是「整份 md 中形如页码标记的行」，不是按页结构识别的「每页页眉/页脚」。真正的按页识别依赖 P1 的 JSON `page_idx` / `bbox`（§11）。

统一用 `PAGE_MARKER_RE` 匹配。必须同时满足：

- 有 `第 <阿拉伯数字> 页`；
- 后面跟「共 <阿拉伯数字> 页」或「/ <阿拉伯数字> 页」。

支持形态：

| 形态 | 示例 |
|---|---|
| 全角括号 | `第5页（共8页）` |
| 半角括号 | `第5页(共8页)` |
| 无括号、空格 | `第 1 页 共 5 页` |
| 斜杠 | `第2页/共6页`、`第2页／6页` |
| 逗号 | `第2页，共6页` |
| 括号/空格混合 | `第 1页（共 5页）` |

正则（实现以此为准）：

```python
_PAGE_NUM = r"[0-9０-９]{1,3}"
PAGE_MARKER_RE = re.compile(
    rf"第\s*{_PAGE_NUM}\s*页\s*"
    rf"(?:[（(]\s*共\s*{_PAGE_NUM}\s*页\s*[）)]"
    rf"|[／/]\s*共?\s*{_PAGE_NUM}\s*页"
    rf"|[，,]?\s*共\s*{_PAGE_NUM}\s*页)"
)
```

#### 4.1.1 弱锚点：独立页码碎片

当前语料里还发现一种「只剩半截」的页脚：`共6页` 独占一行（昌平一中 Q25，`questions.id=6713`）。它没有 `第N页`，强锚点匹配不到；但整行完全等于 `共N页`，几乎不可能是正文。另加两个**只用于整行**的弱锚点：

```python
BARE_PAGE_RE = re.compile(rf"^第\s*{_PAGE_NUM}\s*页\s*$")
BARE_TOTAL_RE = re.compile(rf"^共\s*{_PAGE_NUM}\s*页\s*$")
# 「第」被 OCR 丢掉，只剩「2页 共7页」（昌平一中语文 2024，一脏脏三题）
BARE_PAGE_TOTAL_RE = re.compile(
    rf"^{_PAGE_NUM}\s*页\s*[，,]?\s*共\s*{_PAGE_NUM}\s*页\s*$"
)
```

- 只匹配**整行**，不做行内删除；所以「请阅读第 2 页」「本试卷共 8 页」不会命中。
- 命中即整行删除，不需要 residual 判定。
- 当前语料命中：`共6页` 1 处、`2页 共7页` 1 处（3 行）；`第N页` 独行暂无真实样本，但属于同类碎片，一并支持。

### 4.2 什么不算（负例，绝不删）

| 负例 | 原因 |
|---|---|
| `本试卷共8页，共两部分…` | 没有「第 N 页」，是考生须知 |
| `请阅读第 2 页的问题 1` | 没有「共 M 页」/`/M页`，是正文引用 |
| 单独一行 `1`、`2`、`3`、`4` | 可能是图片标号（一零一物理实测），不是页码 |
| 围栏代码块里的 `第1页` | 可能在内嵌 SVG/代码里 |
| HTML 标签内部的 `第1页` | 删除会破坏标签 |
| `<table>…</table>` 里的 `第1页` | 删除可能破坏表格结构 |

> 整行只有 `第5页` 或 `共6页` 属于弱锚点，按 §4.1.1 删除；只有它们出现在句子中间（`请阅读第 2 页`）才保留。**不得**删除裸数字行（图片标号）。

> **硬约束**：不得用「删除纯数字行」这种规则。页码必须由「第N页 + 共M页/斜杠」或「整行只有 第N页/共N页」锚定；裸数字行、正文里的「第N页」引用一律保留。

### 4.3 整行删除 vs 行内删除

清洗按行处理，每行分三种情况：

1. **整行删除**：删掉页码标记后，剩余内容为空，或剩余内容是一个「纯页眉/页脚」。
2. **行内删除**：页码标记嵌在正文/答案行里，只删除标记和紧邻的运行页眉片段，保留正文。
3. **整行保留**：标记不在允许的位置（围栏、HTML 标签、表格内），或形态不匹配；原样保留并记 issue。

#### 4.3.1 纯页眉/页脚判定

`residual = PAGE_MARKER_RE.sub("", line).strip()`；判定前再去掉 Markdown 标题前缀 `#{1,6}`（与 `page_chrome._normalize` 同口径），避免 `# 第5页（共8页）` 留下孤立的 `#`。

`residual` 满足以下全部条件 → 整行删除：

- 长度 ≤ 50；
- 不含句末标点 `。！？；`；
- 不以题号/小节编号开头（`^\d{1,2}[.．、]`、`^[（(][一二三四五六七八九十]+[）)]`）；否则只删标记，不删整行，避免丢掉「27．评分参考」「（二）」这类标题；
- 不含分值括号（`[（(]\s*(?:共)?\s*\d+(?:\.\d+)?\s*分`）；否则只删标记，避免丢掉「（2分）」这类答案内容；
- `residual` 为空、命中 `_RUNNING_HEAD_RE`、命中 `_PAPER_HEAD_RE`、命中 `_SUBJECT_GRADE_RE`，或只是一个日期/年份（`^20\d{2}(?:[.．-]\d{1,2}|年\d{1,2}月)?$`）。

不满足 → 走行内删除；不要用「含试卷/答案/年级等关键词」这种宽泛条件整行删，避免误删「考试时间 120 分钟」这类正文。

`_RUNNING_HEAD_RE` / `_PAPER_HEAD_RE` / `_SUBJECT_GRADE_RE`（严格白名单，只认已确认的形态；未识别形态不整行删，走行内删并记 issue）：

```python
_RUNNING_HEAD_RE = re.compile(
    r"^(?:"
    r"(?:[一二三四五六七八九]年级\s*[（(]?\s*(?:语文|数学|英语|物理|化学|道法|政治|历史|地理|生物)?\s*[）)]?)"
    r"|(?:[^。！？；]{0,50}?(?:试卷|试题)[^。！？；]{0,30}?(?:答案及评分(?:参考|标准)|参考答案|评分参考))"
    r"|(?:[^。！？；]{0,30}?(?:答案及评分(?:参考|标准)|参考答案|评分参考))"
    r")(?:\s*20\d{2}(?:[.．-]\d{1,2}|年\d{1,2}月)?)?$"
)

# 只有「试卷/试题」、没有「答案及评分」的页眉（如「北京市西城区九年级模拟测试试卷」）
# 排除「请参考试卷」「见试卷」「阅读试卷」这类正文指令
_PAPER_HEAD_RE = re.compile(r"^[^。！？；请见阅读参看]{0,40}(?:试卷|试题)$")

# 只有学科/年级的页眉（如「语文」「九年级数学」）
_SUBJECT_GRADE_RE = re.compile(
    r"^(?:[一二三四五六七八九]年级\s*)?"
    r"(?:语文|数学|英语|物理|化学|道法|政治|历史|地理|生物)\s*"
    r"(?:试卷|试题)?$"
)
```

判定示例：

| 行 | residual | 判定 |
|---|---|---|
| `第5页（共8页）` | 空 | 整行删 |
| `共6页`（独占一行） | — | 整行删（弱锚点） |
| `第5页`（独占一行） | — | 整行删（弱锚点） |
| `语文试卷答案及评分参考 第 1页（共 5页）` | `语文试卷答案及评分参考` | 整行删 |
| `北京市西城区九年级模拟测试试卷 第2页（共6页）` | `北京市西城区九年级模拟测试试卷` | 整行删（`_PAPER_HEAD_RE`） |

| `九年级物理试卷答案及评分标准 第2页（共2页）` | `九年级物理试卷答案及评分标准` | 整行删 |
| `（2分，每空 1 分。有错该空不得分）语文试卷答案及评分参考 第 1页（共 5页）` | `（2分，…不得分）语文试卷答案及评分参考` | **不整行删**（含 `。`），走行内删 |
| `⑪…全留在一桥一水一九年级（语文）第8页（共11页）` | `⑪…全留在一桥一水一九年级（语文）` | **不整行删**（长度 > 50），走行内删 |

#### 4.3.2 行内删除

只删除「页码标记 + 紧邻的运行页眉」，不碰正文。运行页眉用严格白名单：

```python
_INLINE_HEAD_RE = re.compile(
    r"(?:"
    r"(?:[一二三四五六七八九]年级\s*[（(]\s*(?:语文|数学|英语|物理|化学|道法|政治|历史|地理|生物)\s*[）)])"
    r"|(?:[^。！？；）)]{0,30}?(?:试卷|试题)[^。！？；）)]{0,30}?(?:答案及评分(?:参考|标准)|参考答案|评分参考))"
    r"|(?:[^。！？；）)]{0,20}?(?:答案及评分(?:参考|标准)|参考答案|评分参考))"
    r")(?:\s*20\d{2}(?:[.．-]\d{1,2}|年\d{1,2}月)?)?\s*$"
)
```

算法（从标记起点向左看）：

1. 在 `line[:marker.start()]` 的末尾匹配 `_INLINE_HEAD_RE`；匹配上就把删除起点前移到该片段开头。
2. 若删除起点落在标点/空白上（`，,、：:；;）)（( `、全角空格），向右移到第一个非标点字符，避免把上一句的逗号/右括号删掉。
3. 合并片段与标记之间的空白（空格/全角空格）。
4. 删除 `[删除起点, marker.end())`。
5. 如果删除点两侧都是非空白文本，直接拼接（不插空格）；如果两侧有空格，保留一个。
6. 同一行有多个页码标记时，行内删除要循环处理，直到该行没有 `PAGE_MARKER_RE` 命中；每次重新计算删除区间，避免偏移。
7. **行尾续行合并**（仅行内删除且标记位于行尾）：若删除后当前行非空、不以句末标点 `。！？；` 结尾，且下一行（可跨过空行）非空、不含 `PAGE_MARKER_RE`、不是结构行（`#` 标题 / `![` 图片 / `<table` / 列表 `- * +` / 题号 `^\d{1,2}[.．、]` / `（一）` 小节 / `一、` 大题 / `第N部分` / 字段行 `^(答案|思路|解析|题型|答案示例)\s*[:：]` / 分隔线 `^-{3,}$` / 页码行 `^第\s*\d+\s*页`），则把下一行 `lstrip` 后并入当前行，并跳过下一行（连同中间空行）。目的：避免 `preprocessMaterialMarkdown` 把「一桥一水一」和「人家之间了」当成两个段落。真实八一案例页脚后有空行，续行仍要合并；空行后是结构行则保留空行，不合并。

两个补充护栏：

- **标题行只删页码**：`## 27．评分参考 第5页（共8页）` 只删页码，不能把标题词「评分参考」当运行页眉删掉；
- **有一个标记被保护就不整行删**：同一行只要有一个标记在表格/标签/围栏内，就跳过整行删除，只删未被保护的标记，避免把表格单元格一起删掉。

判定示例：

| 原行 | 删除片段 | 结果 |
|---|---|---|
| `…（2分，每空 1 分。有错该空不得分）语文试卷答案及评分参考 第 1页（共 5页）` | `语文试卷答案及评分参考 第 1页（共 5页）` | `…（2分，每空 1 分。有错该空不得分）` |
| `…全留在一桥一水一九年级（语文）第8页（共11页）` | `九年级（语文）第8页（共11页）` | `…全留在一桥一水一` + 下一行 `人家之间了…`（行尾续行合并，结果为 `…一桥一水一人家之间了…`） |
| `…（4分）` 后独立页脚行 | 整行删除 | 正文不变 |

> 整行删除默认**不做**跨行 join：已知案例里，整行页脚都落在段落/题边界（Q24、答案末尾），句子被切断的八一案例是行内粘连。若后续出现「整行页脚夹在句子中间」的新样本，再按同一规则扩展。

### 4.4 护栏

- **围栏代码块**：遇到 ` ``` ` 开/闭围栏时切换状态；围栏内不删任何东西。
- **HTML 标签内部**：若标记起点之前最近的 `<` 比最近的 `>` 更近，说明在标签内，跳过。
- **表格内部**：维护 `in_table` 状态（`<table` 开、`</table>` 关）；同一行内用位置判断，跨行表格用状态判断；表内不删并记 issue。
- **图片语法**：若标记位置在 `![...](...)` 内，跳过并记 issue。
- **幂等**：清洗两遍结果相同。
- **不改变未命中行**：逐行处理，未命中的行原样返回（包括行尾空格；实现时只对命中行做 `rstrip`）。

## 5. 模块设计

### 5.1 新模块 `src/page_markers.py`

```python
"""试卷/答案页脚页码标记清洗（确定性，不调 LLM）。"""

@dataclass(frozen=True)
class PageMarkerHit:
    line_no: int              # 原始文本中的 1 基行号
    raw: str                  # 被删除的完整片段（含运行页眉）；manual 时为整行
    whole_line: bool          # True=整行删除，False=行内删除
    removed: bool = True      # False=表格/标签/围栏内命中，不删、留人工复核

def strip_page_markers(text: str) -> tuple[str, list[PageMarkerHit]]:
    """删除试卷/答案里的页码标记。

    - 只处理 PAGE_MARKER_RE / BARE_PAGE_RE / BARE_TOTAL_RE 命中的行；
    - 整行/行内两种模式见 §4.3；
    - 围栏/HTML 标签/表格内跳过；
    - 幂等；返回清洗后文本与命中列表（供调用方打日志）。
    """

def is_page_marker_line(line: str) -> bool:
    """答案区结构过滤用：该行是否是页码标记（不负责删除）。"""
```

实现要点：

- 先判弱锚点 `BARE_PAGE_RE` / `BARE_TOTAL_RE`（整行），再判强锚点 `PAGE_MARKER_RE`（整行/行内）。
- 行号以 `text.split("\n")` 的 1 基索引为准；整行删除时**彻底删除该行、不保留空行**。理由：页脚通常已独占一行，前后已有空行；保留空行会在答案正文里留下多余空行。
- 行尾统一为 `\n`（现有 md 均为 LF）；CRLF 输入允许行尾归一，但未命中行的文本内容不得改变。
- 若删除整行后，相邻两行都是非空正文，保持两行不动，不主动 join（避免把两段无关内容拼在一起）。
- 只对命中行调用 `_strip_inline`；未命中行原样 `append`，保证不改变其他内容。
- `PageMarkerHit.raw`：整行删除时为整行原文；行内删除时为被删片段原文。
- 返回的 `hits` 用于调用方打印 `[page-marker] <stem>: 删除 N 处（行 37、39）`。**调用方必须按 `removed` 分开统计**：`removed=True` 计入删除数；`removed=False` 打印 `[WARN] page-marker 未处理`（表格/标签/围栏内），不计入删除数。
- `strip_page_markers` 不抛异常、不写 `answer_issues.jsonl`；未识别运行页眉时只删标记，调用方根据 `hits` 打印 `[WARN] page-marker 未识别运行页眉：<行号>`。

## 6. 题目区跨页的影响与边界

### 6.1 为什么题干通常不会「缺一半」

md 没有页边界 token。跨页时，下一页的续行仍是普通文本行，`split_page` 会把它追加到当前题 `content` 或 `material_text`。所以：

- 单纯跨页：题干/材料通常是**完整但脏**（多页脚），不是缺一半；
- 页脚落在选项之间：会并入上一个选项正文；`split_options` 不会清；
- 页脚落在共享材料中间：一段材料污染多题（Q19-21 实测）；
- 页脚落在题干末尾：题干末尾多一行页脚（Q24 实测）。

### 6.2 什么情况会真的截断

只有下一页开头出现**结构行**时：

- 重复的大题标题 `一、选择题` → `is_group_header` 分支关闭当前题；
- 部分标题 `第二部分 非选择题` → `is_part_header` 分支关闭当前题；
- 题号行 `21. …`（假题号）→ 新建题，上一题结束。

当前样本里，重复的大题标题都恰好落在题边界/答案区，未命中截断；但机制存在。§5.5 的告警用于发现它。

### 6.3 选项跨页的边界

若页脚落在 `A. …` 与 `B. …` 之间，`split_options` 按选项标记切分，页脚会成为 A 选项正文的一部分。清洗后页脚消失，选项恢复正确。若页脚以 `A`/`B`/`C`/`D` 开头（几乎不会），才可能多出假选项；本期不做额外防御。

### 6.4 表格跨页的边界

MinerU 可能把跨页表格拆成两个 `<table>`。第二个表若没有表头，`parse_answer_table` 可能解析失败。本期不处理；`[WARN] 答案表有题号没解析出答案` 已存在，命中时按既有流程人工核对。

## 7. 数据库清洗

### 7.1 清洗范围

| 表 | 字段 | 是否清洗 | 说明 |
|---|---|---|---|
| `questions` | `content` | 是 | 题干；改动后需重算 `content_hash` |
| `questions` | `material_text` | 是 | 共享材料；不影响 `content_hash` |
| `questions` | `answer` | 是 | 答案 |
| `questions` | `explanation` | 是 | 解析 |
| `questions` | `approach` | 是 | 思路 |
| `questions` | `options` | 否 | JSON；如扫到页码只记人工复核 |
| 其他表 | — | 否 | 不改 `is_active`/`answer_verified` |

### 7.2 `content_hash` 处理

`content_hash = SHA256(normalize_content(content) + "\x1f" + options_signature(options))`（`db_loader.content_hash`；无选项时只哈希正文）。

- `content` 被清洗时：
  - 旧 `content_hash` 为 `NULL` → 保持 `NULL`（不引入新哈希）；
  - 旧 `content_hash` 非空 → 用清洗后的 `content` + 原 `options` 重算；
  - 新哈希与旧哈希相同 → 不更新该列；
  - 新哈希与**其它行**冲突（`content_hash` 唯一索引）→ **整行跳过**，打印 `[conflict]`，留给人工合并；不自动改 `is_active`。
- `material_text`/`answer`/`explanation`/`approach` 改动不影响 `content_hash`。

行为：

1. 连接 DB，查询待扫描行：
   ```sql

   FROM questions q
   WHERE 1=1
     [AND EXISTS (SELECT 1 FROM paper_questions pq
                  WHERE pq.question_id=q.id AND pq.paper_id=%s)]  -- --paper-id
     [AND q.subject_id=(SELECT id FROM subjects WHERE code=%s)]  -- --subject
   [LIMIT %s]  -- --limit
   ```
   `options` 不参与清洗，只用于 `content` 变化时重算 `content_hash`。
2. 另查 `paper_questions` 建 `question_id -> (paper_id, question_no)` 映射（只用于预览展示；一题可挂多卷时取第一行并标 `+N`）。
3. 对每个字段调用 `strip_page_markers`；无命中跳过。
4. 打印预览（前后各 80 字，换行用 `\n` 转义）。
5. 若 `--apply` 且 `--yes`：
   - 写备份 JSONL（旧值 + 新值 + 命中列表）；
   - `conn.begin()`；
   - 按 `question_id` 聚合，一条 `UPDATE questions SET <变化列>=%s[, content_hash=%s] WHERE id=%s` 写该行所有变化列（避免半行更新）；
   - `conn.commit()`；
   - 重新扫描，断言「可自动清理的标记」为 0；非 0 则打印失败明细并退出 1；
   - 表格/HTML 标签/围栏内的标记不自动改，单独打印 `[manual]` 清单，不计入硬 0 断言。
6. 幂等：第二次运行应显示 0 命中。

安全：

- 不使用 `UPDATE ... WHERE id IN (...)` 批量覆盖；逐行、只写变化的列。
- 备份文件写在 `output/`，不覆盖旧备份（时间戳命名）。
- 失败回滚，不半写。
- 不显式写 `updated_at`；列级 `ON UPDATE CURRENT_TIMESTAMP(3)` 会自动更新。
- 不改 `content_hash` 以外的派生字段。

### 7.4 回滚

- 备份 JSONL 包含 `id`、字段名、旧值；手工回滚用 `UPDATE questions SET <field>=<old> WHERE id=<id>`。
- 不提供自动回滚 CLI（避免误用）；设计文档记录手工步骤即可。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 误删正文里的「第 N 页」 | 内容丢失 | 只认「第N页 + 共M页/斜杠」；负例测试；裸数字绝不删 |
| 行内删除切到正文 | 句子被截断 | 运行页眉用严格白名单 `_INLINE_HEAD_RE`；未知形态只删标记并记 issue |
| 围栏/HTML/表格内删除 | 破坏 SVG/表格 | 围栏状态机 + 标签/表格位置判断；命中只记 issue |
| `content_hash` 冲突 | 唯一索引报错 | 先查冲突；冲突整行跳过并打印 `[conflict]`，不自动合并 |
| 改动 `answer_verified=1` 的答案 | 已核验数据被静默改 | 不重置标记；CLI 输出 `[note]` 列出这些 id，建议抽查 |

| 行号偏移影响 `split_suspects` | LLM 复核行号错位 | 清洗在 `split_page` 前一次完成；suspects 使用清洗后行号；不跨轮混用 |
| 存量 md 未清洗 | 重跑提取仍脏 | 清洗在提取入口执行；不需要改写 md；文档注明 |
| 真实 PDF 还有其他页脚形态 | 漏删 | 未识别形态记 issue；用 `[page-marker]` 日志暴露；后续按样本扩白名单 |

## 11. P1 设计（另案，不在本批实现）

### 11.1 目标

解决「跨页/跨栏阅读顺序导致的答案错位、题干截断」，以及「裸页码/重复运行页眉」在没有 `第N页（共M页）` 锚点时的识别。

### 11.2 方案

利用 MinerU `extract -f md,json` 的 sidecar JSON：

- 每个块有 `page_idx` + `bbox`（0–1000 归一化）；
- 页面顶部/底部 8% 的短文本块，若在多页重复，判为页眉/页脚；
- 没有页码锚点的重复运行页眉（如每页顶部重复「语文试卷答案及评分参考」）也用同一频率 + 页面边缘规则识别；本期不处理，避免误删答案区标题；
- 裸页码（`5`、`— 5 —`）只有在页面边缘才删，不会误伤正文里的图片标号；
- 重复的大题标题如果落在页面顶部且文本相同，判为运行页眉，不触发 `is_group_header`；
- 跨页答案错位：按 `page_idx + bbox` 重排，或至少在题号回退时用页边界判断「这是上一页的续行还是下一页的新题」。

**英语卷 `Page N of M`**：当前语料 0 样本，本期不实现、不凭猜测启用；后续导入英语试卷时先收集样本，再扩 `PAGE_MARKER_EN_RE` 和英文运行页眉白名单。

### 11.3 不推荐的做法

- 直接从块数组重建 Markdown：会丢失 MinerU 已生成的表格/公式/图片排版，风险高。
- 用「题号回退就自动合并到已有题」：会把合法的题号乱序（如题 18 排在题 14 前）误合并；现有代码已证明不能顺延。

### 11.4 交付物（另案）

- `src/page_layout.py`：读 sidecar、页面边缘块识别、chrome 集合；
- `split_page` 增加可选的 `page_boundaries` 参数（仅 P1 使用）；
- 新增 `page_layout.jsonl` 诊断日志；
- 独立 spec + plan，不与本批混做。
