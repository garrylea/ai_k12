# 错题补偿套题（相似题专项练习）设计

- 日期：2026-09-21
- 状态：已与用户逐项确认（分组粒度 / 提示位置 / 新旧合并 / AI 题沉淀 / 完成语义 / 生成同意 / 计分方案）
- 范围：训练轨 · 仅数学 · 触发场景 = 真题考试 + 专项练习
- PRD 锚点：§6.3 训练轨、§7.6 末条「测评后推荐薄弱点专项练习」（本功能是该句的具体实现）、§7.13 积分体系

## 1. 背景与目标

训练轨的考试 / 专项练习做完后，错题只进错题本被动等学生自己去练，缺一个**主动推送的补偿训练闭环**。本功能：考/练出分后征得学生同意，按错题生成一套「同考点、同题型、同难度」的相似题（每组 3 题），挂在训练轨三卡页持续提示，答对清题、全对清套。

与 §7.10 错题变式**互补不冲突**：变式 = 错题**再次**做错时触发的原题改造；本功能 = 考/练**完成后**主动推荐的相似题组，题库优先、AI 兜底。

## 2. 核心决策（用户逐项裁决）

| # | 决策点 | 裁决 |
|---|---|---|
| 1 | 分组粒度 | 按（考点 + 题型 + 难度）**三元组去重**：两道错题三元组全同 → 共用一组；任一不同 → 各自一组 |
| 2 | 每组题量 | 3 题 |
| 3 | 生成前提 | 交卷/专项完成后**询问学生**，同意才生成；跳过则什么都不发生（原错题照常入错题本，§7.4 不变） |
| 4 | 提示位置 | 训练轨三卡页（/student/training/home）顶部提示条；套题未清掉就每次进页都提示 |
| 5 | 新旧套题冲突 | **追加合并去重**：新错题三元组若已有组则跳过，新三元组追加组 |
| 6 | AI 生成题去留 | **入库可复用**：写入 questions（source='remediation'），过轻校验，后续同考点可再抽到 |
| 7 | 完成语义 | **套题自清零**：答对 → 该题标「已答对」；答错 → 留在套题稍后再出；**全部题答对 → 整套记录从库中删除**（questions 里的题本身不动，清的是套题记录） |
| 8 | 错题本关系 | 套题作答**不入错题本、不参与主线清零门禁**（原错题已按 §7.4 入本，不重复记账） |
| 9 | 积分 | **每做一道题都给分、高分值、不看对错**：选择题 3 / 填空题 4 / 大题 6（见 §7） |

## 3. 整体流程

```text
数学真题考试交卷/超时收卷 → 出分页        数学专项练习完成 → 完成页
        │                                        │
        └──────────┬─────────────────────────────┘
                   ▼
   有判错题？──否──→ 什么都不发生（现状）
                   │是
                   ▼
   询问卡：「本场错了 N 题（M 题可生成），生成相似题专项练习？」
      [生成] ──────────────── [跳过] → 不生成（原错题照常入错题本）
                   │
                   ▼
   三元组去重成组，每组 3 题：题库抽题 → 难度放宽一档 → AI 生成补齐
                   │
                   ▼
   训练轨三卡页顶部提示条：「待完成相似题专项练习：N 题 / M 组」
      [开始练习] → 套题作答页        [稍后再说] → 留在三卡页
                   │
                   ▼
   逐题作答（复用训练轨作答流：答题卡/判题/草稿抽屉）
   答对 → 该题标记已答对（答题卡打勾）；答错 → 留在套题稍后再出
   每题首次作答即发积分（对错不限，每题只发一次）
                   │
                   ▼
   全部题答对 → 整套记录删除 → 回三卡页
```

## 4. 数据模型（新迁移，折回 schema.sql）

| 表 | 关键列 | 说明 |
|---|---|---|
| `remediation_sets` | student_id, subject_id, status('active'), created_at, updated_at | 每学生每学科至多一条 active |
| `remediation_groups` | set_id, kp_id, type, difficulty, ai_pending_count, UNIQUE(set_id, kp_id, type, difficulty) | 三元组去重靠唯一键；`ai_pending_count` 记 AI 补题缺口 |
| `remediation_set_items` | group_id, question_id, origin_question_id, is_correct, points_awarded, attempts, last_answered_at | `origin_question_id` 留审计；答对即 `is_correct=1`；`points_awarded` 防重复发分 |

约束与口径：

- 三表级联挂 students（删除学生清套题）；`question_id` 外键 RESTRICT（题库题不可因套题被删）；`ai_pending_count` 是组内尚未到位的 AI 题数。
- **追加合并去重**靠 `remediation_groups` 的唯一键：INSERT 撞键 = 该三元组已有组，跳过。
- 无知识点标注的错题（`question_knowledge_points` 无 primary 行）无法成组 → 跳过；询问卡显示「N 题中 M 题可生成」。

## 5. 生成器

### 5.1 触发与同步边界

- 触发点：真题考试 `finalizeSession`（手动交卷与超时收卷同一出口）、专项练习完成出口。**生成不挂在交卷响应路径上**——同意生成的请求本身只同步做「建组 + 题库抽题」，即刻返回。
- **AI 补题异步 fire-and-forget**（工程铁律：LLM 调用无墙钟上限，凡在关键路径上必出事）。进程内 promise 继续跑；**进程重启导致 `ai_pending_count` 悬挂时，下次读取套题惰性重试**（发现缺口且无 in-flight 任务则重新触发生成）。

### 5.2 题库抽题谓词

- 候选：subject = 数学 ∧ `question_knowledge_points` primary = 该考点 ∧ type 相同 ∧ difficulty 相同 ∧ is_active。
- 排除：原错题本身、该学生 active 套题已有题、「不再展示」标记题（复用 targeted 的 exclude-marked 机制）、停用题。
- **放宽阶梯**：同难度抽不满 3 → difficulty ±1 各试一轮 → 仍不足由 AI 生成补齐至 3。
- 首期不按「该学生是否做过」排除（题库量与实现成本考量，只排除原错题与在套题）。

### 5.3 AI 生成与入库

- 复用 ai-core `variation` 场景（基于原错题换数 / 换场景 / 调条件），无需新增场景路由。
- 轻校验（照 `variation_questions.validator_passed` 先例）：题干完整、题型合法、有可解答案；数学题过逻辑自洽校验（§7.10 风控要求）。
- 入库 `questions`：`source='remediation'`、`answer_verified=0`、`content_hash` 去重（复用辅轨规则，撞 hash 复用已有题 ID）。**不复用 `variation_questions` 表**（它挂 `original_error_item_id`，语义是「错题再错变式」，来源不同）。
- 校验不通过的 AI 题不入库、不入套题；该组维持题库抽到的题（可少于 3 题），`ai_pending_count` 清零并留日志。

## 6. 作答与清零

- 逐题作答复用训练轨既有链路：判题走 `judgment` 出口、草稿抽屉、答题卡。
- 答对 → `is_correct=1`（答题卡打勾置灰，不再出）；答错 → `is_correct` 保持 0，排到套题后面重新出。
- 全部 items `is_correct=1` → 删除 `remediation_sets` + `groups` + `items` 三表相关行（物理删除，用户裁决「清的是套题记录」）。
- 套题作答**不写错题本、不参与主线门禁**（§2 决策 8）。

## 7. 积分（新任务 `remediation_question`）

挂进现有 `point_rules` / `point_ledger` / `student_points` 体系，档位语义 = 题型（与 `cn_dictation` 体裁档位同构）：

| tier_key | tier_label | points | 默认每日上限 |
|---|---|---|---|
| `choice` | 选择题 | 3 | 不限 |
| `fill_blank` | 填空题 | 4 | 不限 |
| `major` | 大题 | 6 | 不限 |

- **题型映射**：`choice` + `true_false` → `choice` 档；`fill_blank` → `fill_blank` 档；其余（`calculation` / `proof` / `short_answer`）→ `major` 档。
- **发分时机**：每题**首次作答**即发，**不看对错**（对齐平台「完成即给分」哲学与用户「鼓励多做」的诉求）；`dedupe_key` 幂等保证**每题（set item）全程只发一次**——有意偏离「跨天可再得」默认，理由：套题内同一题反复作答是清零流程的一部分，不是新任务，且防刷分。
- `ref_type='question'`，`ref_id` = `remediation_set_items.id`。
- 家长可改分值 / 上限 / 停用档位（既有 point_rules 能力，零额外开发）；默认规则只对新学生生效（既有行为）。学生端 `GET /api/points/me/rules` 自动带出新任务。
- 套题**整体完成**不另发整套奖励（避免双重计分）。

## 8. API（挂 training 模块；API 文档 §4 / openapi.yaml 同步更新）

| 端点 | 语义 |
|---|---|
| `POST /api/training/remediation/generate` | 学生同意后调用；body 带来源（考试 sessionId / 专项 trainingSessionId）；同步完成建组 + 题库抽题即返回套题概要，AI 补题后台跑 |
| `GET /api/training/remediation/me` | active 套题概要（组数 / 总题数 / 未答对数），三卡页提示条用；顺带做 ai_pending 惰性重试 |
| `GET /api/training/remediation/questions` | 拉取未答对题目（含渲染数据），作答页用 |
| `POST /api/training/remediation/answers` | 逐题提交，走既有判题链路；判对置 `is_correct`；首次作答发积分；全对删套题记录并在响应中返回完成态 |

注意 Nest `@Post` 返回 201，openapi 按 `'201'` 记（仓内约定）。

## 9. 前端

- **询问卡组件**：考试出分页 / 专项完成页复用同一组件；显示「错了 N 题（M 题可生成）」+ [生成] [跳过]。
- **三卡页提示条**：有待完成套题时显示（组数 / 题数），[开始练习] [稍后再说]；非阻断。
- **套题作答页**：复用训练轨逐题作答组件；答题卡上已答对的题打勾置灰；答错的题排后重出；全对后跳回三卡页并提示完成。
- 样式遵守 `style.md` §2 唯一配色、线性 SVG 图标、无 emoji；训练轨页面写死 `data-theme="student-day"`（既有规则）。

## 10. 边界与不做清单

- **仅数学、仅训练轨（考试 + 专项）触发**；错题练习做错不触发（它本身就是清零场景）、主线作业做错不触发（留作后续扩展，数据模型天然支持）。
- 套题作答不入错题本、不参与主线门禁、不影响主线进度。
- 不做：套题手动删除/放弃（用户未提；「稍后再说」已是非破坏性出口）、跨学科扩展、按学生做题历史排除候选题、整套完成额外奖励。
- 订阅 / 额度不受影响（套题是普通判题 + 可能的 LLM 生成，走既有 llm_call_logs 记账）。

## 11. 测试要点

- **后端**：三元组去重（全同共用组 / 任一不同分组）、追加合并撞唯一键跳过、抽题谓词与放宽阶梯、排除项（原错题/在套题/不再展示/停用）、AI 异步入库与 `ai_pending_count` 悬挂惰性重试、AI 校验失败不入库不悬挂、判对回写 `is_correct`、全对三表删除、无考点错题跳过、积分首答即发 + dedupe 幂等 + 题型映射、`GET /me` 概要口径。

- 判题链路复用不新写判题逻辑，只测出口回写。
