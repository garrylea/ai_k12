# 教研角色与内容纠错 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `researcher`（教研）角色，把试卷管理从 admin 迁到教研，支持查看试卷内容、更正五字段（题干/选项/答案/解析/思路）、在字段里上传多图并做完整图片生命周期清理，所有改动写审计，改答案不回填历史数据。

**Architecture:** 后端复用 `admins` 表加 `role` 列区分 admin/researcher，`RolesGuard` 泛匹配天然支持新角色；新建独立 `ResearchModule`（controller/service/repo 三组），试卷仓储从 `admin-papers.repo.ts` 迁移；图片复用 `uploaded_files` 表 + `source='research'` 分目录，清理逻辑集中在 `ResearchImagesService` 供题目 PATCH 与删卷共用；新增 `content_audit_logs` 表记录三类改动；前端新 `/research` 路由组与轻量布局，编辑抽屉复用 LatexEditor 的占位→上传→替换模式但做五字段隔离。

**Tech Stack:** NestJS 10 + TypeScript + mysql2 + zod + vitest（server）；React + Vite + TS + Tailwind + React Router 6 + Zustand + vitest + @testing-library/react（web）；MySQL 8（迁移脚本手工 apply）。

## Global Constraints

- 角色标识固定 `researcher`；JWT 角色联合类型 = `'admin' | 'researcher' | 'parent' | 'student'`。
- `auth_sessions.role` 枚举中 `researcher` **必须追加在末尾**，不得插到首位（ENUM 序数值参与排序/比较，改序会漂移存量值）。
- `admins.role ENUM('admin','researcher') NOT NULL DEFAULT 'admin'`；存量 admin 行自动保持 admin。
- 可编辑字段**仅限五个**：`answer` / `content` / `options` / `explanation` / `approach`。题型/难度/满分/`material_*`/图片替换本期不做。
- `content_hash` **不重算**；`answer_verified=1` 仅在本次改了 `answer` 时置位。
- 图片：复用 `uploaded_files`，`source='research'`，落盘 `UPLOAD_DIR/research/<uuid><ext>`，URL `/uploads/research/<uuid><ext>`；**零新增图片表**。
- 删除图片五条铁律：只清 research 图；删前全局扫描 `questions` 五列 + 学生作答三表确认无引用；`extract_tasks` 关联行跳过；磁盘删除在 DB commit 后且失败只记日志；每次清理写审计。
- `approach` 字段禁止相对路径图（物化盲区，`publish_cli.py:33` / `db_loader.py:103` 都不含 approach）。
- 保存按钮禁用条件（任一即禁）：无字段变更、`confirmedSource` 未勾选、有上传在 flight、saving 中。
- 编辑抽屉常驻静态提示：「本次修正仅影响之后的判题，不会修改已有作答记录、错题本、积分与掌握度。」
- 组件改动必须补渲染测试；`globals:false`，多用例文件必须自己写 `afterEach(() => cleanup())`。
- 后端分页列表用 `pool.query`，计数/详情用 `pool.execute`（`LIMIT ?` 在 execute 下预编译失败，仓内有护栏测试）。
- 迁移脚本必须幂等（沿用 information_schema + PREPARE 模式）；含 DDL 的批次收尾跑 `python3 tools/db/schema_reconcile.py`。
- 给用户的交付命令只能有一条（若需要交付脚本，收尾串成一个入口）。
- UI 不用 emoji、不用装饰元素；颜色只用现有 token。

```sql
-- 1) admins.role
SET @col := (SELECT COUNT(*) FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'admins' AND COLUMN_NAME = 'role');
SET @ddl := IF(@col = 0,
  'ALTER TABLE admins ADD COLUMN role ENUM(''admin'',''researcher'') NOT NULL DEFAULT ''admin''',
  'SELECT 1');
PREPARE stmt FROM @ddl; EXECUTE stmt; DEALLOCATE PREPARE stmt;

-- 2) auth_sessions.role 扩枚举（researcher 追加末尾，不改存量序数）
SET @enum := (SELECT COLUMN_TYPE FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'auth_sessions' AND COLUMN_NAME = 'role');
SET @ddl := IF(@enum LIKE '%researcher%', 'SELECT 1',
  'ALTER TABLE auth_sessions MODIFY COLUMN role ENUM(''admin'',''parent'',''student'',''researcher'') NOT NULL');
PREPARE stmt FROM @ddl; EXECUTE stmt; DEALLOCATE PREPARE stmt;

-- 3) 审计表
CREATE TABLE IF NOT EXISTS content_audit_logs (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  actor_id BIGINT NOT NULL,
  actor_role VARCHAR(16) NOT NULL,
  actor_name VARCHAR(50) DEFAULT NULL,
  action VARCHAR(32) NOT NULL,
  target_type VARCHAR(16) NOT NULL,
  target_id BIGINT NOT NULL,
  paper_id BIGINT DEFAULT NULL,
  before_json JSON DEFAULT NULL,
  after_json JSON DEFAULT NULL,
  note VARCHAR(255) DEFAULT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  KEY idx_cal_target (target_type, target_id),
  KEY idx_cal_actor (actor_id),
  KEY idx_cal_created (created_at),
  KEY idx_cal_paper (paper_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

```ts
export interface AuditEntry {
  actorId: number; actorRole: string; actorName: string | null;
  action: 'paper.delete' | 'question.update' | 'image.delete';
  targetType: 'paper' | 'question' | 'image'; targetId: number;
  paperId?: number | null; beforeJson?: unknown; afterJson?: unknown; note?: string | null;
}
@Injectable()
export class ContentAuditRepository {
  constructor(@Inject('DATABASE_POOL') private readonly pool: Pool) {}
  async append(e: AuditEntry): Promise<void> {
    await this.pool.execute(
      `INSERT INTO content_audit_logs
        (actor_id, actor_role, actor_name, action, target_type, target_id, paper_id, before_json, after_json, note)
       VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
      [e.actorId, e.actorRole, e.actorName, e.action, e.targetType, e.targetId,
       e.paperId ?? null, e.beforeJson == null ? null : JSON.stringify(e.beforeJson),
       e.afterJson == null ? null : JSON.stringify(e.afterJson), e.note ?? null],
    );
  }
}
```

- [ ] **Step 5: 实现 repo.updateWithAudit（事务内写审计，沿用 Task 4 已建成的 `appendOnConnection`）**

⚠️ **审计原子性（用户已裁决 spec §9.2 优先，与 Task 4 删卷同口径）**：题目更新与审计必须在**同一个数据库事务**里；审计写失败 → 整单回滚（题目不改）。**不要**用 pool 级的 `audit.append()` 跟在更新后面——那是另一条连接，不参与事务。

```ts
// research-questions.repo.ts（注入 ContentAuditRepository）
async updateWithAudit(
  id: number, fields: Record<string, unknown>, markVerified: boolean,
  audit: AuditEntry,
): Promise<void> {
  const keys = Object.keys(fields);
  if (keys.length === 0) throw new BadRequestException({ code: 1001, message: '无变更字段' });
  const sets = keys.map((k) => `${k} = ?`).join(', ');
  const params: Array<string | number | null> = keys.map((k) => fields[k] as string | number | null);
  if (markVerified) params.push(1);
  const conn = await this.pool.getConnection();
  try {
    await conn.beginTransaction();
    await conn.execute(
      `UPDATE questions SET ${sets}${markVerified ? ', answer_verified = 1' : ''} WHERE id = ?`,
      [...params, id],
    );
    await this.audit.appendOnConnection(conn, audit);   // 同一 conn，commit 之前
    await conn.commit();
  } catch (err) {
    await conn.rollback();
    throw err;
  } finally {
    conn.release();
  }
}
```
安全：keys 来自 zod 固定白名单（`answer/content/options/explanation/approach`），无 SQL 注入。测试必须断言「审计写失败 → 回滚、题目未改」与「appendOnConnection 用的就是事务的 conn」。

```ts
const RESEARCH_URL_RE = /^\/uploads\/research\/[0-9a-f-]+\.[a-zA-Z0-9]+$/;

async cleanupUnreferenced(urls: string[]): Promise<{ deleted: number; skipped: number }> {
  let deleted = 0, skipped = 0;
  for (const url of new Set(urls)) {
    if (!RESEARCH_URL_RE.test(url)) {
      throw new BadRequestException({ code: 1001, message: `非法图片 URL：${url}` });
    }
    const row = await this.files.findByUrl(url);
    if (!row || row.source !== 'research') { skipped++; continue; }

    // 铁律 2：全局引用检查（questions 五列 + 学生作答三表）
    const like = `%${url}%`;
    const [q] = await this.pool.execute<RowDataPacket[]>(
      `SELECT COUNT(*) AS cnt FROM questions
        WHERE content LIKE ? OR options LIKE ? OR answer LIKE ? OR explanation LIKE ? OR approach LIKE ?`,
      [like, like, like, like, like],
    );
    const [a] = await this.pool.execute<RowDataPacket[]>(
      `SELECT (SELECT COUNT(*) FROM exam_answers WHERE answer_text LIKE ?)
             + (SELECT COUNT(*) FROM answers WHERE answer_text LIKE ?)
             + (SELECT COUNT(*) FROM special_answer_records WHERE answer_text LIKE ?) AS cnt`,
      [like, like, like],
    );
    // 铁律 3：extract_tasks FK RESTRICT
    const [t] = await this.pool.execute<RowDataPacket[]>(
      'SELECT COUNT(*) AS cnt FROM extract_tasks WHERE file_id = ?', [row.id],
    );
    if (Number(q[0].cnt) > 0 || Number(a[0].cnt) > 0 || Number(t[0].cnt) > 0) { skipped++; continue; }

    // 铁律 1+4：DB 先删，commit 后删磁盘；失败只记日志
    try {
      await this.files.delete(row.id);
      const abs = path.resolve(this.uploadDir, url.replace(/^\/uploads\//, ''));
      if (!abs.startsWith(path.resolve(this.uploadDir) + path.sep)) {
        this.logger.warn(`非法图片路径，跳过删文件：${url}`);
      } else {
        await fs.unlink(abs).catch((e) => this.logger.warn(`删图失败 ${url}: ${e}`));
      }
      await this.audit.append({
        actorId: this.currentActorId, actorRole: 'researcher', actorName: this.currentActorName,
        action: 'image.delete', targetType: 'image', targetId: row.id,
      });
      deleted++;
    } catch (e) { this.logger.warn(`清理失败 ${url}: ${e}`); skipped++; }
  }
  return { deleted, skipped };
}
```
