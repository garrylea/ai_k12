## UX/UI 设计强制约束

进行任何 UX/UI 设计、原型、界面规范、组件库、交互流程相关工作时，**必须遵循以下规则**：

1. **以 PRD 为唯一基准**：所有设计前必须先阅读 [K12智学系统-产品需求文档.md](./K12智学系统-产品需求文档.md)，并以其中的功能、流程、规则为设计输入。
2. **不得违背 PRD 中的任何要求**，包括但不限于：
   - 双轨制学习结构（主线 §6.1 / 辅线 §6.2）不得混淆，主线必须严格遵循"错题清零 → 发放奖励 → 下一课 / 单元检测 / 期中期末"流程。
   - 苏格拉底式 AI 辅导边界（§7.1）：主线讨论严格限定在当前卡片，辅线开放范围；AI 不直接给答案。
   - 内容卡片化（§7.2）：教材原文以卡片分页展示，每张卡片配"讨论"入口。
   - 闯关奖励机制（§7.3）：小学虚拟奖励 / 中学物质奖励由家长兑现，错题清零是解锁前置条件。
   - 双错题本（§7.4）：主线影响解锁、辅线不影响主线，UI 上必须清晰区分两本错题。
   - 自动判题与提示（§7.5）：客观题自动、主观题 AI 批改；学生可请求"提示"而非完整答案。
   - 测评考试（§7.6）：单元检测、期中、期末嵌入主线，错题进入主线错题本必须清零。
   - 家长端（§7.7）：低干预、AI 对话全透明回放、异常行为顶部 Banner 全局预警、目标提醒、行为管控。
   - 账号权限（§7.8）：家长主账号 + 学生子账号；开通子账号必须强制录入"年龄/年级"；同设备 PIN/密码隔离；不支持学生自主注册。
   - AI 异常兜底（§7.9）：连续 3 次失败/不会触发完整解析与知识点总结；闲聊采用温和阻断话术 + 家长端预警。
   - 错题变式（§7.10）：AI 动态生成 + 逻辑自洽校验。
   - 护眼日夜模式（§7.11）：仅作用于 `student-theme-container`（学、练、考、错题本沉浸层）；登录、注册、学科选择、关卡星图、家长管理台必须物理屏蔽夜间模式。
   - 输入方式（§8）：键盘公式、拍照搜题、手写为首发；语音为后续迭代。
   - 非功能性需求（§11）：AI 响应 ≤ 3s（复杂题 ≤ 5s）、严禁闲聊、学生数据仅家长可见。
3. **冲突处理**：若设计需求与 PRD 出现冲突，必须先与用户确认是否更新 PRD；**不得擅自在 UI/UX 设计中绕过或弱化 PRD 规则**。
4. **MVP 边界（§13）**：首发仅数学学科、键盘公式 + 拍照识别；UI 可预留扩展位，但首发界面不得引入未列入 MVP 的能力。

## 设计工作流程

- 启动任何设计/开发任务前，先 Read 产品需求文档对应章节。
- 输出设计稿、组件清单、流程图时，标注其对应 PRD 的章节编号（如"依据 §6.1 主线流程"）。
- 评审时以 PRD 为对照清单，确保功能、流程、文案、奖励、错题、家长端管控等关键规则全部落地。
