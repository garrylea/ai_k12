## 1. 文档说明

### 1.1 目的

本文档定义 K12 智学系统的整体技术架构，明确前后端技术选型、核心子系统划分、数据流转路径、数据模型与接口边界，为开发、测试、部署与后续演进提供技术基准。

### 1.2 范围

- 前端：WebApp（MVP 阶段唯一实现端）
- 后端：Node.js 服务端，包含 AI-Agent 中枢、Content Service、Data Refinery、Assessment Service、ErrorBook Service、ParentAdmin Service、Auth Service、Reward Service 等
- 数据：课程/题库/用户/学习记录/错题/对话/奖励等核心数据
- 集成：第三方大模型 API、OCR/手写识别、对象存储

### 1.3 架构原则

1. **PRD 优先**：所有技术决策服务于产品需求；主线“错题清零→奖励→解锁”为不可绕过的核心规则。
2. **双轨隔离**：主线与辅线在数据、状态、解锁逻辑上严格隔离。
3. **AI 可路由**：辅导请求按学科/难度/场景分发至最合适的大模型。
4. **内容可扩展**：教材版本、学科、学段以配置化方式支持后续新增。
5. **安全合规**：未成年人数据最小化采集，家长主账号持有监护授权。

**数据准备链路**：

```text
┌─────────────────────────────────────────────────────────────┐
│                 离线数据准备工具（非运行时）                   │
│  ┌────────────────┐                                         │
│  │  网络爬虫系统   │                                         │

│           │ 采集原始 PDF/图片                                │
│           ▼                                                  │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 数据分析与整理系统（Data Refinery）— 批量模式        │    │
│  │ 本地私有模型：PDF/图片 → Markdown → 提取题目入库     │    │

└─────────────────────────────────────────────────────────────┘
```

- **网络爬虫系统**：仅在收集原始教材/试卷数据时运行，部署在独立机器上，作为独立工具使用。
- **Data Refinery（批量模式）**：在系统建设/内容补充阶段，使用本地私有模型批量处理爬虫采集的 PDF/图片，提取题目后写入 Content Service。
- **Data Refinery（实时模式）**：系统上线后，学生辅线上传错题/不会题图片时，由 ErrorBook Service 调用 Data Refinery，Data Refinery 再调用第三方 OCR/文档解析 API 识别并提取题目，最后交由 AI-Agent 中枢讲解。

| 数据库 | MySQL 9.7.1 LTS | 关系型主库，TEXT 存 JSON 字符串由应用层解析 |

### 2.3 部署视图

**运行时部署**（7×24 在线服务）与**离线数据准备工具**分离：

- **业务服务层**：所有用户请求由 Server Pod 中的业务服务（Content / DataRefinery / Assessment / ErrorBook / ParentAdmin / Auth / Reward）处理。
- **通用智能能力层**：AI-Agent 中枢作为「智学系统服务端」内部的通用智能能力层模块，与业务服务共进程部署（MVP 共进程模块化），业务服务按需调用；AI-Agent 中枢不直接接收用户请求，只输出智能结果。
- **Data Refinery**：作为应用服务在线部署，提供两种模式：
  - **实时模式**：接收 ErrorBook Service 传入的学生上传图片/PDF，调用第三方 OCR/文档解析 API 识别并提取题目。
  - **批量模式**：在系统建设/内容补充阶段，由 Worker Pod 或独立机器使用本地私有模型处理爬虫采集的 PDF/图片，提取题目后写入 Content Service。
- **网络爬虫系统**：仅在收集原始教材/试卷数据时运行，部署在独立机器上，不属于线上服务集群。

## 4. 后端架构

### 4.1 分层架构


### 4.2 核心子系统

#### 4.2.1 AI-Agent 中枢

**定位**：系统的**智能能力提供者**。采用「基础设施层 + 能力层」两层结构，单进程模块化部署，便于演进。AI-Agent 中枢自身**不持有业务数据**（包括对话流水，参见 §4.2.10 ConversationService）。

**两层结构**：

```text
ai-core/（单进程部署，模块化组织）
├── infra/  基础设施层（共用、薄、无业务状态）
│   ├── ModelRouter        多模型路由
│   ├── PromptBuilder      提示词模板与构建
│   ├── ModelClient        多厂商客户端适配
│   ├── SafetyGuard        学习相关性 / 异常检测 / 内容安全
│   ├── ResponseParser     结构化输出解析（LaTeX/JSON）
│   └── FallbackHandler    连续失败兜底
└── capabilities/  能力层（业务编排，调用 infra 组合实现）
    ├── TutoringCapability      苏格拉底辅导（多轮对话主入口）
    ├── GradingCapability       主观题按步骤给分
    ├── ExplanationCapability   错题解析、重讲生成
    ├── VariationCapability     变式题生成 + Validator 校验
    └── AnalyticsCapability     学情分析、报告内容生成
```

**模型路由策略（可配置）**：

| 场景 | 首选模型 | 备选模型 | 说明 |
|------|----------|----------|------|
| 通用语言/概念讲解 | Kimi | DeepSeek-V4-Flash | 中文表达自然 |
| 常规数学题 | Qwen-3.7-Max | DeepSeek-V4-Flash | 数学推理强 |
| 复杂数学证明/高难综合 | Gemini-3.1-Pro | Qwen-3.7-Max | 长推理链、多步证明 |
| 快速提示/简单判断 | DeepSeek-V4-Flash | - | 成本低、响应快 |
| 变式题生成 | Qwen-3.7-Max | Gemini-3.1-Pro | 需结构化输出 |
| 闲聊/边界检测 | DeepSeek-V4-Flash | - | 快速分类 |
| 主观题判分 | Qwen-3.7-Max | Kimi | 需按步骤给分 |
| 学情报告生成 | Kimi | Qwen-3.7-Max | 中文总结自然 |

**主要组件**：


**成本与配额策略**：

- 大模型 API 费用已包含在家长订阅/缴费套餐中，**不按单次调用向学生或家长额外计费**。
- 家长在创建/续费家长账号时购买对应套餐，系统按套餐级别为整个家庭账号分配 AI 调用额度（可按月/按周期重置，或按总课时包计）。
- 额度控制以**家长账号**为维度统一核算，其下所有学生子账号共享该额度池。
- 多节点部署下，配额计数走中心化的 **Redis 原子计数器**，避免节点本地各自计数导致超用
- 系统保留调用量监控与预警能力：当家庭账号接近套餐额度上限时，向家长端推送提醒；额度耗尽后降级为有限服务（如仅保留判题与提示，关闭深度讨论），或引导续费。
- AI-Agent 中枢内部通过模型路由、缓存命中、兜底降级等手段控制成本，但不改变“家长预付、家庭共享”的计费原则。

#### 4.2.2 内容与课程体系（Content Service）

**定位**：管理教材版本、章节结构、知识点、教材卡片、题库。

**核心能力**：

1. **版本管理**：人教版、北师大版、苏教版等版本元数据
2. **章节结构**：学段 → 学科 → 教材版本 → 学期 → 单元 → 课 → 知识点
3. **教材卡片**：分页存储教材原文，绑定知识点与讨论范围
4. **题库管理**：真题（易/中/难）、测试题存储与元数据维护；为 Assessment Service / AI-Agent 中枢按条件返回候选题目集
5. **组卷候选查询**：按考试范围、知识点覆盖、难度分布、题量返回候选题目；**最终组卷策略由 AI-Agent 中枢决策**

**数据来源**：

- 基础内容：网络爬虫系统采集公开教材/试卷 PDF/图片
- 结构化数据：Data Refinery 批量模式转换为 Markdown 并拆解题目后写入 Content Service

#### 4.2.3 数据识别与提取系统（Data Refinery）

**定位**：将非结构化的 PDF/图片转化为 Markdown 并提取结构化题目的**应用服务**。对外提供统一的"题目提取"接口，对内通过**多 Provider 策略**支持不同的提取后端，调用方按场景选择 Provider。

**Provider 策略**：

| Provider | 实现 | 适用场景 |
|---|---|---|
| LocalModelProvider | 本地部署的私有模型（OCR + 版面分析 + 题目拆解） | 自有模型质量够用、希望控制成本与数据流向 |
| ThirdPartyApiProvider | Mathpix / 讯飞等第三方 OCR / 文档解析 API | 私有模型不够好、追求识别质量与开箱即用 |

两种 Provider **对调用方完全透明**，按部署/运营配置切换。同一调用方也可根据请求特征动态选择 Provider。

**核心能力**：

1. **文档解析**：PDF 文字/图片/公式提取、图片 OCR
2. **Markdown 生成**：生成教材卡片正文与题目标准格式
3. **结构识别**：识别章节、单元、课、知识点、例题、习题层级
4. **题目拆解**：将试卷/练习拆分为独立题目（题干、选项、答案、解析、知识点、难度）
5. **质量校验**：人工抽检入口、AI 自动校验

**典型工作流**：

```text
PDF/图片输入
  │
  ▼
Provider 选择（按调用方配置 / 请求特征）
  │
  ▼
文档解析（OCR + 版面分析）
  │
  ▼
结构识别（章节/知识点/题目边界）
  │
  ▼
生成 Markdown + 元数据
  │
  ▼
题目拆解与知识点标注
  │
  ▼
逻辑/答案校验
  │
  ▼
返回结构化题目（供 Content Service 入库 或 ErrorBook 实时使用）
```

#### 4.2.4 网络爬虫系统（Crawler）

**定位**：从公开渠道采集 K12 教材、试卷、真题等原始素材。**离线独立工具**，部署在独立机器上，仅在需要补充原始数据时运行，不属于线上服务集群。

**核心能力**：

1. **种子管理**：教委公开资源、学校公开试卷、公开真题库 URL
2. **白名单范围约束**：爬虫严格限定在运营/教研配置的 URL 白名单内，只采集传入的连接，**不允许越站爬到白名单外的域名或页面**
3. **调度与去重**：分布式任务调度、URL 指纹去重
4. **文件下载**：PDF、图片、网页快照
5. **合规控制**：遵守 robots.txt、限速、版权风险标记
6. **原始存储**：下载文件存入对象存储，记录来源与采集时间

**安全与合规**：

- 仅采集公开免费义务教育资源
- 对出版社数字版权敏感内容做风险标记
- **不允许越站**：爬虫只在配置的 URL 白名单内活动，不会跟随链接扩散到非授权站点
- 为后续“知识点图谱自研体系”预留替代方案

#### 4.2.5 错题本系统（ErrorBook Service）

**定位**：双轨错题本的**状态管理中心**。负责错题生命周期、重做记录、升级、清零、薄弱点数据聚合；不生成解析/变式，智能内容由 AI-Agent 中枢提供。

**核心能力**：

1. **主线错题本（全系统唯一，按学科拆分）**：统一承载三轨错题，以来源字段（`source`）区分——`practice`（课堂练习）/ `exam`/`targeted`/`error_practice`（训练轨）参与课程/单元/考试解锁的清零门禁；`auxiliary`（辅线答疑题目）自动入本、无需判错，不参与门禁（PRD §7.4）。**唯一例外：语文古诗文专项（默写 / 解释）不入本、不参与门禁**（PRD §7.4 例外，理由见 §4.2.13 —— 错题本是「接主线清零门禁的待办队列」，篇目级作答无重做—清零对象、无变式生成物）
2. **自动录入**：课堂练习/训练轨判错自动写入，自带学科属性（**古诗文专项除外，它一律不入本**）；辅线答疑题目结构化入库时自动写入
3. **主动录入**：辅线页面上传图片/PDF，调用 Data Refinery 实时模式识别并提取题目，再请求 AI-Agent 中枢拆解学科与知识点、生成讲解
4. **错题升级**：再次做错提升级别（L1-L5），触发 AI-Agent 中枢重讲与变式生成
5. **薄弱点数据聚合**：按学科、知识点、时间段、题型聚合错题统计数据，为 AI-Agent 中枢学情分析提供输入
6. **清零机制**：做对一次即从该学科待清零列表移除（仅门禁计数来源；`auxiliary` 题清零与否不影响门禁）

**主动录入流程**：

```text
学生上传图片/PDF
  │
  ▼
ErrorBook Service 接收文件 → 存入 OSS
  │
  ▼
调用 Data Refinery 实时模式
  │
  ▼
第三方 OCR/文档解析 API 识别 → 提取题目
  │
  ▼
AI-Agent 中枢拆解知识点 + 讲解
  │
  ▼
生成候选题目，学生确认/编辑
  │
  ▼
存入主线错题本（source='auxiliary'）
```

#### 4.2.6 家长与管理系统（ParentAdmin Service）

**定位**：家长端的**展示与配置代理**。负责聚合各业务数据与 AI-Agent 中枢生成的结论，向家长展示学情、预警、回放；本身不生成智能结论。

**核心能力**：

1. **学情报告展示**：按学科维度聚合学习时长、完成进度、正确率、薄弱点统计，展示 AI-Agent 中枢生成的学情分析结论与报告内容
2. **AI 对话回放**：按日期/学科/课程回放完整对话流水，闲聊/异常内容高亮；对话数据由 ConversationService 只读提供，ParentAdmin 仅做展示
3. **异常预警触达**：接收 AI-Agent 中枢的 SafetyGuard 写入的 safety_alerts`，按家长配置的档位与开关通过 WebSocket/站内信/短信触达；强制类预警不可关闭
4. **预警配置**：家长可选择系统预设三档（宽松/标准/严格），并按预警类型开关；系统按学段自动推荐默认档位（小学低年级默认严格，小学高年级/初中默认标准，高中默认宽松）
5. **目标设定**：每日/每周学习目标与提醒
6. **行为管控**：使用时长、禁用时段、奖励兑换开关、辅线/拍照开关
7. **奖励兑现**：中学物质奖励确认兑现，小学虚拟奖励查看
8. **子账号管理**：创建/编辑/删除学生子账号，强制年龄/年级

#### 4.2.7 用户与权限系统（Auth Service）

**定位**：账号体系、身份鉴别、同设备隔离。

**核心能力**：

1. **家长主账号**：手机号注册，拥有学生子账号管理权
2. **学生子账号**：由家长创建，用户名非手机号格式，强制录入年龄/年级
3. **统一登录**：按用户名格式判断身份（手机号 → 家长，否则 → 学生）
5. **数据隔离**：家长仅可见自己孩子的数据

#### 4.2.8 测评与考试系统（Assessment Service）

**定位**：单元检测、期中/期末考试的**会话管理、AI 组卷、作答、批改、成绩记录**。组卷与主观题批改由 AI-Agent 中枢主导，客观题在有标准答案时直接判分，无标准答案时由 AI 兜底。

**核心能力**：

1. **AI 组卷**：
   - 输入：考试范围（单元/章节）、知识点覆盖率目标、难度分布、题型配比、题量
   - 实现：由 AI-Agent 中枢的组卷能力（或相关 capability）主导，从 Content Service 题库中按约束抽题并做知识点覆盖校验；KnowledgeGraphService（§4.2.11）提供知识点关联与覆盖率验证
   - 题库不足时，由 AI 直接生成变式题补充，保证卷面完整
   - 组卷场景低频，AI 处理完全胜任，无需单独规则引擎
2. **限时作答**：倒计时、自动保存、到时强制交卷
3. **自动批改**：
   - **客观题（有标准答案）**：由本服务按标准答案直接判分，AI 不参与
   - **客观题（无标准答案）**：由 AI-Agent 的 GradingCapability 判分
   - **主观题**：由 AI-Agent 的 GradingCapability 按步骤给分 + 总评；有参考答案时以标准答案为参照，AI 做步骤评价
4. **成绩报告**：分数、知识点正确率、薄弱点 TOP 3（基于 KnowledgeGraphService 的根因定位）、推荐复习；报告结论与文本由 AI-Agent 的 AnalyticsCapability 生成
5. **错题接入**：考试错题进入主线错题本

**自测定位**：所有考试均为查漏补缺自测，AI 服务暂时不可用时学生可稍后重新发起考试，不阻塞主线进度。

#### 4.2.9 奖励服务（Reward Service）

**定位**：主线闯关奖励的发放、状态管理与兑现。

**核心能力**：

1. **课级奖励**：完成一课且错题清零后发放
2. **单元级奖励**：完成单元检测且错题清零后发放
3. **小学虚拟奖励**：徽章、奖杯、勋章入册
4. **中学物质奖励**：生成待兑现记录，通知家长端
5. **奖励状态**：待领取/已领取/待兑现/已兑现

#### 4.2.10 对话服务（ConversationService）

**定位**：AI 对话流水的**数据所有权服务**。所有 AI 对话（主线/辅线/答疑/讨论）的会话与消息读写均由本服务持有，其他服务通过明确的读/写接口访问。

**为什么独立设置**：

- 对话数据是学生侧核心交易数据，不应绑定到任何展示型服务（如 ParentAdmin）的部署/可用性上
- AI-Agent 中枢自身无状态，对话上下文需要专门的持久化服务
- 多节点部署下，对话续接、跨节点上下文加载都需要统一的数据出口

**核心能力**：

1. **会话生命周期管理**：创建/查询/归档 `ai_dialogues`
2. **消息持久化**：写入 `ai_messages`（用户消息 + AI 回复，含元数据：模型、token 消耗、耗时、安全标记）
3. **上下文加载**：按 `session_id` 加载历史消息，支持 token 预算控制与摘要截断
4. **多维度查询**：
   - 学生维度：按学生 ID + 时间范围（家长回放、学情分析）
   - 课程/知识点维度：按 `cardId` / `knowledgeId`（辅导上下文）
   - 安全维度：按 `alertLevel`（异常对话审计）
5. **多节点会话续接**：所有可见状态落库，节点切换后通过 `session_id` 无缝恢复

**与其他服务的关系**：

| 调用方 | 接口性质 | 用途 |
|---|---|---|
| AI-Agent 中枢（TutoringCapability） | 读历史 + 写本轮消息 | 多轮对话上下文构建 |
| ParentAdmin Service | **只读** | 家长端 AI 对话回放（P6.4） |
| AI-Agent（AnalyticsCapability） | 只读 | 学习行为分析、报告生成 |
| 安全审计 | 只读 | 异常对话审计与回溯 |

**数据归属边界**：

- `ai_dialogues` / `ai_messages` 表的**写权限仅 ConversationService 拥有**，禁止其他服务直接写入
- `safety_alerts` 表由 AI-Agent 中枢的 SafetyGuard 检测时直接落库，ConversationService 在消息上打安全标记并保留外键关联

#### 4.2.11 知识点图谱服务（KnowledgeGraphService）

#### 4.2.13 语文古诗文专项（ChinesePassage Service）

**定位**：训练轨下「训练 → 语文 → 专项」的**独立子系统**，含**古诗文默写**（作者 / 朝代 / 正文三字段整篇默写）与**古诗文解释**（重点字词释义 + 逐句翻译）两个专项。

**独立性（核心架构约束，2026-09-15 确立）**：

- 作答单位是**篇目**而非「题」，标准答案是**篇目自带属性**（正文 / 释义 / 译文），判题方式专项专属（默写走程序化 diff，解释走 LLM 释义比对）。
- **不挂 `questions` 表**：篇目级数据全部由自有表 `chinese_passages` 承载，无外键指向任何表，也不被任何表指向。
- **不进错题本、不参与主线清零门禁、不用「不再展示」/ 提示缓存 / 自评** —— 错题本本质是「接主线清零门禁的待办队列」，篇目级作答无重做—清零对象、无变式生成物（依据见 PRD §7.4 例外说明与 `docs/superpowers/specs/2026-09-15-chinese-interpretation-special-design.md` §2）。
- **边界**：本条**只覆盖古诗文专项**。语文**试题类**（试卷 / 真题 / 考试）属正常题库业务，仍走 `questions` + 错题本 + 考试 / 组卷既有体系，**复用、不另起一套**。划界依据是**形态**不是学科。

**数据表**：`chinese_passages`（见 §6.2）。两个专项**共用一篇一行**，各取各的列：默写用 `body`（+ `author`/`dynasty`）；解释用 `key_terms` / `sentences` / `full_translation` 三列（2026-09-16 已实施）。

**内容生产**：走 data-refinery 的**旁路管线**，**不接 4.1–4.5 的四阶段主线**（不产出 `cards`、不写 `questions`）。两条子路径差别很大：

- **默写** `dictation_cli`：爬 → convert → 目录 → 定位切片 → 自检 → 入库（正文要从教材扫描页里定位切出）。见使用手册 §4.9。
- **解释** `interpretation_cli`（2026-09-16 新增）：**不碰教材页 MD**——正文用库里已校验的 `body`，**字词由用户手工整理**后经 `--input`（JSON / Markdown）交进来，管线只做「解析 → 切句 → 字词归属 → 出译文 → 自检 → 幂等入库」。译文是**混合模式**：输入给了就用输入的（不调模型），没给才由 LLM 生成。见使用手册 §4.10。

**抽题池（两个专项口径有意不同）**：默写 = `verified=1 AND memorize_required=1 AND is_active=1`；解释 = `verified=1 AND is_active=1 AND JSON_LENGTH(sentences) > 0`——不设「必背」（要背诵不是要理解翻译的必要条件），加「内容就绪」（没切过句的篇目点进去没题目）。

**判题路径**：不经过题目型判题路由（`JudgeCoreService` 的 choice / fill_blank / short_answer 等分支）。默写为纯程序比对 + LCS 差异定位（不调 LLM）；解释为 **逐句** LLM 判题（`interpretation_judge` 场景，本地模型优先、ds flash 兜底）——能确定的项（空白 / 归一化全等）由程序短路掉，只有非要语义判断的项才进模型，实测单句 ~1.3s。**两条路径都不写任何学生状态**。

### 7.3 WebSocket 设计

| 通道 | 用途 | 说明 |
|------|------|------|
| `ws://host/ws/ai/{dialogueId}` | AI 辅导流式响应 | SSE 备选；支持首字立即推送，完整响应按 token 流输出 |
| `ws://host/ws/notifications/{studentId}` | 家长端实时预警通知 | 异常行为、额度预警、目标提醒 |

**连接管理**：

- **鉴权**：建立连接时携带 JWT，服务端校验并绑定 `studentId` / `parentId`
- **心跳**：客户端 30s 一次 ping，服务端 60s 无响应则断开
- **断线重连**：客户端指数退避重连（1s → 2s → 4s → ... 最大 30s），重连成功后携带 `lastMessageId` 请求补发离线期间消息
- **订阅模型**：家长端预警通道支持按预警类型订阅/取消订阅
- **跨节点续接**：`dialogueId` 绑定到 ConversationService 的持久化数据，节点切换后新连接通过 `dialogueId` 无缝恢复上下文

## 8. 安全与合规

### 8.1 账号安全

- 用户名 + 密码，bcrypt 加盐存储
- 登录后服务端 Session（Redis）或简单 JWT
- MVP 阶段不引入 Refresh Token 和设备指纹，后续有多端登录需求时再升级

### 8.2 数据安全

- 学生数据与家长账号隔离，家长仅可访问自己孩子数据
- 所有接口按身份鉴权
- 静态资源签名访问
- 数据库敏感字段加密

### 8.3 AI 安全

- 所有 AI 输出经学习相关性校验
- 闲聊温和阻断，不严厉封禁
- 异常输入实时推送家长端
- 对话记录全量留存，支持回放

### 8.4 合规

- 遵守《未成年人个人信息保护规定》
- 家长主账号模式下明确监护人授权
- 数据采集最小化，年龄/年级仅用于课程匹配
- 公开教材/试卷采集需记录来源并评估版权风险

## 9. 非功能性设计

### 9.1 性能目标

| 指标 | 目标 | 说明 |
|------|------|------|
| AI 首字延迟 | ≤ 1s（实测为准） | 通过 SSE/WS 流式输出，让学生立即看到 token |
| AI 完整响应 | ≤ 3s（常规）/ ≤ 5s（复杂证明） | 按模型实测确定，架构层不固化 |
| 页面首屏加载 | ≤ 2s | |
| 题库/章节查询 | ≤ 200ms | |
| 流式传输 | 必须支持 | 所有 AI 长响应走 SSE 或 WebSocket 流式 |


### 9.2 高可用

- 服务多实例部署，Nginx 负载均衡
- Redis 集群，数据库主从 + 读写分离
- 大模型 API 降级策略：主模型失败自动切换备选模型

**多节点部署与跨节点续接**：

- 业务服务部署多节点，Nginx 负载均衡将学生会话分发到不同节点
- 节点故障时，学生重新登录后由负载均衡路由到健康节点，通过 `session_id` / `dialogueId` 从 ConversationService 恢复会话上下文
- 所有**用户可见状态**（对话消息、答题草稿、考试进度）必须落 MySQL；Redis 仅做缓存与会话 token，不持有唯一状态
- 进行中的流式响应（AI 生成到一半节点挂了）由客户端检测到断线后自动重连，ConversationService 提供 `lastMessageId` 支持断点续传


### 9.3 可扩展性

- 学科、版本、学段以配置化表结构存储
- AI-Agent 模型路由可配置，新增模型无需改动业务代码
- 数据处理流水线以 MQ 任务形式异步扩展

### 9.4 可观测性

- 日志：结构化日志，按子系统/请求链路聚合
- 监控：Prometheus + Grafana，关注 AI 响应时间、错误率、成本
- 链路追踪：OpenTelemetry，追踪 AI 请求端到端延迟

**AI 质量与成本监控**（产品核心价值，必须监控）：

| 监控项 | 实现方式 | 告警阈值 |
|---|---|---|
| 判分准确率回归 | 每周跑固定题集（30 道），对比各模型判分结果与参考答案的一致性 | 准确率下降 > 5% |
| 辅导有效性 | 学生看完 AI 解释后下一题正确率 | 连续 7 天下降 |
| 变式题合格率 | VariationCapability 内部 Validator 拒绝率 | 拒绝率 > 30% |
| 单家长账号 token 消耗 | ModelClient 拦截器实时累加，按家长账号维度聚合 | 接近套餐额度 80% |
| 单次对话成本 | 记录每轮对话的 input/output token 与模型单价 | 异常高耗时排查 |
