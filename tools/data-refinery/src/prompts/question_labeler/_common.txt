【输出格式 -- 必须严格遵守】
1. 只输出一个 JSON 对象 {...}，不要输出任何其它内容。
2. 不要使用 ```json``` 等 markdown 代码块；输出的第一个字符必须是 {，最后一个字符必须是 }。
3. 字符串值必须是合法 JSON：换行用 \n，双引号用 \"。
4. LaTeX 反斜杠在 JSON 中转义为两个 \\（如 \frac -> \\frac，\mathrm -> \\mathrm，\times -> \\times）。

【输出字段】
- type: 只能是 "choice"（选择）、"fill_blank"（填空）、"true_false"（判断）、"short_answer"（简答）、"proof"（证明）、"calculation"（计算）
- difficulty: 难度 1-5 的整数，按上面【本学科判定标准】的分层给
- knowledge_points: 知识点 code 列表（从下列已有知识点中选，0..N 个）
- suggested_new_kps: 建议新增的知识点名称列表（仅当题目涉及下列列表中不存在的知识点时才填，否则空数组 []）
- completeness: 完整性检测结果
    - is_complete: bool（题干 + 选项 + 材料 是否完整）
    - issues: 数组，具体缺陷描述（如「选择题选项不足4个」「题干截断」「材料段不完整」）；完整时为空数组 []
- regenerated: 修复后的完整题（is_complete=true 时为 null；is_complete=false 且缺陷可修复时必须输出修复结果）
    格式：{"content": "修复后完整题干", "options": [{"label":"A","text":"..."},...], "material_text": null, "answer": "..."}

【修复规则 -- is_complete=false 时】
- 只有【本学科判定标准】里标为「可修复」的缺陷才允许修复；标为「只报告」的缺陷
  **必须** `is_complete=false` + `regenerated=null`，在 issues 里写清缺什么。
  这类缺陷（原文里本来就没有的文字、PDF 排版丢失的画线/加点/图片内文字）无法从
  上下文推出来，任何补全都是编造，会把假题推给学生。
- 修复必须基于原文残片：只在原文能找到依据时补全（例如选项标记存在但文字被截断），
  找不到依据就不要修，改为只报告。
- 修复后的题必须完整可用（学生能做题），保留原题意图，不要生成全新题。
- regenerated.content：修复后完整题干（剥离选项和材料，保留 Markdown/LaTeX/图片引用）。
- regenerated.options：选择题按本学科要求的项数给出；非选择题 null。
- regenerated.material_text：材料题的共享材料；无材料 null。
- regenerated.answer：保留输入中已对齐的答案原文；原文无答案则填 ""（**不得编造**，
  无答案的题由做题环节大模型补，本阶段不补答案）。

【规则】
- 不切题（已按题号切好），不自行生成全新题（只修复原题）。
- 保留原始 Markdown 图片语法 ![alt](path)。
- 不输出 answer/explanation/content/options/material_text 顶层字段（这些由系统 Python 拆分或 regenerated 提供）。
- 题目以「题干：/选项A：/选项B：...」分行形式呈现时，说明系统已按选项标记确定性拆分：
  不要重写/重排拆分结果（此时 regenerated 必须为 null）。仅当拆分结果本身有真实缺陷
  （选项为空、题干截断）时才修复。这是硬性要求：重写拆分结果会被系统一致性校验拒绝。

【知识点标注约束】
