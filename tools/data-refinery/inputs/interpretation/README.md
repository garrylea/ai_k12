# 语文古诗文解释专项 · 输入稿

本目录放**「古诗文解释（翻译）」专项的输入稿**——重点字词由人工整理后交管线入库。
管线见 `docs/data-refinery-使用手册.md` §4.10。

## 两种写法都认（实际用过的是第二种）

**写法 A：`# 篇名` + `序号. 词：解释`**（`诗文重点字词.md` 是这个格式的空模板）

```markdown
# 岳阳楼记

1. 谪守：因罪贬谪流放，出任外官
2. 越明年：到了第二年
```

**写法 B：`# 文档标题` + `## 篇名` + `〔词〕解释`**（课本注释的原样形式，2026-09-16 实际入库用的就是它）

```markdown
# 古诗文重点字词解释

> 说明：……（文档前言，会静默跳过）

---

## 沁园春·雪

〔北国〕指我国北方。

〔须〕等到。
```

规则：文件里**有 `##` 子标题时**，`#` 当文档标题跳过、`##` 才是篇目，第一个 `##` 之前的
`>` 前言与 `---` 水平线一并静默跳过；**只有 `#` 时**（写法 A），`#` 本身就是篇目。

## 你只要给字词，别的都不用

| 不用给 | 为什么 |
|---|---|
| 作者 / 朝代 | 库里已有（`chinese_passages.author` / `dynasty`） |
| **册次** | 不给就按篇名匹配——九上/九下重复收录的 9 篇会**一次写入两册**（`sentenceIndex` 按各册正文分别计算）。只在「同一篇两册要写不同字词」时才写一行 `册次：下册` |
| **正文** | 以库里已校验的 `body` 为准，管线自己切句 |
| **逐句译文** | 没给就由本地模型生成（想覆盖时**只给译文**、按句序一行一条；**别给原文**——两册正文标点可能不同，给了会对不上） |

## 注音保留，不影响定位

`〔滕子京谪（zhé）守巴陵郡〕……` 这种带注音的词**原样入库**（学生要看得见读音），
前端展示 `〔滕子京谪（zhé）守巴陵郡〕`；只有「在正文里定位」与「前端高亮」用去注音形式
（`滕子京谪守巴陵郡`，因为正文里没有注音）。`start` 接口因此下发两个字段：`term`（带注音）+ `plain`（去注音）。

## 格式容错

| 变体 | 例子 |
|---|---|
| 行首编号可有可无 | `1.` / `1、` / `1` / `①` / `-` / `*` / `（1）` |
| 词用括号界定（写法 B） | `〔谪守〕因罪贬谪流放` / `[谪守]…` / `【谪守】…` |
| 词带括号（写法 A） | `〔谪守〕：…` / `谪守：…` |
| 分隔符任选 | `：` / `:` / `＝` / `=` / 首个空白 |
| 简写也认 | `1 则:那么` → `term=则`，`gloss=那么` |
| 批注 | `<!-- … -->` 整段跳过 |
| 显式指定册次 | 篇名下加一行 `册次：下册` |

## 两条要知道的规则

1. **篇名不要手抄**。库里有些篇名带**半角括号**（`行路难(其一)`）、有些 `·` 前后**有空格**
   （`山坡羊 · 潼关怀古`）、有些没有（`丑奴儿·书博山道中壁`）。抄错一个，管线就报
   「在库里找不到」并列出相近篇名。**匹配本身已做归一**（全角/半角括号、空格差异都能对上），
   只给词牌名（`水调歌头`）也能匹配到 `水调歌头(明月几时有)`。
2. **在正文里定位不到的词会被丢弃并告警**（例如把篇名本身当词写进去、或词在词前小序里）。
   过目清单里能看到丢了哪些、为什么。

## 没填完也能跑

没填字词的篇目**不会被跳过**——它会入库但只有逐句翻译、没有字词（过目清单里有告警）。
所以可以分批填、分批跑。

## 跑法

```bash
cd tools/data-refinery

# 打样：先只跑 3 篇，看过目清单确认没丢字词
python src/interpretation_cli.py --extract --limit 3 --input <你的文件.md>

# 全量：解析 → 切句 → 字词归属 → 出译文 → 自检 → 入库
python src/interpretation_cli.py --all --input <你的文件.md>

# 或分两步（人工过目可以发生在入库之前：不想要的篇目直接从 JSONL 里删掉）
python src/interpretation_cli.py --extract --input <你的文件.md>
python src/interpretation_cli.py --load    --input <你的文件.md>
```

**译文生成有随机性**：本地模型偶尔会漏句/截断 JSON，导致个别篇目 fail-closed（该篇不入库、
过目清单里明确列出）。**重跑 `--extract` 通常就过**；也可把失败篇目单独存成一个小文件再跑，
然后把它产出的行追加进主 JSONL。`--load` 是幂等的（只 UPDATE 三列），随时可重跑。

产物落 `output/interpretation/语文/<文件名>.jsonl` 与 `-review.md`（过目清单：
句数 / 字词数 / 被丢弃的词及原因 / 未通过项 / 告警）。

## 入库后怎么验

```sql
-- 有内容的篇目（这就是解释专项的抽题池口径）
SELECT id, work_title, semester, JSON_LENGTH(sentences) AS n_sent, JSON_LENGTH(key_terms) AS n_terms
FROM chinese_passages
WHERE verified = 1 AND is_active = 1 AND JSON_LENGTH(sentences) > 0;
```
